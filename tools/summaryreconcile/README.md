# summaryreconcile — 請求計算・支払計算の実DB突合ハーネス（UAT-05/06 再現）

請求計算・支払計算（`SummaryDb.CalcSummary*`）を実DBに対して走らせ、生成された
`SummaryUriSei` / `SummaryKaiShi` を **請求台帳（発行控え）** / **支払台帳（発行控え）** の
SQLで突合する開発ツール。完成度チェックリスト §4.1 段階7・§3.11 の P0 Release Gate、
および UAT-05（売掛・請求）/ UAT-06（買掛・支払）の再現に使う。

- `creativevision10.slnx` には**含めない**（スタンドアロンの開発ツール）。
- 生SQLで手投入せず、`ExDatabaseSqlite` ＋ ドメインオブジェクトの `Insert` → `SummaryDb.Calc*`
  で投入・計算する（`Tests/TestServer/SummaryKakeDbTests.cs` と同じ正準方式）。

## 前提

- 対象DBは**開発用**であること（テスト伝票を投入・締日を一時変更するため）。実運用DBには使わない。
- 実行前に DB をバックアップ（例: `refer/back/`）。`server-*.db` は `.gitignore` 済み。
- 既定DB: `CvServer/server-user163.db`。KIN区分マスタId・対象取引先は同DBの実値を前提にコード内へ定数化している（別DBでは要調整）。

## 使い方

```bash
dotnet run --project tools/summaryreconcile -- <command> [dbPath]
```

| command | 内容 | 対応する検証 |
|---|---|---|
| `seed` | テスト範囲を掃除して再投入し、4計算を実行して台帳を表示（既定） | UAT-05/06 通し・数値突合 |
| `show` | 現在の `SummaryUriSei`/`SummaryKaiShi` を台帳SQLで表示 | 帳票=Summary の突合 |
| `idempotent` | 計算を2回実行しSummaryスナップショットが一致するか | D-02 Rebuild冪等性 / D-03 請求書番号・再発行世代の維持 |
| `closingcheck` | 締日を99→20に変更→締日変更検査SQLで不一致検出→送信ブロック→締日を99へ復元 | E7 締日変更警告（`SummaryRebuildClosingCheck`） |
| `all` | seed → show → idempotent → closingcheck を順に実行 | 上記すべて |

## テストデータ仕様（テスト月 202607 = 既存取引ゼロのクリーンルーム）

既存取引先に、実マスタの締日/支払・回収条件（得意先=末日締・翌月末回収、仕入先=末日締・当月末支払）のまま紐づける。

| 区分 | 取引先 | 伝票 |
|---|---|---|
| 売上/入金 | 得意先 000002 | 売上100,000/税10,000・返品20,000/税2,000・値引5,000/税500・入金 現金50,000+手数料440 |
| 売上/入金 | 得意先 000014 | 売上30,000/税3,000・入金 現金33,000 |
| 仕入/支払 | 仕入先 001 | 仕入80,000/税8,000・返品10,000/税1,000・支払 現金50,000+相殺20,000 |
| 仕入/支払 | 仕入先 002 | 仕入15,000/税1,500・支払なし |

### 期待値（手計算）

| 帳票 | 取引先 | 主要値 |
|---|---|---|
| 請求台帳 | 000002 | 売上額83,500 入金額50,440 残高-33,060 入金予定日20260831 番号 `{Id}-20260731-01` |
| 請求台帳 | 000014 | 売上額33,000 残高0 入金予定日20260831 |
| 支払台帳 | 001 | 仕入額77,000 支払額70,000 残高-7,000 支払予定日20260731 |
| 支払台帳 | 002 | 仕入額16,500 支払額0 残高-16,500 支払予定日20260731 |

税は返品分を符号反転（請求 8,500=10,000−2,000+500 / 支払 7,000=8,000−1,000）。

## UAT-05/06 実施手順（証跡の取り方）

1. `refer/back/` に対象DBをバックアップ。
2. `dotnet run --project tools/summaryreconcile -- all` を実行し、出力を証跡として保存。
3. `show` 出力の各値が上表の期待値と一致することを確認（数値突合）。
4. `idempotent=PASS`（再計算で番号・金額・予定日が不変）、`closingcheck=PASS`（締日変更でブロック）を確認。
5. 帳票PDFの目視確認は WPF クライアントから請求台帳/支払台帳/請求一覧表/支払一覧表/月別予定表を出力して行う（本ツールはSQL層の突合まで）。

（`Program.cs` の `Clean()` と同じ）。
