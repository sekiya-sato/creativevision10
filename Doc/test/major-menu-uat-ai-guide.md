# 大メニューUATのAI向け手順

大メニューのUAT依頼では、この手順を使って調査・計画・実行・証跡整理を行う。画面確認skill `.agents/skills/verify-wpf-screen-runtime/SKILL.md` と `Doc/test/UatVm/README.md` を併用し、実装の事実とUATで確認した事実を区別する。

## 1. 計画を作る

1. `git status --short` と対象範囲の `AGENTS.md` を確認し、既存差分・作業物を保持する。
2. メニュー定義、View/ViewModel、帳票フォーム、既存シナリオ、UAT報告を調べ、対象画面・入力条件・分岐・期待結果を一覧化する。
3. DB確認、データ準備、実ViewModel→CvServer→PDF経路、実WPF表示・画像保存、後片付けの順に計画する。
4. テストデータ投入は依頼内の許可と対象DBを確認して進める。既存データの変更・削除、意味変更や業務判断が必要な場合は、影響・復旧方法を先に整理して判断を求める。
5. 「全分岐」の意味を明示する。選択肢の全組合せが多い場合は代表値で省略せず、優先度・対象外・未検証を合意して記録する。

## 2. DBとテストデータを確認する

1. 対象DB、環境、サーバー接続先、対象年月・コード範囲を特定する。DB名や接続先を推測しない。
2. まず読み取り専用で対象期間の行数・予算/実績・参照マスタを調べ、投入候補が既存データと衝突しないことを確認する。
3. 投入が許可されている場合は、狭く識別可能なコード/年月に限定する。投入処理を再実行しても既存行を上書きしないガードを設け、実行前後の行数・合計を記録する。
4. 売上や伝票等の既存実績を変更せずに済むデータ設計を優先する。UATデータを残す/戻す方針を計画に記し、無断削除や広範囲な復旧SQLを行わない。
5. PDF行数・合計等の期待値は、ViewModel出力とは独立したDB集計でも確認する。生成結果をそのまま期待値にしない。

## 3. 実VM・CvServer経路でPDF分岐を確認する

帳票ごとに、実ViewModelが生成したSQL/パラメータを既存の印刷gRPC経路へ渡し、CvServerからPDFを受け取る。帳票の直接呼出しやPDFの単体描画だけで、画面操作やサーバ経路まで検証したと表現しない。

- 既存の `Doc/test/UatVm` シナリオが対象動作を確認していれば再利用する。必要なら `Scenarios/` にシナリオを加え、`Program.cs` に登録する。
- 帳票分岐が複数ある場合は、分岐値と生成物の対応を一覧にする。再利用可能な専用Runnerを追加するときも、既存のViewModelと `ICoreService.PrintPdfAsync` 経路を使う。
- PDFごとに成功/失敗、フォーム名、印刷データ行数、ページ数、サイズまたはSHA-256を記録する。代表ページだけでなく、最終ページや境界ページも描画確認する。
- `--manage-server` はCvServerの起動と正規終了をUatVmに任せる。別プロセスを使う場合は接続先を明示し、起動主体と終了責任を記録する。

実行の基本形:

```powershell
$env:DOTNET_ENVIRONMENT = 'Development'
$env:ASPNETCORE_ENVIRONMENT = 'Development'
dotnet build CvServer/CvServer.csproj
dotnet build Doc/test/UatVm/UatVm.csproj
Doc/test/UatVm/bin/Debug/net10.0-windows10.0.19041/UatVm.exe <scenario> --manage-server
```

実際の帳票Runnerを使う場合は、そのRunnerのREADME/引数を確認し、対象期間・URL・出力先を明示して実行する。

## 4. UatVmで実WPF画面を表示して画像保存する

1. メニュー定義から各項目のView/ViewModel型を列挙する。`OpenView<TView,TViewModel>()` は実Viewを生成して既定で表示し、XAMLリソース、Binding、コンバータ、描画時例外を確認できる。
2. ViewModelの初期化経路を確認する。`BaseWindow` は表示完了時に `InitCommand` を実行する。必要な初期状態はViewModelプロパティへ設定し、読み込み/検索コマンドを直接実行する。保存・削除などDB更新コマンドは表示確認だけのために実行しない。
3. `--hide-views` を付けずにUatVmを実行し、実画面を一画面ずつ表示して確認する。複数Viewを同時に開く場合は重なりを避け、どの画像がどのViewか特定できるようにする。
4. 画像保存には `.agents/skills/verify-wpf-screen-runtime/SKILL.md` の実画面確認手順と、利用可能な画面キャプチャ手段を使う。UatVmのJSONL証跡はスクリーンショットを保存しないため、別途PNG等を保存し、ファイル名をView型・条件・連番から付ける。
5. 画像には画面全体、主要入力条件、結果一覧/帳票条件が読める範囲を含める。切れ、重なり、空欄、ダイアログ、スクロール位置など、確認した所見を対応する画像名と一緒に記録する。
6. 画面キャプチャを取得できなかった場合、VM/サーバー経路の成功で代替せず、画面目視未確認として報告する。

## 5. 証跡を集約する

作業ごとに `Doc/test/<日付>/<対象>/` 等の新しい専用フォルダを作り、既存報告・他者作業物に上書きしない。最低限、次をまとめる。

- UAT報告README: 対象/対象外、環境・DB・期間・コード範囲、データ準備と残置/復旧方針、実行方法、分岐ごとの結果、未確認事項。
- `run.json` 等: 各帳票/シナリオの条件、PDF名、フォーム名、行数、ページ数、成功/失敗、実行日時。
- UatVm JSONLと `boot.log`: View/ViewModel、実行コマンド、ダイアログ、check/fail/result、サーバー起動・終了。
- 画面画像: 各対象画面と条件に対応した画像。報告書から相対リンクする。
- PDF: 受入に必要な成果物だけ保存し、代表ページ画像または描画確認結果を付ける。

生ログ・出力ファイルだけで済ませず、再実行条件と結果を短いREADMEへ転記する。秘密情報、接続資格情報、無関係なDBデータを証跡へ含めない。

## 6. 人間向け結果報告

報告は「対象と方法」「DB/テストデータ」「画面・帳票の分岐結果」「画像とログの場所」「未確認事項・残余リスク」「後片付け」の順に簡潔にまとめる。コード/ビルドが通ったことと、画面・PDFの実表示確認を混同しない。未実施・失敗・対象外の項目をPASSに含めず、データをDBに残した場合は明記する。

## 7. 後片付け

1. 起動したCvServer/CvWpfclientを特定し、強制終了ではなく通常の終了経路を使う。UatVmの `--manage-server` はサーバーを正規停止する。
2. `Get-Process -Name CreativeVision10,CvServer -ErrorAction SilentlyContinue` で対象プロセスが残っていないことを確認する。
3. 一時スクリプト、スクリーンショット、PDFなどの保存先を確認する。報告に必要な証跡は残し、一時物だけを削除する。投入したUATデータの削除は事前に決めた承認済み手順に従う。
4. `git status --short` と `git diff --check` を確認し、UAT報告・必要な証跡以外の差分を変更/削除しない。commitは明示依頼がある場合だけ行う。

## 予算UATを使った参照例

`Doc/test/uat20260926/yosan/README.md` は予算メニューの例。2026/08の既存予算0件を確認して19行を投入し、実ViewModelとCvServer経由で14PDF・21ページを確認した。UatVmで実WPFの8画面を開き、18判定・8PNGとJSONLを保存した。F6操作、マスタ一覧取得ダイアログ、前年比非ゼロ等の未確認事項も同READMEに記録している。
