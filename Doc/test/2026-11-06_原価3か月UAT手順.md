# 原価3か月UAT 手順（SQLiteのみ・試験用原価履歴）

作成日: 2026-11-06／対象HEAD: `20ebd9f3`
用途: [やることリスト](../spec/2026-11-05_todolist.md) P1-2 のうち、旧CVnet（Oracle）を使わずに、試験用の伝票から3か月連続の原価履歴を作り、原価4項目（消化仕入・諸掛・総平均原価／最終仕入原価・評価替え）の計算をSQLiteで確認する。

## 1. 範囲

## 3. 期待値（手計算）

総平均: `AfterCost = floor((前月在庫数×前月原価 + 当月仕入金額 + 諸掛) / (前月在庫数 + 当月仕入数))`。仕入返品・諸掛返品は負で合算する。最終仕入: 月内最後の通常仕入明細（日付→伝票Id→明細No）で `round_away(金額/数量)`、諸掛は加算しない。

## 4. 実行手順

`Doc/spec/使用ガイドライン.md` 2章・4.1 に従う。共有の開発DBは更新しない。

1. 開発DBの整合したコピーを新しい専用フォルダ `Doc/test/uat-<日時>-cost3m/test.db` に作る（ガイドライン2章「複製DBと専用サーバ」）。
2. `change4uat_run.ps1` で認証を解除し、CvServer と UatVm を build する。
3. 専用ポートで実行する（シードはサーバ起動前に行われる）。

   ```powershell
   & ./Doc/test/UatVm/bin/Debug/net10.0-windows10.0.19041/UatVm.exe cost3m --sqlite $dbPath --url http://127.0.0.1:5017 --manage-server
   ```

4. シナリオは次の順に進む（各手順の判定は JSONL に記録）。
   1. 消化仕入更新 2026/11・2026/12・2027/01（確認→更新）。2026/11 を再度確認→更新して二重計上が無いこと。
   2. 在庫のみ再集計 2026/11〜2027/01。在庫累計を 3.1 と照合。
   3. 諸掛確認 2026/11・2026/12。
   4. 総平均原価更新 2026/11 → 2026/12（確認一覧と保存値を 3.4 と照合、D の対象外）。
   5. 評価替え 2026/12（B、80%）。
   6. 総平均原価更新 2027/01。
   7. T-04: 2026/11 を確認 → A の仕入を追加 → 更新が中断されること。
   8. T-05: 在庫のみ再集計 → 2026/11 を再確認（後続月を含む確認一覧を照合）→ 更新 → 保存値・現在原価を 3.6 と照合。
   9. 原価方式を最終仕入原価へ切替え、最終仕入原価更新 2026/11・2026/12・2027/01 を順に実行して 3.7 と照合。
5. 終了コード・VERDICT・JSONL を確認し、結果を本書 5章に記録する。
6. 専用サーバを正規停止し、`change4uat_run.ps1 enable_auth` で認証を戻して CvServer を再 build する（失敗時も実施）。

### 5.2 事項D（製品修正 2026-11-06、未コミット）

- 現象: 初期原価0の商品C を、後続月の結果が出た後に初回月（2026/11）から再計算すると、前原価が「現在の商品原価」（400＝2027/01 の結果）になった。「解決した前原価が0以下なら現在の `TankaGenka` を使う」規則による。前月在庫0のため原価結果（333）は変わらないが、前月在庫がある商品では将来月の原価が過去月の計算に入り得る。
- 判断: 利用者判断で製品を修正（2026-11-06）。
- 修正: `CostUpdateDbCost` の総平均原価・最終仕入原価で、現在原価へ置き換えるのは「基準行（`SumMonth=190101`）以外の原価履歴が無い商品」だけにした。基準行だけの商品は従来どおり現在原価（商品マスタで設定した値）を使うため、設計 §6.5 の「原価0円で対象外 → 商品マスタに原価を設定して再実行」は引き続き有効。単体テスト `PreviewTotalAverageCost_RerunFirstMonth_DoesNotUseLaterCurrentCost`・`PreviewTotalAverageCost_BaselineOnlyZero_UsesCostSetInMaster` を追加。
- 影響: 計算済み履歴がある商品で、前原価の解決結果が0円になる過去月の再計算だけが変わる（前月在庫ありなら「原価未設定のため対象外」になる）。
- 対象外: 消化仕入（原価代用）の計算単価にも同じ置き換えがあるが、変えると単価0のエラーになり仕入金額の結果が変わるため、今回は変更していない。
