# 原価2022年試算（実データ・SQLite）

確認日: 2026-11-06／対象HEAD: `bef8e2c6` ＋ 本試算シナリオ・最終仕入の0円明細除外（いずれも未コミット）
用途: [やることリスト](../spec/2026-11-05_todolist.md) P1-2 の「旧CVnet 3か月突合」の置き換え（利用者判断 2026-11-06）。

## 1. 背景と方針

旧CV（Oracle スキーマ `CV52`）を読み取り専用で調べた結果（2026-11-06）:

- 商品マスタの `原価計算方法FLG` は 10,118件すべて0。月次在庫表 `HC$MANAGE_ZAIKO`（2009/10〜2025/11）の在庫原価・入庫原価は全月0。原価変更履歴 `HC$MASTER_SHOHIN_GENKA_HENKOU`（13,973件）は担当者・仕入伝票NOが空の手入力変更で、移動平均・評価替えのフラグも全件0。→ **旧CVは固定原価で運用しており、総平均原価の記録は無い。**
- CV10 開発DB（`server-user52.db`）との対応: 商品原価（原価が正の 8,464件、合計 41,299,369円）が完全一致。2022/01〜05 の伝票件数（本社売上・店舗売上・生地付属仕入・仕入・移動）が全月一致。生地付属仕入の明細金額は一致、仕入の明細金額は月 −2〜+10円の端数差。CV10 開発DBの原価方式も固定原価（`CostMethod=0`）。
- 伝票は 2022/05 でほぼ止まっている。

旧CVに比べる値が無いため「突合」はできない。代わりに **2022/02〜04 の実データで CV10 の総平均原価・最終仕入原価を試算し、結果の妥当性を利用者が確認する** 形にする。

## 2. 手順

- 開発DBの複製 `Doc/test/uat-20261106-cost2022/test.db`（git管理外）で、UatVm `cost2022`（[Cost2022TrialScenario](UatVm/Scenarios/Cost2022TrialScenario.cs)）を `--sqlite`・専用URL `http://127.0.0.1:5017`・`--manage-server` で実行。前後で認証を解除・復元（ガイドライン 4.1）。
- 流れ: 原価方式を総平均へ（シーダー）→ 在庫のみ再集計 2022/01〜04 → 月ごと（02→03→04）に諸掛確認・総平均の確認・検算・更新 → 原価方式を最終仕入へ（gRPC汎用更新で代用）→ 最終仕入 02〜04 のプレビュー・検算（更新しない）。
- 検算は製品の計算ロジックを呼ばずに行う: 当月仕入（区分10/20、返品は CalcFlag で負）・前月在庫（在庫集計の前月まで合計）・諸掛を C# で集計し直して確認一覧と比較し、原価は算式 `floor((前月在庫数×前原価＋仕入金額＋諸掛)÷(前月在庫数＋仕入数))` で確かめる。最終仕入は採用明細（日付→伝票Id→行No 最大）と `round_away(金額÷数量)` を独立に求める。
- 出力（複製DBと同じフォルダ、UTF-8 BOM の CSV）: `00_summary.csv`、`10_総平均_2022MM.csv`、`20_最終仕入_2022MM.csv`。証跡 `Doc/test/UatVm/out/cost2022-20261106-*.jsonl`（第1回 `150802`、第2回 `151641`）。

### 3.1 利用者に確認してほしい点

1. **固定原価と総平均の差（原価の下落）**: 前月在庫0で当月仕入だけから原価が決まる商品について、旧CVの固定原価と仕入単価の比を見ると、1.00（固定原価＝仕入単価）の商品と、1.19〜1.30倍の商品に分かれる（例: 2022/04 は40商品中、1.23倍が17件、1.00倍が8件）。旧CVの固定原価に仕入単価への上乗せ（輸入諸掛などと推定）が含まれている商品は、総平均にすると原価が約2割下がる（例: `102102034` 4,797→3,696、`102104045` 4,699→3,621）。総平均で上乗せ分を原価に入れるには、生地付属仕入で商品ごとに諸掛を入力する運用が要る（2022/02〜04 の諸掛明細は1行だけ）。
2. **最終仕入の0円明細**: 2022/03/07 の `102104010` に、0円の仕入（区分10）と同数量・0円の返品（区分20）が3行ずつ組で入っている（旧CVの `HC$TRAN_TORI0/1` も同じ。打ち消しの伝票と推定）。最終仕入原価は月内最後の通常仕入明細を採用するため 0円の明細を拾い、「計算後原価が0円以下」のエラーで 2022/03 の更新全体が止まる。総平均は仕入が相殺されるため影響しない。
   → **製品修正（利用者判断 2026-11-06、未コミット）**: 最終仕入原価の採用対象を「明細金額が0より大きい明細」に限定した（`CostUpdateDbCost.ComputeLastPurchaseForMonth`）。0円明細しか無い商品は当月仕入なしと同じく更新しない（`102104010` は 2022/03 の対象から外れ、原価を維持）。月次状態の対象商品数（`CostUpdateDb.FetchEligibleProductCount`）も同じ条件にし、再実行要と誤判定しないようにした。単体テスト2件を追加。
3. **仕入の無い月の諸掛**: 2022/02/04 の諸掛 −3,583円（`102102205`、前月在庫124）は、その月に仕入が無いため総平均の対象外となり原価に反映されない（諸掛確認では「情報」）。負の諸掛（区分10・金額マイナス）が意図どおりかも確認が要る。
4. 試算の前原価（基準）は現在の商品マスタ原価で、2022年当時の原価ではない。旧CVの原価変更履歴は 2022/02 以降に 103件（2022/02 34件、03 37件、04 29件、2023/02 3件）あり、これらの商品は当時と前原価が異なる。
