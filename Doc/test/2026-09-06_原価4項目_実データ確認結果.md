`Doc/spec/2026-09-05_原価4項目_詳細設計.md` §11.4「実データ確認」の実施結果。

対象:

- 旧CV.net Oracle スキーマ **CV163**（`192.168.9.243/cvnet`）
- CV10 移行済みSQLite `CvServer/server-user163.db`（DBバージョン 26090601 時点）

**重要な限定**: 旧Oracle側の確認は **CV163 の1スキーマのみ**である。
§3.2 の `ManualNo` に関する結論は「全77スキーマの実測」によるものだが、
本書の結果はCV163に限る。他スキーマで異なる可能性は否定できない。
ただし**CV10へ移行するのはCV163**であり、移行結果を論じるうえでは本書の数字が該当する。

| 仕入区分 | 件数 | 消化計算区分 | 消化掛率 | 消化桁切指定 | 消化端数区分 |

商品マスタ 80,409件。**`仕入区分=3`（消化仕入）は0件**、

`HC$MASTER_SHOHIN` に `仕入仕方区分` 列は存在しない（§16.5 が言及する
旧CV.netの `仕入仕方区分 NOT IN (4,5)` は、CV163のこのテーブルには該当列が無い）。

**結論**: 消化仕入はCV163では一度も運用されていない。§4.2 の

検証には新規テストデータが必要である（完成度チェックリスト §6.1 の

| `行NO` | 件数 |
|---:|---:|

## 4. `関連商品CD` の照合率（§11.4 第4項）

### 4.1 全伝票

```sql
SELECT 関連商品CD, COUNT(*) FROM HC$TRAN_TORI1 GROUP BY 関連商品CD
```

明細1,140万行に対し、**相異なる値はわずか6種類**。

| `関連商品CD` | 件数 |
|---|---:|
| `.` | 11,406,297 |
| `黒` | 2 |
| `白` | 2 |
| `赤` | 2 |
| `木目` | 2 |
| `20120320033` | 1 |

### 4.2 生地付属仕入（`伝票処理区分 = 2`）に限定

諸掛の対象は生地付属仕入である（§3.3）。同区分の明細だけに絞る。

| `関連商品CD` | 件数 |
|---|---:|
| `.` | 1,728 |
| `20120320033` | 1 |

明細1,729件。**うち1,728件（99.94%）が `.`** であり、商品コードとして解決できない。
唯一の候補 `20120320033` は `HC$MASTER_SHOHIN.商品CD` に**1件ヒットする**（解決可能）。

### 4.3 移行時の `Id_Shohin=0` 件数の見積り

**1,728件（99.94%）が `Id_Shohin=0` になる。解決できるのは1件のみ。**

Step 6 で実装した `ConvertDbTran.BuildMaterialMeisaiList` の移行は、
解決できないコードを異常終了させず `Id_Shohin=0`・`Code_Shohin=旧コード` として扱う設計であり、
この結果でも移行は完走する。解決失敗件数はログに1回だけ出る。

**含意**: 諸掛はCV163の移行データでは機能しない。
§3.1 の運用前提「1明細 = 1商品、入力者が按分」は**今後の運用で入力するもの**であり、
移行データに遡って諸掛が成立するわけではない。
Step 10-6 で生地付属仕入入力へ商品欄を追加したのはこのためである。

**注意**: §3.2 は全77スキーマの実測から「対応キーは明細の `関連商品CD` だった」と結論したが、
少なくともCV163では `.` の埋め草であり、対応キーとして機能していない。
§3.2 の結論と本書の結果は矛盾しないが（「`手入力伝票NO` ではない」点は共通）、
**「`関連商品CD` に実データが入っている」という期待はCV163には当てはまらない**。

## 5. 原価0円・負在庫による全件停止リスク（§11.4 第5項。**D-20 の判断材料**）

CV10移行済みデータ（`server-user163.db`）で、§6.1 の抽出条件を満たす商品のうち
§6.5 でエラーになる件数を月別に数えた。

抽出条件（§6.1）: 対象期間に `IsStock=1`・`IsPay=1`・`Kubun IN (10,20)` の仕入がある
`MasterShohin.IsZaiko=1` の商品。

エラー条件（§6.5）:
- `OpeningQty > 0` かつ `BeforeCost <= 0`（前月在庫があるのに原価0）
- `OpeningQty < 0`（負在庫）

| 計上月 | 対象商品 | 原価0エラー | 負在庫エラー | エラー計 | エラー率 |
|---|---:|---:|---:|---:|---:|
| 202201 | 685 | 371 | 42 | 413 | **60%** |
| 202202 | 625 | 307 | 47 | 354 | **57%** |
| 202203 | 524 | 199 | 86 | 285 | **54%** |
| 202204 | 586 | 262 | 53 | 315 | **54%** |
| 202205 | 328 | 200 | 42 | 242 | **74%** |

参考: 在庫対象商品（`IsZaiko=1`）49,141件のうち、**`TankaGenka <= 0` が15,335件（31%）**。

### 5.1 これが意味すること

§6.5 は「1商品でもエラーがあれば当月の総平均原価更新が一切実行できない」と定めている
（§2.4-2 のエラー1件で更新不可、§10.2 の全件ロールバックとの組み合わせ）。

**したがって移行データでは、どの月も総平均原価更新を1件も実行できない。**
5ヶ月すべてで対象商品の半数以上がエラーになるため、
「運用で少しずつ是正する」では現実的に到達しない。

### 5.2 D-20（U-15）への論点

原因は2種類あり、対処が異なる。

| 原因 | 件数の規模 | 性質 |
|---|---|---|
| **原価0円**（`TankaGenka<=0` かつ前月在庫あり） | 月あたり200〜371件 | 移行時に原価が入っていないだけ。データを入れれば解消する |
| **負在庫**（`OpeningQty<0`） | 月あたり42〜86件 | 在庫の整合性そのものの問題。U-06 で「中断」と決定済み |

原価0円のほうは、§2.6 の**初回基準行生成マイグレーション**で
`MasterShohin.TankaGenka` を埋められれば解消しうる。ただし
**そもそも原価が未設定の商品に何を入れるか**は業務判断であり、本設計の範囲外である。

負在庫のほうは U-06 で「計算可能でも中断する」と決定済みであり、
在庫訂正が前提になる。

**D-20 の選択肢（U-15）**:

1. **全件停止のまま運用で是正** — 移行直後は総平均原価更新が使えない。
   原価0円15,335件の是正と、負在庫の在庫訂正が先行する
2. **恒久除外設定を新設** — `IsZaiko=0` へ落とす、または除外フラグを設ける

本書は件数を出すところまでとし、判断は行わない。
なお **`CostMethod=1`（最終仕入原価）は §6.5 のエラー条件を持たない**ため、
移行直後も実行できる。総平均原価が使えるようになるまでの暫定運用の選択肢にはなる。

## 6. 未実施

§11.4 の最後の項目
「最低3ヶ月について旧CV.netの諸掛金額（商品別）、総平均原価、消化仕入金額と比較する」
は**未実施**である。理由:

- **諸掛**: §4 のとおりCV163では `関連商品CD` が未使用のため、
  旧側に「商品別の諸掛金額」が存在しない。比較対象が無い
- **消化仕入**: §2 のとおりCV163では消化仕入が未運用のため、比較対象が無い
- **総平均原価**: 比較は可能だが、旧側の月次原価がどのテーブル・列に残っているかの
  特定から必要であり、本作業では着手していない

**総平均原価の突合は残作業として残る。** §5 のとおり移行データでは
総平均原価更新自体が実行できないため、**D-20 の決着が先行する**。

## 7. 使用したクエリ

再現できるよう主要なものを残す。

```sql
-- §2 消化仕入設定
SELECT 仕入区分, COUNT(*) AS CNT,
       MIN(消化計算区分) AS CALC_MIN, MAX(消化計算区分) AS CALC_MAX,
       MIN(消化掛率) AS RATE_MIN,   MAX(消化掛率) AS RATE_MAX,
       MIN(消化桁切指定) AS DIG_MIN, MAX(消化桁切指定) AS DIG_MAX,
       MIN(消化端数区分) AS FRA_MIN, MAX(消化端数区分) AS FRA_MAX
FROM HC$MASTER_SHOHIN GROUP BY 仕入区分 ORDER BY 仕入区分;

-- §3 Jgenka の行NO分布
SELECT 行NO, COUNT(*) FROM HC$MASTER_SHOHIN_GENKA GROUP BY 行NO ORDER BY 行NO;

-- §4.2 生地付属仕入の関連商品CD
SELECT d.関連商品CD, COUNT(*) AS CNT
FROM HC$TRAN_TORI1 d JOIN HC$TRAN_TORI0 h ON h.SEQ_NO = d.ヘッダNO
WHERE h.伝票処理区分 = 2 GROUP BY d.関連商品CD ORDER BY CNT DESC;
```

CV10側（SQLite）の月別エラー件数は、§6.1 の抽出条件と §6.5 のエラー条件を
`Tran03Shiire` / `SummaryStock` / `MasterShohin` から組み立てた集計SQLによる。
`SummaryStock.CumulativeSu` は使わず `Su` の累計で前月在庫を求めている（§6.2）。
