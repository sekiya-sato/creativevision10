## 1. 目的と背景

### 1.1 選定理由

完成度チェックリスト §4.1 段階7・§3.11 の P0 Release Gate は「支払計算が生成した `SummaryKaiShi` を帳票と数値突合する」ことである。請求側は請求台帳（発行控え, `943aa16`）で確定値を突合帳票化した。その支払側の対として本帳票を新設する。

支払計算（`SummaryDb.CalcSummaryKaiShi`）は締め時点で確定した **`ShiharaiYoteiDay`（支払予定日）** を `SummaryKaiShi` に保存済みだが、次のとおり**どの帳票も出力していない**:

- 「支払一覧表」(`ShiharaiListReport.qfm`) は金額中心（仕入/返品/値引/税/支払/残高）で支払予定日を持たない。
- 「月別支払予定表」(`MonthlyShiharaiYoteiTable`) は `MasterShiire` の `PayMonth`/`PayDay` から**ライブ再計算**しており、保存済み `ShiharaiYoteiDay` とは別物（請求側の「月別入金予定表」と同じ構造）。

したがって「支払計算の確定結果（保存済み支払予定日）を突合・確認する帳票」が欠落している。これを埋める新帳票 **支払台帳（発行控え）** を作る。データ源（`SummaryKaiShi`）は実装済み。D-04/D-05 にブロックされない（社内の発行確認・突合用の管理一覧のため）。

### 1.2 請求台帳との差異

`SummaryKaiShi` には請求側の `SeikyuNo`・`Renban` に**相当する列が存在しない**（`CvBase/BaseDbKake.cs`）。よって支払台帳は番号・再発行世代を持たない**9列構成**とし、空いた分を支払額(`TotalOut`)へ充てて 仕入額+支払額+残高 で対称化する。

### 1.3 既存帳票との棲み分け

| 帳票 | 用途 | 保存済み支払予定日 |
|---|---|---|
| 支払一覧表 (既存) | 支払日単位の金額一覧 | 出力しない |
| 月別支払予定表 (既存) | 支払条件からのライブ再計算予定額 | 出力しない（ライブ再計算） |
| 支払残高明細書 (既存) | 仕入先1件ごとの明細（単票） | 出力しない |
| **支払台帳（発行控え）(新設)** | 支払計算の確定結果の突合・発行控え（一覧） | **出力する** |

## 2. 仕様

### 2.1 データ源

`SummaryKaiShi k` JOIN `MasterShiire s ON s.Id = k.Id_Shiire`（既存 `ShiharaiListReport` と同一の結合）。

### 2.2 出力列（qfm item1..item9、SELECT 列順と一致）

| # | item | 見出し | ソース | 型/整形 |
|---:|---|---|---|---|
| 1 | item1 | 支払日 | `DateLabel(k.DenDay)` | yyyy/MM/dd |
| 2 | item2 | 仕入先CD | `s.Code` | 文字列 |
| 3 | item3 | 仕入先名 | `s.Name` | 文字列 |
| 4 | item4 | 対象期間 | `DateLabel(k.DayFrom)‖'～'‖DateLabel(k.DayTo)` | 文字列 |
| 5 | item5 | 仕入額 | `k.TotalShiire` | 整数（右詰） |
| 6 | item6 | 消費税 | `k.Tax` | 整数（右詰） |
| 7 | item7 | 支払額 | `k.TotalOut` | 整数（右詰） |
| 8 | item8 | 残高 | `k.Balance` | 整数（右詰） |
| 9 | item9 | 支払予定日 | `DateLabel(k.ShiharaiYoteiDay)` | yyyy/MM/dd（空欄可） |

金額列の `decode` は既存 `ShiharaiListReport.qfm` / `SeikyuLedgerReport.qfm` と同じく `datatype="string"`（SQL は生の整数を返す）を踏襲。カンマ整形は入れない（qfm 仕様 §5.2 の将来改善余地）。

### 2.3 入力パラメータ（画面）

`ShiharaiListReport` と同一の UI:

- 支払日 From / To（`yyyy/MM/dd`、既定 = 当月1日〜今日）
- 仕入先 From / To（コード範囲、検索ダイアログ付き、空欄可）
- 出力対象: 「支払額･残高があるのみ」(既定) / 「全て」

検証: 日付書式不正 → 警告して中止。From > To → 「支払日の範囲が逆転しています。」警告して中止。

### 2.4 SQL（列順 = item 順）

```sql
SELECT
    {DateLabel("k.DenDay")}  AS payDayLabel,
    s.Code AS shiireCode,
    s.Name AS shiireName,
    {DateLabel("k.DayFrom")} || '～' || {DateLabel("k.DayTo")} AS termLabel,
    k.TotalShiire AS totalShiire,
    k.Tax         AS tax,
    k.TotalOut    AS totalOut,
    k.Balance     AS balance,
    {DateLabel("k.ShiharaiYoteiDay")} AS shiharaiYoteiLabel
FROM SummaryKaiShi k
JOIN MasterShiire s ON s.Id = k.Id_Shiire
WHERE k.DenDay >= @from AND k.DenDay <= @to
  {activeOnly}{shiireWhere}
ORDER BY k.DenDay, s.Code
```

- `@from` / `@to` = 支払日範囲（`yyyyMMdd`）。`AddSqlParameter` で採番。
- `activeOnly` = `IsActiveOnly` のとき `AND (k.TotalOut != 0 OR k.Balance != 0)`。
- `shiireWhere` = `BuildCodeRangeWhere(params, "s.Code", from, to)`。

## 6. 非対象・リスク・次工程

- 顧客/仕入先提出用の支払通知書様式は本帳票の対象外（社内突合・発行控え）。
- `SummaryKaiShi` に番号・再発行世代が無いため、請求側 `Renban` に相当する差し替え世代管理は支払側では提供しない（必要ならスキーマ拡張の要件化）。
- 金額のカンマ整形は将来改善（qfm 仕様 §5.2）。
- **次工程（P0/P1）**: 実 DB（`CvServer/server-user163.db`、`refer/back/` にバックアップ済み）で 支払台帳／支払一覧表／月別支払予定表 を出力し、保存済み支払予定日 vs ライブ再計算予定日、金額・残高・繰越を突合。請求側（請求台帳）と対で P0 帳票突合を閉じ、UAT-06（買掛・支払）へ接続する。
