## 1. 目的と位置づけ

移行時の**期首売掛残・期首請求残・期首買掛残・期首支払残**を、期首日より前の年月／年月日を持つ
`Summary*` 行として投入する専用画面を新設する。

2026-08-19 の D-08 決定は「専用画面は作らず `ExternalCsvImportView` で代替」であったが、
方針を改め、**外部CSVマスタ取込（`ExternalCsvImportView`）と取込レイアウト作成
（`ImportTemplateCreateView`）の実装を流用した専用画面**を新設する（承認事項A）。

汎用CSV取込のままでは残高投入に必要な次の点が担保できないため、専用画面が必要である。

| 汎用CSV取込の不足 | 本画面での対応 |
|---|---|
| 再取込で一意キー（`uk1`）違反になる（`InsertBulkParam` は Insert のみ） | 対象日付＋対象取引先の既存行を削除してから登録する洗い替え（1トランザクション） |
| 期首日より前の年月／日で入れる必要があるが検査が無い | `MasterSysman.FiscalStartDate` を読み、期首前であることを必須検査 |
| **繰越の引き継ぎ方が掛と請求／支払で異なる**（3章）ため、手書きCSVでは繰越が効かない事故が起きる | 画面が両方式を自動で埋め、整合を検査 |
| 残高の符号（内部は負＝未回収）が直感と逆 | 業務語のCSV（正数＝未回収残）を入出力し、内部符号は画面が変換 |
| テーブル名・内部列名・型行を書いたCSVを移行担当者が作る必要がある | 画面が取引先一覧入りのテンプレートCSVを出力する |
| 部分失敗でDBが中途半端になる | サーバー側1トランザクション |

## 2. 対象テーブルと期首行のキー

| 残高区分 | テーブル | 一意キー(uk1) | 期首行の日付 | 取引先マスタ |
|---|---|---|---|---|
| 売掛 | `SummaryUriKake` | `Id_Tokui` + `DenMonth`(yyyyMM) | 期首年月の前月 | `MasterTokui` |
| 請求 | `SummaryUriSei` | `Id_Tokui` + `DenDay`(yyyyMMdd) | 期首日直前の締日 | `MasterTokui` |
| 買掛 | `SummaryKaiKake` | `Id_Shiire` + `DenMonth`(yyyyMM) | 期首年月の前月 | `MasterShiire` |
| 支払 | `SummaryKaiShi` | `Id_Shiire` + `DenDay`(yyyyMMdd) | 期首日直前の締日 | `MasterShiire` |

`Summary*` 4テーブルに `V*`（`CodeNameView`）列は無い。取引先名はプレビュー表示のためだけに使い、DBへは書かない。

## 3. 【重要】繰越の引き継ぎ方が2方式ある

`CvDomainLogic/SummaryDb.cs` の再計算SQLを確認した結果、繰越の読み方が掛と請求／支払で異なる。
**期首行の作り方を間違えると繰越が 0 のまま積み上がる**ため、本画面の中心的な役割はここの吸収である。

| 対象 | 再計算SQLの `previousBalance` | 期首行で必ず埋める列 |
|---|---|---|
| `SummaryUriKake` / `SummaryKaiKake` | `DenMonth < 開始月` の**最大 `DenMonth` 行の `Balance` 列** | `Balance` |
| `SummaryUriSei` | `DayTo < 開始日` の全行の **`SUM(TotalIn - TotalSales)`**（`Balance` 列は読まない） | `TotalIn` と `TotalSales` |
| `SummaryKaiShi` | `DayTo < 開始日` の全行の **`SUM(TotalOut - TotalShiire)`**（同上） | `TotalOut` と `TotalShiire` |

本画面は 4 区分すべてで `Balance`・`TotalIn`/`TotalOut`・`TotalSales`/`TotalShiire` を
同時に矛盾なく書き込むため、どちらの方式でも期首残が正しく起点になる。

### 3.1 符号の規約

内部の `Balance` は `前残 + 入金 − 売上`（買掛は `+ 支払 − 仕入`）であり、**未回収の債権・債務は負値**である。
`Tests/TestServer/SummaryKakeDbTests.cs` の期首残テスト
（`SummaryUriKake { DenMonth="202606", Balance=-5000, TotalSales=5000 }`）と一致する。

**ユーザーが触れるCSVでは常に「正数＝未回収残」**とし、内部符号への変換は画面が行う（承認事項B）。
過入金・過払いなど貸方残は負数で入力する。画面上に符号切替は置かない（4.6 B'）。

### 4.2 ① 期首情報

| 項目 | 型 | 仕様 |
|---|---|---|
| 期首日 | 読み取り専用 | `AppGlobal.LogicGetSysman().FiscalStartDate` を `yyyy/MM/dd` 表示。`19010101` のままなら赤字で「期首日が未設定です。システム管理マスタで設定してください。」と表示し、②③をすべて無効化する |

### 4.3 ② テンプレートCSVの出力

| 項目 | 仕様 |
|---|---|
| 取引先コード範囲 | From/To（空欄可）。部分移行や分割作業に使う |
| 対象件数表示 | 「対象 152件 / うち期首残あり 0件」。区分・締日・コード範囲の変更で再照会 |
| 出力内容 | ラジオ 2択。「全取引先（残高欄は空）」＝新規移行向け（既定） / 「既存の期首残がある取引先のみ」＝修正・再出力向け（現在値を残高欄に入れて出力） |
| 内訳列を含める | チェックボックス（既定OFF）。OFFなら最小3列のみ |
| 出力ボタン | `SaveFileDialog`。既定ファイル名 `期首残高_売掛_202606.csv`（請求・支払は `期首残高_請求_20260630.csv`） |

対象取引先の照会SQL（売掛の例）:

```sql
SELECT t.Code, t.Name, t.Shime1, s.Balance, s.TotalSales, s.TotalIn, ...
FROM MasterTokui t
LEFT JOIN SummaryUriKake s ON s.Id_Tokui = t.Id AND s.DenMonth = @0
WHERE t.TenType IN (1, 3)       -- 卸先・売仕店のみ（倉庫・直営店を除く）
  AND (@1 = '' OR t.Code >= @1) AND (@2 = '' OR t.Code <= @2)
ORDER BY t.Code
```

- 請求・支払は `AND t.Shime1 = @3` を追加する（請求計算・支払計算の対象集合と一致させる）。
- 買掛・支払は `MasterShiire` を使い、`TenType` 条件は無い。

### 4.4 CSVフォーマット（標準形式）

Excelで開いて記入する前提とし、**1行のコメント行＋1行の日本語ヘッダ行＋データ行**とする。
文字コードは **UTF-8（BOM付き）**。BOM付きにするのは Excel で開いたときに日本語が化けないためで、
取込側は既存の `StreamReader(detectEncodingFromByteOrderMarks: true)` がBOM有無どちらも読める。

得意先コード,得意先名,期首残高

得意先コード,得意先名,締日,期首残高,売上,返品,値引,その他売上,消費税,現金入金,振込手数料,電子記録債権,相殺入金,その他入金,入金予定日

#### 4.4.1 列定義

| 列名 | 区分 | 必須 | 内容 |
|---|---|---|---|
| 得意先コード / 仕入先コード | 全 | ○ | `MasterTokui.Code` / `MasterShiire.Code` |
| 得意先名 / 仕入先名 | 全 | — | 参照専用。取込時はマスタ名と照合し、違えば警告（エラーにはしない） |
| 締日 | 請求・支払 | — | 参照専用。①で選んだ締日と違えばエラー |
| 期首残高 | 全 | ○ | **正数＝未回収残**。空欄は0扱い |
| 売上 / 仕入 | 全 | — | 内訳 |
| 返品 / 値引 / 消費税 | 全 | — | 内訳 |
| その他売上 | 請求のみ | — | 内訳（`Sonota`。区分99） |
| 現金入金 / 現金支払 | 全 | — | 内訳 |
| 振込手数料 / 電子記録債権 | 全 | — | 内訳 |
| 相殺入金 / 相殺支払 | 全 | — | 内訳 |
| その他入金 / その他支払 | 全 | — | 内訳 |
| 入金予定日 / 支払予定日 | 請求・支払 | — | `yyyy/MM/dd`。空欄可 |

- 列の順序は自由。ヘッダ名で対応付ける。
- 先頭が `#` の行、および全列が空の行は読み飛ばす。
- ヘッダ名は前後空白・全角半角・かっこ書き（例「得意先名(参考)」）を正規化して照合する。
- 必須列が無ければエラーで停止する。未知の列は警告して無視する。

#### 4.4.2 数値の受け入れ

Excel経由のCSVを前提に、次を正規化してから `long` へ解析する。エラーメッセージには元の値をそのまま出す。

- 前後の空白、桁区切りカンマ（`1,200`）、通貨記号（`¥`）、全角数字・全角マイナス
- `(1200)` は会計表記の負数として `-1200` に読み替える
- 小数点付きは**エラー**（残高は円単位の整数）

#### 4.4.3 互換: 詳細形式（3行ヘッダ）

`ExternalCsvImportView` と同じ 3行ヘッダ形式（テーブル名行・内部列名行・型行）のCSVも自動判別して受け付ける。
1行目1列目が対象4テーブルのいずれか（旧テーブル名 `MANAGE_KAKEURI` 等を含む）であれば詳細形式とみなす。
この形式では `Balance` 列は**内部符号（負＝未回収）**で解釈する。旧システムのダンプをそのまま使う場合の逃げ道であり、
運用の正式フォーマットは標準形式とする。

### 4.5 ③ 取込・検証・登録

#### 4.5.1 行の状態

| 状態 | 条件 | 動作 |
|---|---|---|
| 新規 | 期首残高≠0 かつ 既存行なし | INSERT |
| 上書き | 期首残高≠0 かつ 既存行あり | DELETE → INSERT。備考に現在値を表示 |
| 削除 | 期首残高＝0（空欄含む）かつ 既存行あり | DELETE のみ。備考に現在値を表示 |
| 対象外 | 期首残高＝0 かつ 既存行なし | 何もしない（0の行を作らない） |

テンプレートは全取引先を出力するため大半が「対象外」になる。これにより、残高のある取引先だけが
`Summary*` に入り、テーブルが 0 行で膨らまない。CSVに載っていない取引先の既存行は一切触らない（承認事項E）。

#### 4.5.2 内訳の自動生成と整合検査（承認事項C）

内訳列が無い、または全て空の場合:

- 売掛・請求: `TotalSales = 期首残高`, `TotalIn = 0`, 内訳は全て0, `Balance = -期首残高`
- 買掛・支払: `TotalShiire = 期首残高`, `TotalOut = 0`, 内訳は全て0, `Balance = -期首残高`

内訳列に値がある場合は次を検査し、不一致はエラーとする（自動補正しない）。

- 売掛: `TotalSales = 売上 - 返品 - 値引 + 消費税`
- 請求: `TotalSales = 売上 - 返品 - 値引 + その他売上 + 消費税`
- 買掛・支払: `TotalShiire = 仕入 - 返品 - 値引 + 消費税`
- 共通: `TotalIn`（`TotalOut`）`= 現金 + 振込手数料 + 電子記録債権 + 相殺 + その他`
- 共通: `期首残高 = TotalSales - TotalIn`（買掛・支払は `TotalShiire - TotalOut`）→ `Balance = -期首残高`

## 11. 実装時の補足

- **締日の表示**: `OpeningBalanceCsv.FormatShime` は `28` を超える締日（29/30/31/99）をすべて「末日」と表示する。
  表示専用であり、期首行のキー日付の算出は `OpeningBalanceCsv.GetClosingDay`（`SummaryDb.GetClosingDay` と同一規則、
  月末を超える指定は月末へ丸める）を使うため日付計算には影響しない。
  なお請求計算・支払計算画面（`BaseBillingCalculationViewModel`）は `99` だけを「末日」と表示し 30 は「30日」と出すため、
  同じ締日が画面間で違う表記になり得る。実データが 99 と月末締めのみのため実害は無いが、表記統一は別途検討する。
- **取引先照会の絞り込み**: テンプレート出力では `TenType IN (1,3)`・選択締日・コード範囲で絞る。
  取込時のコード解決では**一切絞らない**。絞ると対象外の取引先が「マスタにありません」という誤ったエラーになり、
  「卸先・売仕店ではありません」（警告）「締日が一致しません」（エラー）という本来の指摘が出せなくなる。
- **`TenType` 列**: `MasterShiire` には `TenType` が無い（`MasterTokui` のみが持つ）。
  買掛・支払の照会SQLでは `0 AS TenType` を出力する。4区分×2スコープの照会SQLを実スキーマで実行するテストで担保している。
- **`Offset` 列**: SQLite の予約語のため照会SQLでは `s."Offset"` と引用符付きで参照する。
- **エラーコード**: 期首以降のキー日付・許可外テーブルなど画面で直せる入力エラーは
  `CvMsgErrorCode.InvalidParameter`(-9904) で返し、想定外エラー(-9902)と区別する。

## 12. 併せて修正した既存不具合（請求書の前回残高）

`CvWpfclient/ViewModels/06Uriage/SeikyuBalanceDetailViewModel.cs` の前回残高が
`s.Balance - s.TotalSales + s.TotalIn` になっていた。`SummaryUriSei` の当月残高は
`Balance = 前回残高 + TotalIn - TotalSales` で作られるため、逆算は
`s.Balance + s.TotalSales - s.TotalIn` である。旧式は当月増減を2回効かせており、
前回残高が `前回残高 + 2 ×（TotalIn − TotalSales）` になっていた。

期首残高を投入すると請求書（`SeikyuBalanceDetail.qfm` の item5「前回残高」）に必ず現れる箇所なので、
**2026-08-21 に本作業と併せて修正した**。

- 符号の規約は開発DBの実データで確認した（`SummaryKaiKake` / `SummaryKaiShi`:
  `Balance=-10400`, `TotalShiire=15400`, `TotalOut=5000`、前残0 → `-10400 = 0 + 5000 - 15400`）。
- QFMは `item5`（前回残高）・`item9`（当月残高）をそのまま印字し、符号反転は行っていない。
- 回帰テスト `CalcSummaryUriSei_PreviousBalanceIsRecoveredByAddingSalesAndSubtractingPayments`
  （`Tests/TestServer/SummaryKakeDbTests.cs`）で、連続2締期間を計算し、正しい式が前月の当月残高と
  一致し、旧式が一致しないことを固定した。

### 残る論点（本作業では変更しない）

帳票は `前回残高` / `当月残高` を内部符号のまま印字するため、未回収の債権が**負値**で出る。
得意先へ渡す請求書としては正数表示が自然だが、これは `balance`（当月残高）側も含む表示方針の変更であり、
前回残高の算式誤りとは別の論点なので今回は触っていない。表示符号を変えるなら
`SeikyuBalanceDetail`・`SeikyuListReport`・`SeikyuLedgerReport` などを揃えて判断する必要がある。
