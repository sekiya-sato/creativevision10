# `Tran*.Rate` 列の掛率・税率分離課題

作成日: 2026-08-24
発端: `Doc/spec/archive/2026-08-24_HHTデータ更新詳細設計.md` の検討中に判明。**HHTデータ更新の実装スコープ外**として切り出した。
状態: **完了（2026-09-02）。案Bを採用し、既存データの洗い替えは実施しない方針で決着した。**
入力画面・移行処理の分離は 2026-08-24 に実装済み。`Rate` は掛率として使う方式で確定しており、
実際の `Rate` 列は変更していない。既存値が残るのは実データに影響しない過去データのみのため、
**そのままとする**（第6章 #1 の決定）。

## 1. 課題

`Tran00Uriage` / `Tran01Tenuri` / `Tran03Shiire` / `Tran12Jyuchu` の `Rate` 列は、
列コメントが「掛率」であるにもかかわらず**入力画面が消費税率(%)として使っていた**。

方針として「`Tran13Hachu` と同様に `Rate` を掛率のまま残し、税率はローカル変数
`taxRatePercent` に分離する」ことが決定し（2026-08-24）、入力画面側は第4章のとおり実装した。
ただし**既存データの移行方針は未決**である（第6章）。

## 2. 現状の実装

### 2.1 `Rate` を税率として使っていた画面（すべて分離済み）

| 画面 | 該当箇所 |
| --- | --- |
| 出荷売上 | `CvWpfclient/ViewModels/06Uriage/ShukkaUriageInputViewModel.cs` `LoadTaxRateAsync()` / `UpdateHeaderTotals()` |
| 店舗売上 | `CvWpfclient/ViewModels/06Uriage/ShopUriageInputViewModel.cs` 同 |
| 仕入 | `CvWpfclient/ViewModels/05Shiire/ShiireInputViewModel.cs` 同 |
| 受注 | `CvWpfclient/ViewModels/04Juchu/JuchuInputViewModel.cs` 同 |

いずれも 2026-08-24 に 2.2 の形（ローカル `taxRatePercent`）へ統一した。分離前は次の形だった。

```csharp
async Task LoadTaxRateAsync() {
    var rate = await AppGlobal.LogicGetTax(1, Current.DenDay);
    CurrentEdit.Rate = rate;              // ← 税率を Rate へ入れている
    UpdateHeaderTotals();
}

void UpdateHeaderTotals() {
    var absKingakuTotal = Math.Abs(CurrentEdit.KingakuTotal);
    var tax = (int)Math.Round(absKingakuTotal * CurrentEdit.Rate / 100.0);   // ← Rate を税率として使用
    CurrentEdit.Tax = tax;
    CurrentEdit.Total = absKingakuTotal + tax;
}
```

### 2.2 目標とする形（発注が既に実装済み）

`CvWpfclient/ViewModels/03Hatchu/HachuInputViewModel.cs` は税率を `Rate` から分離している。

```csharp
// 仕入先掛率(Rate)から分離した消費税率のキャッシュ。伝票を開いた時点の発注日基準で LoadTaxRateAsync が更新する。
int taxRatePercent = 10;

void UpdateHeaderTotals() {
    var absKingakuTotal = Math.Abs(CurrentEdit.KingakuTotal);
    var tax = (int)Math.Round(absKingakuTotal * taxRatePercent / 100.0);
    CurrentEdit.Tax = tax;
    CurrentEdit.Total = absKingakuTotal + tax;
}

async Task LoadTaxRateAsync() {
    taxRatePercent = await AppGlobal.LogicGetTax(1, Current.DenDay);
    UpdateHeaderTotals();
}
```

### 2.3 移行処理も分離済み（2026-08-24）

`CvDomainLogic/ConvertDbTran.cs` は旧CVnetの「掛率1」を `Rate` へ入れていたが、
2026-08-24 に次のとおり分離した（該当5箇所: `Tran00Uriage` / `Tran01Tenuri` / `Tran03Shiire` / `Tran12Jyuchu` / `Tran13Hachu`）。

- `Rate` = 取引先マスタ(`MasterTokui.RateProper`)の掛率。`getTorihikiRatePercent(取引先CD1)` で引く（コード→掛率をキャッシュ）
- 消費税・総合計は従来どおり旧「掛率1」（実質すべて税率値）から `CalcMigratedTaxTotal()` で導出。ローカル変数名を `taxRatePercent` に変更
- マスタが引けない取引先は `Rate = 0`（未設定）。税率値を掛率として残さない

再変換すれば `Rate` は掛率になる。**既存の移行済みデータは再変換しない限り税率値(10)のまま**（第6章-1）。

## 3. 既存データの実態（`server-user163.db` / 2026-08-24 確認）

| テーブル・列 | 値の分布 | 意味 |
| --- | --- | --- |
| `Tran00Uriage.Rate` | **10 が 50,311件**、0 が 5件 | 全件が税率。掛率として読み替えると「掛率10%」と誤解釈される |

## 4. 実装内容（2026-08-24・入力画面）

入力画面4本（出荷売上・店舗売上・仕入・受注）を発注(2.2)と同じ形へ統一し、あわせて返品入力の `Rate` 格納も直した。

- 消費税率をローカルフィールド `int taxRatePercent = 10` に分離。`UpdateHeaderTotals()` はこれを使う。
- `LoadTaxRateAsync()` は `taxRatePercent` のみ更新し、`CurrentEdit.Rate` を書かない。
- 伝票を開くたび `OnCurrentEditChangedCore` から `LoadTaxRateAsync()` を呼ぶ（従来の `Rate == 0` 条件付き呼び出しは削除）。
  既存伝票の `Rate` が税率10のままでも `Tax` は `MasterSysman` の税率で計算される。
- `PropertyChanged` の再計算トリガから `Rate` を除外（掛率変更は税額に影響しない）。
- 掛率の供給元を明示: 仕入は `MasterShiire.RateProper`、出荷売上・受注は `MasterTokui.RateProper` を
  取引先選択時に `Rate` へ設定する。新規伝票の既定値は発注と同じ `Rate = 100`（仕入・受注）。
  店舗売上(`Tran01Tenuri`)は `Rate` を保存列に含めないため税率分離のみ。
- 返品入力(`05Shiire/HenpinInputViewModel.cs`)も `Rate = taxRate` をやめ、仕入先掛率(`MasterShiire.RateProper`)を格納するよう修正。
  税額計算は元からローカル `taxRate` を使っており変更なし。
- 選択ダイアログがCode/Nameしか返さない問題に使う1件取得を `AppGlobal.LogicGetMasterById<T>(id)` へ共通化し、
  発注の `LoadFullShiireAsync` もこれを呼ぶよう置き換えた。

対象ファイル: `CvWpfclient/ViewModels/06Uriage/ShukkaUriageInputViewModel.cs`,
`06Uriage/ShopUriageInputViewModel.cs`, `05Shiire/ShiireInputViewModel.cs`, `04Juchu/JuchuInputViewModel.cs`,
`03Hatchu/HachuInputViewModel.cs`, `05Shiire/HenpinInputViewModel.cs`, `CvWpfclient/AppGlobalSub.cs`, `CvDomainLogic/ConvertDbTran.cs`（移行処理は 2.3）。

画面の項目名は4本ともすでに「掛率」表記であり、XAMLの変更は不要だった。

## 5. HHTデータ更新側の扱い（決定済み・対応不要）

`Doc/spec/archive/2026-08-24_HHTデータ更新詳細設計.md` の決定 F / G により、HHT変換で新規作成する伝票は
最初から次の形で作る。よって本課題の解決を待つ必要はない。

- `Rate` = VULCANの掛率（パーセント整数。`MasterTokui.RateProper` と同単位）
- 税率は `MasterSysman` から取得したローカル値で `Tax` / `Total` を計算し、`Rate` は使わない

入力画面側の分離（2.2 の形への統一）は第4章で実施済みのため、HHT変換が作った伝票を入力画面で開いても
`Tax` が掛率で誤計算されることはない。
