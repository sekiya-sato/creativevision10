# ポイント制度 テーブル設計

- 設計日: 2026-10-06
- 範囲: 定義・登録・旧ランクの構造移行。付与計算(ベース+ランク)と再計算は§8(2026-10-06追記)。ボーナス・利用・失効・手動登録は `2026-10-08_ポイントボーナス・利用・失効_詳細設計.md` で実装済み（2026-10-08）。過去履歴移行は別途。

## 1. 構成

| テーブル | 用途 | 一意キー |
|---|---|---|
| MasterPointBase | 制度コード・版・期間ごとの基本条件 | Code, Version |
| MasterPointRank | ベース版に属するランク別置換条件 | Id_PointBase, Kubun |
| MasterPointBonus | ベース版に対する固定追加付与条件 | Code, Version |
| TranPointEvent | 伝票・操作・適用条件ごとの増減台帳 | EventKey |
| SummaryPoint | 既存の派生残高・購入実績（今回は未変更） | Id_Customer |

全表はBaseDbClassのId(long)、Vdc/Vdu(UTC.Ticks)を継承する。新規金額・付与数・台帳増減はlong。
固定選択肢はint列と非永続EnXxx変換を持つ。ランクコード・版・回数はenumではない。

## 2. ベース

- Code(20)、Name(80)、Version(1以上)、DayFrom/DayTo(yyyyMMdd)、IsEnabled。
- PointUnitPrice(long正数)、PointAmountProper/PointAmountSale(long非負)。
- TaxBasis: EnumPointTaxBasis（0税抜、1税込）。売価の外税/内税とは独立した金額基準。
- CalcUnit: EnumPointCalcUnit（0伝票、1明細）。税計算単位の請求/伝票とは異なる。
- Roundingは既存EnumRounding、IsEnabled/DeductPointUseは既存EnumYesNo。
- 新規は無効。終了日を含む期間で、同一Codeの有効条件の重複を禁止する。

## 3. ランク

- Id_PointBase(long)、Kubun(intの安定したランクコード)、Name(40)、付与単価・P/S付与数(long)。
- 該当ランクはベースの単価・付与数を置換。税基準・計算単位・丸め・利用額控除・期間は親を継承する。
- 旧ランクは親Id=0で既存値を保持。親設定前は適用対象外、新規/修正は実在親Id>0が必須。
- 会員のPointRankは文字列のまま。ランクコードとの対応付けは計算連携前に別途確定する。

## 4. ボーナス

- Code(20)、Name(80)、Version(1以上)、Id_PointBase(long)、DayFrom/DayTo、IsEnabled。
- TriggerType: EnumPointBonusTrigger（0期間内購入、1誕生月購入、2初回購入）。購入確定時の条件。
- PointAmount(long正数)、MinimumKingaku(long非負、親の税基準)。
- IsAllRanksはEnumYesNo。全ランクならRankKubun=0、限定なら親版のランクコードを指定する。
- LimitPeriodType: EnumPointLimitPeriod（0伝票、1適用期間、2会計年度、3生涯）、LimitCount(1以上)。
- 会計年度は会社の年度開始日に従う。回数制限は版だけでリセットせず安定したCodeを使う。
- 期間は親の期間内。基本付与とは別イベントで記録する。

## 5. 台帳

- EventKey(160)、DenDay、Id_Customer/Id_Tenpo/Id_Tenuri(long)、PointDelta(long)。
- EventTypeはEnumPointEventTypeとEnEventType。付与は正、利用/失効は負、取消は元の逆符号。
- Id_OriginalEvent、Id_Shain、SourceVdu、Id_PointBase/Id_PointRank/Id_PointBonusはlong。非該当参照は0。
- 適用条件への明示参照は使用済み版保護に使用する。Jcalc(4000のJSON文字列)は計算条件・版・対象金額・結果の監査値、Memoは200。
- 同日複数伝票・複数条件を別行で記録する。再送時は同じEventKeyを使用し、履歴は追記専用とする。

## 6. 移行・検証境界

- TranPointRirekiのC#定義/作成登録と旧ToDoを削除。旧実表・データは削除しない。
- 新表はDefineDataTableが作成。TranPointEventは本commitで初導入、接続先SQLiteにも未作成であり未リリース中間定義の移行は対象外。
- UpdateDb 26_10_06_01で旧ランクにId_PointBaseを追加しuk1を複合キーに再作成。新列の索引は移行後に作成する。
- SQLite既存NUMBER列はlong値を保持できる。他DBの既存ランクint列の幅変更・実移行は未確認。
- Account.Point、SummaryPointの顧客Id/残高/累計額のintは未変更。残高連携は型移行を含め別途設計する。

## 7. メンテ時の保護方針

- 使用済み版の条件・期間・識別子は編集/削除不可。ベース/ボーナスは有効フラグ切替のみ許可し、再有効化時も期間重複を検査する。
- 所属ランク/ボーナスが使用済みなら親ベースの条件集合も固定する。
- 親子参照が残る削除は拒否。台帳・残高は一般CRUDでは保存しない。
- 入力・参照・期間・使用済み保護を画面詳細設計後にサーバの単件・一括保存経路へ実装済み。台帳・残高の汎用書込みと条件の部分更新を拒否する。
- 非0初期値の数値列はJsonPropertyで明示保存し、共通JSONの既定値省略による付与数0・四捨五入・限定ランクの初期値復帰を防止する。

## 8. 付与計算と再計算（確認日 2026-10-06、調査対象HEAD 19e842ed）

実装: `CvDomainLogic/PointCalcDb.cs`。本節はベース+ランクの記録（確認日時点）。キャンペーン・ボーナス・利用ポイント控除・失効・手動登録はそれぞれの詳細設計を参照（2026-10-08 実装済み）。

- 対象: 店舗売上(Tran01Tenuri)で顧客Id>0、区分10/11/14(P/S売上・社販)・20/21/24(各返品)。消費税(99)は対象外。
- ベース: 伝票日付を期間に含む有効版。複数制度コードが同時に有効ならコード順の先頭を適用する。
- ランク: 会員情報(MasterEndCustomerAccount.PointRank)を数値化しMasterPointRank.Kubunと一致した行が単価・付与数を置換。会員情報なし・非数値・不一致はベース条件。
- 金額: 明細Kingaku(税抜)。税込基準は明細Taxを加算。明細Kubun 0=プロパー、1=セール。
- 端数: 伝票単位は (P金額×P付与数 + S金額×S付与数) ÷ 単価 を1回丸め、明細単位は明細ごとに丸めて合計。四捨五入は0から遠い側。
- 返品: 同じ規則で計算しCalcFlag(-1)を掛けた負の付与(EventType=付与、PointDelta<0)を記録する（ユーザー判断 2026-10-06）。
- 台帳同期: 伝票ごとに取消されていない付与と現在の計算結果を比較し、差があれば取消(元の逆符号、Id_OriginalEvent)+新付与を追記。同一なら追記しない（再実行・再送で二重計上しない）。EventKeyは `TENURI:{Id}:G:{Vdu}:{連番}` / `TENURI:{Id}:C:{元Id}`。
- リアルタイム: WriteEffectRunner.After で店舗売上の追加・修正・削除(単件・一括・Id指定)と同一トランザクションで同期。部分更新では Id_Customer/Id_Tenpo を禁止。POS確定等 WriteEffectRunner を通らない作成経路は再計算で補正する。
- 残高: SummaryPoint.Point は対象顧客の台帳合計で作り直す。MasterEndCustomerAccount.Point は移行値を保持するため追記した増減を加算する（ユーザー判断: 両方更新）。移行残高イベント投入後は両者を照合すること。SalesCount/SalesKingaku は未更新。
- 再計算: 指定年月(伝票日付の暦月)の伝票と同期間の台帳を対象に上記同期を1トランザクションで実行。マニュアル排他「ポイント再計算」。gRPC `Msg063_PointRecalc`。
- 自動実行: 月次再集計タスクに「ポイント」区分を追加。掛月を暦月へずらし前月・当月を再計算する。
- 画面: メニュー「ポイント再計算」(PointSummaryView)。既定は当月。
