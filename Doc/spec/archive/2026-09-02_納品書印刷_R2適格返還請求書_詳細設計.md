## 5. 印刷実行と `IsPrint` 更新

`BaseReportViewModel.DoOutputPdfCommand` は PDF 出力結果を返さないため、そのままでは更新順を制御できない。標準 VM に独自の `PrintCommand` を設け、次の順序を固定する。

1. 画面条件を検証する。
2. ヘッダー検索 SQL で対象の `Id` と `Vdu` を取得する。ここでは日付・得意先・伝票番号・取引区分・未発行のみの全条件を適用する。
3. 0 件ならメッセージを出し、更新・PDF 出力を行わない。
4. 取得した全行を 1 回の `PartialUpdateParam` にまとめ、`IsPrint` 列だけを `1` に更新する。各行の `Vdu` を `ExpectedVdu` に渡す。
5. 更新成功後、取得済み `Id` の集合だけを条件に 66 列の帳票 SQL を組み、PDF 出力を開始する。

この順序により、未発行のみを指定しても更新後の `IsPrint=1` によって印刷データが消えることはない。更新競合・更新失敗時は PDF を出力しない。PDF 作成開始後の失敗は `IsPrint=1` を戻さない。これは「印刷実行された時点で更新してよい」という要件に従う。

更新には、伝票保存と同じ副作用を持つ全列更新ではなく、`PartialUpdateParam(typeof(Tran00Uriage), [nameof(Tran00Uriage.IsPrint)], ...)` を使う。これにより在庫・金額・税額の再計算を起こさない。

## 7. R2 税率別集計

税率は印刷時の現在マスタではなく、明細 `Jmeisai.TaxRate` のスナップショットを正典にする。税抜対価は `TaxableAmount1` ～ `TaxableAmount3` を、明細税率ごとに合算して表示する。

| 税計算単位 | 税額の出力値 |
| --- | --- |
| 伝票単位 | ヘッダーの `Tax1` ～ `Tax3` を、対応する明細税率へ配分して出力 |
| 請求単位 | 税率別税抜対価に伝票の `TaxRounding` を適用して、印刷専用に再計算する |

請求単位の再計算は DB 値を更新しない。整数端数処理は `EnumRounding` に合わせ、税抜対価 `A`、税率 `R` に対し次を使う。

- 切捨て: `CAST(A * R / 100 AS INTEGER)`
- 四捨五入: `CAST((A * R + 50) / 100 AS INTEGER)`
- 切上げ: `CAST((A * R + 99) / 100 AS INTEGER)`

これにより請求単位で保存税額が 0 でも、R2 帳票上の返還対価と税額を表示できる。税率スナップショットがない課税明細、または 10%・8% 以外の課税率が含まれる場合は、対象を発行済みにせずエラーとして印刷を中止する。

### 10.3 修正した実行時エラー（`5993e3f`）

実装直後の印刷は失敗していた。原因はSQL構文ではなく、結果行の材料化である。

1. **帳票SQLの66列に `AS itemN` 別名が無かった（根本原因）**。
   `ExDatabase.RawExecCmd` は `reader.GetName(i)` を `Dictionary<string, object>` のキーにするため、
   別名の無い重複式でキーが衝突する。リテラル `''` が8回、`h.DenDay`・`VTokui.Cd`・`VShain.Mei` が各2回、
   明細 `No` が3回あり、`Dictionary.Add` が `ArgumentException` を投げていた。
   66列すべてに `AS item1`〜`AS item66` を付与して解消した。番号はQFMの `datarecord` と1:1である。
   これは `.agents/skills/upgrade-cvnet-print-form/SKILL.md` と `Doc/aicoding_log_011.md` に
   記録済みの既知の落とし穴であり、`ShiireSlipPrintViewModel` に正解例がある。
2. **`RawExecCmd` の失敗が隠蔽されていた**。同メソッドは例外を握り潰して `[{"Error": ...}]` の1行を返す。
   `PrintPdfService.PrintPre` が `dataList.Count == 0` しか見ていなかったため、SQL失敗が
   1列だけのCSVとして下流へ流れ、QFM側の原因不明な失敗に化けていた。
   `RawLastError` の判定を追加し、取得失敗を明示的に返すようにした。
3. **`MasterSysman` の結合がデカルト積だった**。`ON 1=1` を `ON sys.Id = 1` へ。
   現在1行のため実害は無かったが、2行目が入れば全明細が増殖する。
4. **旧形式VMが新QFMを指していた**。`NouhinBookPrintLegacyViewModel` は旧16列SQLを出しながら
   `FormFileName` に新66項目の `NouhinBookPrint.qfm` を返していた。誰も直接生成しないため
   到達不能だったが、`abstract` 化して `FormFileName` の override を削除し、
   派生側で必ず旧形式用QFMを指定させる形にした。
5. **0件のメッセージが `印刷に失敗しました: []` になっていた**。サーバは0件をエラーではなく
   `Code = -1`・`DataMsg = "[]"` で返すが、`FetchTargetsAsync` が `Code < 0` を一律で例外化していたため
   「対象の伝票がありません」に到達していなかった。`CvMsgErrorCode.NotFound` を追加して0件と障害を区別し、
   障害時は生の `DataMsg` より表示用の `Option` を優先する。文言も確認すべき条件を並べた案内へ変更した。
