ご指示は「NohinDay 列を追加」だが、既存の同義列（`TranHaibun.NouhinDay` / `TranHoju.NouhinDay`）に合わせて

## 3. 実装方針

### 3.1 スキーマ（H1）

- `CvBase/BaseDb2Trans.cs`: `Tran13Hachu` と `Tran12Jyuchu` に次を追加（`EndFlag` の近くに置く）。
  ```csharp
  /// <summary>納品予定日 yyyyMMdd 8桁。空なら未設定。伝票単位で持ち、納期遅れ判定に使う（決定 6.2 / H1）。</summary>

  [ColumnSizeDml(8)]
  [Comment("納品予定日 yyyyMMdd 8桁。空なら未設定。伝票単位で持ち、納期遅れ判定に使う。")]
  public partial string NouhinDay { get; set; } = string.Empty;
  ```
  新規DBは `DefineDataTable` が属性から作る。
- `CvBase/UpdateDb.cs`: 既存DB向けにマイグレーションを1行追加（最新 `26_08_17_02` の次）。
  ```

  ```

### 3.2 入力（H1）

- `HachuInputViewModel` / `JuchuInputViewModel` の `LightweightSelectColumns` へ `NouhinDay` を追加する。
  **理由**: 一覧タブは軽量列だけを読み、詳細タブの `CurrentEdit` はその行を使う。`NouhinDay` を含めないと
  既存伝票を修正保存した際に `NouhinDay` が空で上書きされてしまう（`EndFlag` は保存後に再判定されるため軽量列に無いが、
  `NouhinDay` はユーザーデータなので必ず読む）。
- `HachuInputView.xaml` / `JuchuInputView.xaml`: ヘッダの入力フィールド(WrapPanel)に、発注日/受注日の隣へ
  `納品予定日` の `DatePicker`（`DateYmd8Converter` / `FormDatePicker`、`CurrentEdit.NouhinDay` に TwoWay バインド）を足す。
  未設定（空）も許可する（任意入力）。

### 3.3 納品予定照会（H2/H3、発注側）

- `ViewModels/03Hatchu/DeliveryScheduleInquiryViewModel.cs`: 空クラスを `BaseQueryViewModel` 派生へ置換。
  読み取りは `QuerySqlListAsync<Tran13Hachu>`（既存DBマップ型、照会画面の実績パターン）。
  - 検索条件: 納品予定日 from-to、仕入先、「納期遅れのみ」「未完了のみ」。
  - 一覧行 `DeliveryScheduleRow`（`Tran13Hachu` をラップ）: 発注No、発注日、納品予定日、仕入先、発注数(`SuTotal`)、金額、
    完了(`EndFlag`)、**納期遅れ日数**。
  - 納期遅れ = `NouhinDay` が非空 かつ `NouhinDay < 今日` かつ `EndFlag = 0`。遅延日数 = 今日 − `NouhinDay`。
    今日は端末日付でクライアント算出（照会は表示専用のためサーバ日付に依らない）。
  - SQL: `WHERE ifnull(NouhinDay,'') <> '' [AND NouhinDay BETWEEN ..][AND Id_Shiire=..][AND EndFlag=0][AND NouhinDay < 今日] ORDER BY NouhinDay, Id`。
- `Views/03Hatchu/DeliveryScheduleInquiryView.xaml`: 検索カード＋一覧DataGrid（納期遅れ行は色分け）。ZaikoQuery/配分照会と同じ体裁。

サーバ・`WriteEffectRunner` は変更しない（列追加のみ、照会はread-only）。
