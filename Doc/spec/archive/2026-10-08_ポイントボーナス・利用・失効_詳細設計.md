## 1. 範囲

| 機能 | 内容 | 実行経路 |
|---|---|---|
| 利用ポイント | 店舗売上の利用ポイントを台帳へ記録し、ベースの DeductPointUse=する のとき付与対象額から控除する | 保存時同期・再計算（既存 PointCalcDb） |
| ボーナス | MasterPointBonus（期間内購入・誕生月購入・初回購入、回数制限）を購入確定時に別イベントで付与する | 保存時同期・再計算 |
| 失効 | 最終購入日から一定月数経過、または退会で残高を一括失効する | 手動（ポイント再計算画面）・自動実行（日次ジョブ） |

## 2. スキーマ

| 表 | 列 | 型・既定 | 用途 |
|---|---|---|---|
| Tran01Tenuri | GrantPoint | long 0 | 付与ポイント（基本+キャンペーン+ボーナスの有効付与合計、符号付き）。サーバが同期時に設定し、入力値は使わない |
| Tran01Tenuri | UsePoint | long 0 | 使用ポイント（正数で保持。返品伝票は戻すポイント数を正数で保持し CalcFlag で符号化） |
| MasterPointBase | ExpireMonths | int 0 | 最終購入日からの失効月数。0=経過失効しない |

- `DefineDataTable` は列定義から作成、既存DBは `UpdateDb` で列追加（既存値0 = 利用なし・失効しない＝現行動作）。索引追加なし。
- ExpireMonths は付与結果に影響しないため、使用済み版でも変更可とする（§7 使用済み保護の例外）。
- GrantPoint は同期・再計算で台帳と同じトランザクション内に `UPDATE Tran01Tenuri SET GrantPoint` で設定する。利用者の編集ではないため Vdu は変えない（楽観排他・再送判定に影響させない）。保存応答の伝票にも反映する。

## 3. 利用ポイント

- 台帳: 伝票ごとに EventType=Use、`PointDelta = -UsePoint × CalcFlag`（売上は減算、返品は戻し）、EventKey `TENURI:{Id}:U:{Vdu}:{連番}`。対象区分・顧客条件は付与と同じ（顧客Id>0、区分10/11/14/20/21/24）。ベースが無くても利用は記録する。
- 同期: 既存の付与と同じく、取消されていない利用と計算結果を比べ、差があれば取消(Cancel)+新規を追記。
- 控除: 適用ベース版の DeductPointUse=する のとき、伝票の付与対象額合計 T（税基準どおり）に対し各明細の対象額へ `max(0, T - UsePoint) / T` を掛けてから既存計算（キャンペーン・伝票/明細単位・丸め）を行う。1ポイント=1円。端数は明細金額を丸めず、最終ポイントの丸めだけで処理する（旧 mazuda100 の按分と同じ考え方）。
- 残高不足: 店舗売上の保存（単件・一括・Id指定、保存時同期）で利用の増加により保存後の顧客残高（台帳合計）が負になる場合は「ポイント残高不足（残高 n、使用 m）」の警告メッセージで拒否し、トランザクションを戻す。利用の減少・返品・削除は残高に関係なく許可。再計算では拒否せず記録し、残高が負の顧客数を警告ログに出す。負残高は失効対象外。

## 4. ボーナス

- 判定時点: 店舗売上の保存時同期・再計算で、伝票ごと。売上区分(10/11/14)は付与、返品区分(20/21/24)は同じ判定（対象額は絶対値）で該当すれば `-PointAmount` を記録する。
- 適用条件（版ごと）: 有効、伝票日が版の期間内、Id_PointBase=伝票日の適用ベース版、ランク（全ランク または RankKubun=会員ランク）、伝票の付与対象額（税基準・利用控除後）≥ MinimumKingaku、かつ契機:
  - 0 期間内購入: 条件なし。
  - 1 誕生月購入: MasterEndCustomer.BirthNoyear(MMdd)、なければ Birthday(yyyyMMdd) の月が伝票日の月と一致。
  - 2 初回購入: その顧客の対象売上伝票（区分10/11/14、顧客一致）のうち (DenDay, Id) が最小の伝票。返品伝票は初回購入に該当しないためマイナスを記録しない。
- 回数制限: 同じボーナス Code（版をまたぐ）の有効な正のボーナス付与のうち、自伝票以外で期間内の件数 < LimitCount。返品のマイナスは回数を戻さず、回数制限の対象にもしない。期間は 0伝票=自伝票内(1件)、1適用期間=当該版の DayFrom～DayTo、2会計年度=MasterSysman.FiscalStartDate の月日で区切った年度、3生涯=全期間。
- 複数ボーナスが該当すればすべて付与（版ごとに別イベント）。台帳は EventType=Grant、Id_PointBonus=版Id、PointDelta=PointAmount、Jcalc に契機・対象額・回数、EventKey `TENURI:{Id}:B:{版Id}:{Vdu}:{連番}`。
- 同期: ボーナス版ごとに有効付与と期待値を比べ、伝票訂正・削除・条件外になれば取消。既存の基本付与の同期（Id_PointBonus=0 のみ対象）は維持。

## 5. 失効

- 基準日 D（既定=実行日の前日）。対象は台帳合計（SummaryPoint.Point）> 0 の顧客で、次のいずれか:
  - 経過失効: D 時点の適用ベース版の ExpireMonths > 0 かつ 最終購入日 ≤ D − ExpireMonths か月。最終購入日=対象売上伝票（区分10/11/14）の最大 DenDay と MasterEndCustomerAccount.LastVisitDate(移行値) の遅い方。どちらも無い顧客は対象外。
  - 退会失効: IsWithdrawalFlag=1 かつ WithdrawnDate ≤ D（ExpireMonths に関係なく）。
- 記録: EventType=Expire、`PointDelta = -残高`、DenDay=D、Id_PointBase=判定に使った版（退会は0可）、Memo「最終購入日から{N}か月経過の為失効」/「退会の為失効」、EventKey `EXPIRE:{顧客Id}:{D}`。同じ基準日の再実行は EventKey で二重計上しない。残高更新は既存 ApplyBalance（SummaryPoint 作直し、会員 Point へ増減加算）。
- 失効後に過去売上が訂正されても失効は再計算しない（追記のみ）。再計算(Msg063)は Id_Tenuri>0 の台帳だけ扱うため失効行に触れない。
- 失効額は台帳合計。失効はポイント履歴（TranPointEvent）に記録し、SummaryPoint を台帳合計から再計算する。移行ポイントは OpeningBalance イベント投入後に失効対象となる。
- 実行: `PointExpireDb.ExpireAsyncStream(基準日)`、マニュアル排他「ポイント失効」、1トランザクション。gRPC `Msg067_PointExpire`（新設。65・66は既存）。
  - 手動: ポイント再計算画面に「失効処理」欄（基準日・実行ボタン）を追加。
  - 自動: 日次ジョブ「ポイント失効」(cron `40 3 * * *`、**既定無効**、基準日=前日。月次再集計 1:10 と排他を取り合わないようずらす)。
- 失効月数は MasterPointBase.ExpireMonths（制度版ごと、ポイントマスタ(ベース)画面に入力欄追加）。

## 5.1 手動登録（ユーザー指示 2026-10-08）

- 記録先は台帳 TranPointEvent。サーバは汎用CRUD（Msg201 の InsertParam/InsertBulkParam）を通し、`PointMasterDb.ValidateSave` → `PointLedgerDb.ValidateManual` で検査、`WriteEffectRunner.After` → `PointLedgerDb.AfterInsert` で同じトランザクション内に SummaryPoint・会員ポイントを更新する。
- 台帳は追記のみ。汎用の更新・削除・Id指定削除・一括削除・部分更新は拒否する。訂正は取消(Cancel)行を追加する。SummaryPoint への汎用書込みは従来どおり拒否。
- 種別と符号: 付与(Grant)>0、使用(Use)・失効(Expire)<0、調整(Adjustment)≠0、取消(Cancel)=元行の逆符号。期首残高(OpeningBalance)はCSV取込の運用とし手動登録の対象外。
- 手動行は Id_Tenuri/Id_Tenpo/Id_PointBase/Rank/Bonus=0、顧客は実在、計上日は実在日付、理由(Memo)必須、担当者は0か実在。
- EventKey は接頭辞 `MANUAL:`。画面がフォームごとに採番し、成功時だけ再採番するため、再送は一意キーで拒否され二重計上しない。取消は `MANUAL:C:{元Id}` をサーバが設定し、1行1回。取消できるのは手動行だけ（店舗売上・失効処理の行は対象外）。
- 減算（使用・失効・負の調整）で残高が負になる登録は拒否（判断Bと同じ）。取消は訂正のため許可。
- 画面: 顧客管理 ▲ポイント「ポイント手動登録」(PointLedgerManualView)。一覧条件（顧客・計上日・種別・手動のみ）、一覧（取消済み表示）、新規登録フォーム、選択行の取消。

## 7. 検証・受入条件

- 再実行・再送で二重計上しない（EventKey 一意、同期の差分判定）。
- 伝票の訂正・削除・顧客変更で利用・ボーナスが取消・再付与され、SummaryPoint と台帳合計が一致する。
- 失効は同一基準日で冪等、途中失敗で部分適用を残さない。
- 新旧DB（既存SQLite複製）で起動・migration を確認。他DBの実移行は未実施として報告する。
