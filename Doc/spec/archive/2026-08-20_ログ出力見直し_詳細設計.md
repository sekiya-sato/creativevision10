# ログ出力見直し 詳細設計

## 目的

- 通常運用では、要求ヘッダ・業務パラメータ全文を出力せず、ログ量と機微情報の残存を抑える。
- 障害時は、例外全文とクライアント・サーバー共通の相関 ID から原因を追跡できるようにする。
- 調査時だけ既存と同じ詳細データを再出力できるようにする。

## 設定

`CvServer/appsettings.json` に次を追加する。

```json
"Diagnostics": {
  "EnableDetailedRequestLogging": false
}
```

- `false`（既定）: 要求・応答ヘッダと `CoreService` のパラメータ全文を出力しない。
- `true`: 従来と同じ要求パス、要求ヘッダ（`Authorization` を除く）、応答ヘッダ、および `CoreService` の全パラメータ／SQLを出力する。設定変更はサーバー再起動後に反映する。
- 詳細モードは一時的な障害調査だけに使用し、終了後は必ず `false` へ戻す。パラメータやSQLには個人情報・認証関連情報が含まれ得る。

## 相関 ID

- クライアントの gRPC HTTP ハンドラーが、呼出ごとに UUID 形式の `X-CV-Correlation-ID` を付与する。
- サーバーは有効な UUID を受け取った場合に使用し、未指定または不正値なら ASP.NET Core の `TraceIdentifier` を使用する。応答ヘッダにも同じ値を返す。
- サーバーのログレイアウトには `CorrelationId` を追加する。サーバー例外とクライアントの通信失敗には、同じ ID をメッセージにも含める。

## 例外・通常ログ

- サーバー: gRPC 未処理例外にメソッド名と相関 ID を付与し、例外全文を記録する。
- クライアント: NLog ファイルレイアウトへ `${exception:format=tostring}` を加え、既存のグローバル例外処理が渡す例外全文を保持する。
- クライアントの通信ハンドラーは、HTTP 通信失敗だけを Error として記録する。正常な gRPC 呼出は出力しない。

## 影響範囲と検証

- gRPC 契約・業務データ・認可判定は変更しない。追加する相関ヘッダは任意の HTTP ヘッダであり、既存クライアントとの互換性を保つ。
- `CvServer` と `CvWpfclient` をビルドし、`git diff --check` を実行する。
- 実行時には、通常モードでヘッダ／Payloadが増えないこと、詳細モードで従来データが出ること、通信失敗で双方の相関 ID が一致することを確認する。
