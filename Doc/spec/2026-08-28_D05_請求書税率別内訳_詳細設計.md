# D-05 請求書税率別内訳 詳細設計（2026-08-28）

対象画面: `SeikyuBalanceDetailView` / `SeikyuBalanceDetailViewModel`
対象帳票: `printform/SeikyuBalanceDetail.qfm`

## 1. 決定

- 10.0の適格請求書は、標準10%・軽減8%の税率別課税標準額と消費税額を印字する。
- 税率別内訳は`SummaryUriSei`へ保存しない。請求書印刷時に`Tran00Uriage.Jmeisai`を展開して集計する。
- 集計は伝票に保存済みの`TaxRate`/`Tax`を正とする。商品マスタ・税率マスタの現在値は参照しない。
- D-10（メニュー公開状態・実効権限）は10.0リリース対象外とする。

## 2. 集計契約

請求ヘッダ`SummaryUriSei`の`Id_Tokui`、`DayFrom`、`DayTo`に対して、次の`Tran00Uriage`だけを対象とする。

- `Id_Tokui`が一致する。
- `IsPay=1`である。
- `KakeDay`が`DayFrom`〜`DayTo`に含まれる。

明細`Jmeisai`は`json_valid()`で検査してから展開する。明細の`Kingaku`を税抜課税標準額、`Tax`を消費税額とし、返品・値引（ヘッダ`Kubun=20..39`）は負符号、それ以外は正符号で集計する。

|税率|印字する値|
|---|---|
|10%|課税標準額、消費税額|
|8%|課税標準額、消費税額|
|0%|非課税額|

## 3. 印刷前検査

PDFを生成する前に、同じ対象範囲で以下を検査する。不一致があればPDFを生成せず、請求書番号を画面へ表示する。

1. 明細の税抜額合計＋税額合計が`SummaryUriSei.TotalSales`と一致する。
2. 明細税額合計が`SummaryUriSei.Tax`と一致する。
3. `Jmeisai`が不正JSONではない。
4. 税率が0%、8%、10%のいずれかである。

これにより、明細税額未設定や明細欠落の移行伝票を、内訳と請求額が食い違う状態で発行しない。利用者は伝票税額再更新または伝票修正後に再実行する。

## 5. 検証

- 標準10%・軽減8%・非課税・返品を含む請求で、明細集計と請求ヘッダが一致すること。
- 明細欠落・未対応税率・税額不一致では、PDFが生成されないこと。
- 再発行前後で税率別内訳が変化しないこと。
- QFMをcp932で読めること、XML整形式であること、`item1`〜`item20`とCSV列順が一致すること。
- `CvWpfclient`のビルド、`TestServer`、`git diff --check`。
