# HHT 明細書印刷3画面 仕様（2026-10-05）

メニュー「外部連携 > HHT」の未実装3画面。旧CVの機能を CV10 のテーブルで再実装する。

| 画面 | 旧ソース | CV10 データ | 印刷済管理 |
|---|---|---|---|
| 出荷指示明細書印刷 | `SubDlg_08prn_hht02.crs` | `TranVulcanHht`（受信済みHHTデータ） | なし（旧も更新なし） |
| 移動明細書印刷 | `SubDlg_08prn_hhtlist05.crs`（para=0） | `Tran10IdoOut`（積送出庫） | `Tran10IdoOut.IsPrint` |
| 即時移動明細書 | `SubDlg_08prn_hhtlist06.crs`（para=1） | `Tran05Ido`（即時移動） | `Tran05Ido.IsPrint` |

- 即時移動明細書の元ソースは、旧メニュー定義（`menu_dev03.xml`）では `hhtlist06` だった。
- 帳票は3画面共通で `printform/IdoDetailBook.qfm` を使う（旧 `cvnet60prn02.qfm` を LF 改行・cp932 のまま移した）。A4縦、伝票NO(item8)で改ページ、伝票ごとに数量・上代の合計を出す。`_yk` 版（横向き）は作らない。
- SELECT は旧と同じ34列の並びで出す。旧でも qfm が使っていない列（tel・住所・原価FLG など）は空にする。

## 判断事項（利用者決定）

1. 出荷指示明細書の旧データ元 `HC$TRAN_STDHHT` は CV10 に無いため、受信済みの HHT データ `TranVulcanHht` を使う。
2. 旧「印刷FLG」は、`Tran05Ido` / `Tran10IdoOut` に `IsPrint` 列（0=未発行 / 1=発行済）を追加して再現する（`UpdateDb` 26_10_05_01）。
   - 旧列名の対応付け（`OldTableCommentAttr`）は付けない。旧値はビットの組み合わせ（1/2/8）なので、CSV取込で取り込むと値の意味が変わってしまうため。
3. 帳票は A4縦の通常版だけを作る。

## 移動明細書・即時移動明細書

- 条件: 印刷区分（通常発行／再発行）、出庫元コード範囲(`VSoko`)、入庫先コード範囲(`VIdo`)、移動日範囲（初期値は当日）、伝票NO範囲(`Id`)。
- 通常発行: `IsPrint=0` の伝票を印刷し、印刷後に `PartialUpdateParam` で `IsPrint=1` にする（Vdu を照合）。
- 再発行: `IsPrint=1` の伝票を印刷する。フラグは更新しない。
- 並び: 移動明細書は伝票NO順、即時移動明細書は 日付→出庫元→入庫先→伝票NO 順。どちらも伝票内は 商品→色→サイズ 順。
- バーコード: タイトルが「移動明細書」なら入庫先、それ以外なら出庫元のバーコードを、qfm のスクリプトが非表示にする（旧仕様どおり）。
- JAN は `DerivedShohinColSiz` から引く。JAN1 が無ければ明細の `JanCode` を使う。
- 旧の para 2/3（入庫先を自店舗に限定する・更新しない）と、HHT データ出力ボタンは対象外。

## 出荷指示明細書（HHT）

- 条件: 区分（すべて／3入庫／4出庫／5仕入／6仕入返品／11移動）、店舗（`Shop`、空欄なら全店）、日付範囲、伝票NO範囲。
- タイトルは「区分名＋明細書」。出庫元と入庫先の向きは、HHTデータ更新（`HhtProcessUpdateMap`）の伝票作成と揃える。
  - 入庫・仕入: 出庫元=取引先、入庫先=店舗
  - 出庫・移動・仕入返品: 出庫元=店舗、入庫先=取引先
  - 仕入先は `MasterShiire`、それ以外は `MasterTokui` から名称を引く。
- HHT のコード（前0埋め）は、前0を外してマスタと照合する。MariaDB には2引数の `ltrim` が無いため、`replace` で書いている。
- 商品は `DerivedShohinColSiz.Jan1` で引く（同じ JAN が複数あれば最小の Id）。金額は数量×HHT単価。
