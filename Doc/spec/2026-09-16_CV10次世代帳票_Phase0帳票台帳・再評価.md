## 1. 目的

既存対比の「旧CVnetとの差がある＝要修正」をそのまま引き継がず、CV10としての業務価値と危険度で再評価する。Phase 0では実装を行わず、次を確定または明示する。

- 現状で継続できる帳票。
- 軽微差として移植完了とみなせる帳票。
- 数値・法令・監査上、先に是正すべき帳票。
- 利用目的から再設計すべき帳票。
- 統合・廃止・新規実装の候補。
- コードだけでは確定できない業務判断。

## 2. 判定方法

### 2.1 区分

| 区分 | 意味 | Phase 0での扱い |
| --- | --- | --- |
| A | 数値・対象範囲・法令・監査結果が誤る、またはその疑いが具体的にある | Phase 1候補。意味変更前に承認が必要 |
| B | 利用目的、粒度、集計軸、根拠明細が異なる | 利用実態を確認して再設計・統合・現状追認を決める |
| C | 結果を変えない項目・条件・表示差 | 原則「移植済」。必要なら軽微改善 |
| D | 帳票、区分、入力・集計経路などが全く未実装 | 旧互換修正ではなく新規機能として優先度を判断 |
| 継続 | 現状で目的を満たす | 実装対象外。定期的な回帰確認のみ |

複数区分がある場合は `A+B` のように記す。Aが含まれる場合、レイアウト再設計より正確性を先に扱う。

### 2.2 今回確定できない情報

次はソース・QFM・旧資料だけでは確定しないため、推測で埋めない。

- 本番での利用頻度、利用部門、出力件数。
- 旧帳票の選択肢や複数形式が現在も必要か。
- 同名だが粒度が違う帳票を、意図的に再設計したのか移植漏れなのか。
- 取引先へ渡す正式帳票か、社内確認用か。
- 外部連携用フラグ、消費税列、グラフ等の現在の必要性。

## 3. 再評価サマリ

| 判定 | 意味 | 主な対象 |
| --- | --- | --- |
| Aを含む | 数値正確性を先に検証 | 売上分析・経営分析・卸分析の各帳票、返品符号・粗利式に具体的疑義がある帳票 |
| B | 目的・粒度の確認が必要 | 残管理、元帳、受払、チェックリスト、複数形式を縮退した帳票 |
| C | 軽微改善。原則移植済 | 入力伝票の補助列、絞込条件、用紙方向、任意注記の差 |
| D | 新規実装候補 | 配分4帳票7形式 |
| 継続 | 現行維持 | 請求一覧表、請求台帳、請求書印刷 |

旧レイアウトとの一致だけを目的にした修正は行わない。特に用紙方向、余白、罫線、グラフ、旧システム固有フラグは、それ単独ではB以上にしない。

## 5. 統合・名称変更・廃止候補

### 5.1 統合候補

- 販売動向表、品番別販売動向表、投入売上在庫表、商品消化率表: 指標と判断目的を整理し、重複する商品分析を表示モード化できるか検討する。
- 倉庫別受払表、商品別受払表: 並び軸だけの差か、月次集計と伝票台帳という別用途かを確定する。
- 売上週報・月報: 予算進捗と補充判断を同一画面の別表示にするか、別機能にするか判断する。
- 各ランキング・ベスト表: 対象軸と順位指標を共通化できるか検討する。

### 5.2 名称変更候補

- 商品別発注集計表: 現状がブランド構成比なら、発注残集計と誤認しない名称へ変更。
- 商品別受注集計表: 現状が分類別構成比なら同様に変更。
- 品番別仕入／売上／移動チェックリスト: 集計版か明細版かを名称で区別。
- 商品別受払表: 月次在庫サマリなら「伝票台帳」と誤認しない名称へ変更。
- 卸・店舗売上実績表: 現状の全社月次トレンドを表す名称へ変更。

### 5.3 廃止候補

- 売上チェックリスト: メニュー未登録の理由と代替機能を確認し、利用目的がなければ廃止候補。
- 未参照QFM: ファイルの存在だけで削除せず、参照・運用・保存要件を別途確認する。

| D01 | 売上区分と仕入区分は増やす方向で検討する | 現行enumに存在しない区分を、既存帳票の欠陥ではなく新規機能候補として扱う |
| D02 | 全く未実装のものは「新規」扱いでよい | 帳票ファイルの有無だけでなく、区分・入力・保存・集計・権限・画面・出力の経路がない機能をD区分とする |
| D03 | 追加する売上・仕入区分は現行の正負判定帯に収まる | 加算10～19、返品・減算20～29、値引30～39の判定規則は変更しない。具体的な区分値は既存値との重複を確認して詳細設計で固定する |

区分追加はenumだけの変更では完結しない。次の一式を新規機能の詳細設計範囲とする。

- 区分値、名称、正負、在庫・売掛／買掛・税・原価への影響。
- 入力画面の選択肢、初期値、編集可否、返品時の対応区分。
- HHT・POS・旧データ変換・自動生成処理との対応。
- 集計SQL、サマリ、元帳、照会、帳票の対象・内訳・除外条件。
- 既存データとの互換性、DB Migrationの要否、回帰テスト。

`CalcFlag` の正負判定ロジック自体は新規設計の対象外とし、追加区分が所定のコード帯から外れないことをテストする。帳票SQLでは数値を個別列挙する箇所があるため、enum追加後に全参照箇所を追随対象として再検索する。

現時点の新規候補は次のとおり。

| 新規候補 | 現状 | 主な影響範囲 |
| --- | --- | --- |
| 売上「修理」 | `EnumUri00`／`EnumUri01`に独立値なし | 本部・店舗売上入力、HHT/POS、売上集計、店舗日計、実績・ランキング帳票 |
| 売上「社販」 | enumに独立値がなく、HHT変換は明示的にエラー | HHT、店舗売上入力、社員・店舗帰属、予算実績、ランキング、権限 |
| 仕入「消化仕入」 | 独立区分なし。自動生成は `GeneratedKind=ConsumptionPurchase` と通常仕入／返品区分の組合せ | 原価更新、仕入入力、仕入伝票、買掛集計、仕入分析 |
| 仕入「消化仕入返品」 | 独立区分なし。生成処理は符号により仕入／返品へ振分 | 消化仕入取消・再生成、買掛、在庫対象外制御、帳票内訳 |

消化仕入は既に `GeneratedKind` と `IsStock` を持つため、「区分値を増やす」案と「生成種別との複合分類を表示する」案を詳細設計で比較する。二重に意味を持たせないことを優先する。

### 6.1 技術精査で解消した事項

| ID | 結論 | 根拠と計画への反映 |
| --- | --- | --- |
| T01 | 返品符号の正典は既に存在する | `Tran00Uriage`、`Tran01Tenuri`、`Tran03Shiire`等は区分変更時に `CalcFlag` を設定する。`SummaryDb.SignExpr` は返品区分20～29だけ `CalcFlag` を掛け、値引30～39は反転しない。Phase 1ではこの既存規則との一致を検証する |
| T02 | 売上区分に修理・社販の独立値はない | `EnumUri01` は売上10、SALE11、返品20、返品SALE21、その他99。D01・D03により、現行の正負判定帯内で区分拡張する新規機能として検討する |
| T03 | 仕入区分に旧15・25はない | `EnumShiire` は仕入10、返品20、値引30、その他99。D01・D03により正負判定は維持するが、既存の `GeneratedKind` と `IsStock` を含めた意味設計が必要 |
| T04 | 関連伝票No.2は全伝票共通ではない | `Tran03Shiire`、`Tran12Jyuchu`には `RelateNo1` はあるが `RelateNo2` はない。旧列の印字だけを目的にモデル列を追加しない |
| T05 | 支払・入金内訳の基礎列は存在する | Summary系に `Densai`、`Offset`、`Other` があり、仕入先には `Id_Paysaki`、`PayMonth`、`PayDay` がある。買掛・支払帳票の不足はデータ不在ではなく帳票設計の問題 |
| T06 | 配分2画面は印刷未実装 | `ShippingConfirmDetailPrintViewModel` と `ShippingListReportViewModel` は空の `BaseViewModel`。メニューにも「準備中」と明記され、QFMだけを追加しても完成しない |
| T07 | 売上チェックリストは通常導線がない | View、ViewModel、QFMは存在するが `MenuData.cs` に登録がない。現行機能として継続するには導線の意思決定が必要 |
| T08 | 半期報2帳票はCV10上で役割が分かれている | `担当別売上実績半期報` は担当軸、`半期報` は全社の卸・店舗・合計・前年比・累計として別メニュー登録されている。旧資料の重複有無だけで統合しない |
| T09 | 在庫強制調整は金額を持たない設計 | 旧データ変換でも金額・上代・下代・税を移行せず0とする設計が明記されている。旧金額列の復元は帳票修正ではなく在庫調整モデルの仕様変更になる |
| T10 | 帳票出力履歴は現行コードに見当たらない | PDF生成経路は確認できるが、帳票名・利用者・日時を蓄積する履歴機能は検索範囲にない。利用頻度は現状のリポジトリだけでは判定できない |
| T11 | QFM名の単純な静的参照数は台帳に使えない | 121 QFMに対し文字列参照は116種類だが、接頭辞による動的ファイル名と旧名コメントを含む。未参照候補は個別に実行経路を追ってから判定する |
| T12 | 生地付属仕入の在庫非連動は意図された設計 | `Tran02Material` は倉庫実在庫対象外だが、買掛集計には `Tran03Shiire` と合算される。商品仕入帳票へ混ぜるかは技術欠落ではなく帳票目的の判断 |
