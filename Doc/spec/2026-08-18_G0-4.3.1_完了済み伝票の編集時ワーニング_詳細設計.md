# G0-4.3.1 完了済み伝票の編集時ワーニング 詳細設計（2026-08-18）

対象HEAD: `861ebfe`（出荷指示確定・出荷処理を実装）
対象: 仕入入力(`ShiireInput`) / 出荷売上入力(`ShukkaUriageInput`) の保存後ワーニング
根拠: 未適用課題台帳 G0-4.3.1、判断材料 4.3 / 4.3.1、`CvDomainLogic/CompletionDb.cs`（`FindCompleted` 実装済み）。

## 1. 目的と背景

発注残・受注残の完了は自動で立つが（`CompletionDb`、明細単位で全SKU充足）、**いったん完了したら実績が
減っても自動では戻さない**（決定 4.3.1）。戻すのは残完了設定画面からの手動操作だけ。

そのため、**完了済みの発注・受注に紐付く仕入・出荷を編集しても残へ反映されない**。利用者が気付けるよう、
仕入入力・出荷売上入力の**保存後**に、紐付く発注・受注が完了済みなら警告を出す。

## 2. 仕様

- **トリガ**: 仕入(`Tran03Shiire`)または出荷売上(`Tran00Uriage`)の追加・修正・削除が成功した直後。
- **紐付け**: 伝票の `RelateNo1`（仕入→発注Id / 出荷売上→受注Id）。`RelateNo1 = 0`（未紐付け）は対象外。
- **判定**: 紐付く発注(`Tran13Hachu`)／受注(`Tran12Jyuchu`)が `EndFlag = 1`（完了済み）かどうか。
  `CompletionDb.FindCompleted` と同じ条件（`Id = @ AND EndFlag = 1`）をクライアントの読み取りで確認する。
- **表示**: 完了済みなら情報ダイアログで
  「この仕入に紐付く発注 #X は完了済みです。完了は自動では解除されません。数量を変更した場合は、
  必要に応じて発注残完了設定で確認してください。」（出荷売上は「受注」「受注残完了設定」に読み替え）。
  **保存自体はブロックしない**（気付き用の情報表示）。

### 2.1 状態遷移との整合（判断材料 4.3.1）

保存に伴う自動完了判定はサーバ側 `WriteEffectRunner`→`CompletionDb` が同一トランザクションで行う。
本ワーニングはその**後**の状態（＝編集反映後の `EndFlag`）を読む。

- 削除・数量減で完了が残ったまま → `EndFlag=1` を読んで警告（本機能の主目的、4.3.1）。
- 最終納品で今まさに完了した場合も `EndFlag=1` なので警告が出るが、「完了済み・自動解除しない」旨の
  情報として妥当なので許容する（誤りではない。ブロックもしない）。

## 3. 実装方針

サーバ・スキーマ変更は無い。クライアントの2画面に保存後フックを足すだけ。

- **`Helpers/ViewModels/BaseTranInputViewModel.cs`**（共通基底）に保護メソッドを追加:
  `WarnIfLinkedZanCompletedAsync(Type zanType, int relateNo1, string denLabel, string zanLabel, string settingLabel)`。
  `relateNo1 > 0` のとき `SELECT * FROM {zanType} WHERE Id = {relateNo1} AND EndFlag = 1` を
  `Msg101_Op_Query`（`QueryListSqlParam`）で投げ、1件でも返れば情報ダイアログを出す。
  読み取り失敗（通信エラー等）はワーニングを出さずに握りつぶす（保存は成功しているため業務は妨げない）。
  発注/受注はIdが `long` で数値のみなのでSQLへ直接埋め込む（既存の読み取りと同じ規約）。
- **`ShiireInputViewModel`**: `AfterInsert` / `AfterUpdate` / `AfterDelete` を override し、
  `WarnIfLinkedZanCompletedAsync(typeof(Tran13Hachu), item.RelateNo1, "仕入", "発注", "発注残完了設定")` を呼ぶ。
  仕入返品(`HenpinInput`)は `ShiireInput` を継承するので自動的に同じ挙動になる。
- **`ShukkaUriageInputViewModel`**: 同様に `typeof(Tran12Jyuchu)` / "出荷" / "受注" / "受注残完了設定" で呼ぶ。

`AfterInsert/Update/Delete` は同期メソッドなので、警告は `_ = WarnIfLinkedZanCompletedAsync(...)` の
fire-and-forget で起動する（`await` の継続はUIコンテキストに戻るためダイアログ表示は問題ない）。
保存は既に成功しており、警告表示の遅延・失敗が業務に影響しないため fire-and-forget で足りる。
