# 全社分析（基本設計・詳細設計）

作成日: 2026-11-17（調査対象 HEAD `574ca74f`）
位置付け: 「■ 分析 › ▲ 自由照会」に追加する照会画面「全社分析」の設計。実装済み（本書と同時）。

## 1. 目的

| 段階 | 利用者 | 見たいこと |
|---|---|---|
| 1. 全体把握 | 経営者 | 年・月・日単位で、期首在庫・期末在庫・発注・受注・仕入・売上・粗利の金額推移 |
| 2. 状況把握 | ブランド担当・部署担当 | 商品属性（ブランド／アイテム／展示会／シーズン／素材）で絞り込み・内訳 |
| 3. 原因分析 | 担当・経営者 | 何が売れて何が売れなかったか、不良在庫、不要な発注（商品単位の判定） |

## 2. 基本設計

### 2.1 画面構成（`Views/23AiQuery/CorporateAnalysisView`）

```text
┌ ヘッダ帯: ← 全社分析                              [集計] [CSV出力] ┐
│ 条件: 単位(年/月/日)  期間 From〜To  内訳軸(ブランド…商品)  商品の並び順 │
│ 絞込: 全社 › ブランドA › アイテムB      [1つ戻る] [全社に戻る]          │
├ 推移表（期間単位の行＋合計行）: 選択した行の期間で内訳表を出し直す       ┤
├ 内訳表（内訳軸の行）: ダブルクリックで絞り込み、次の軸へ自動で進む       ┤
└ ステータス帯                                                            ┘
```

- 推移表で「全期間」（先頭行）を選ぶと内訳は期間全体、個別の期間行を選ぶとその期間だけになる。
- 内訳の行をダブルクリックすると、その値を絞込に追加し、内訳軸を未使用の次の軸へ進める（ブランド→アイテム→シーズン→展示会→素材→商品）。商品行は絞り込み終端。
- 絞込を変えたら推移表・内訳表とも再集計する。条件（単位・期間）を変えたら旧結果を消し、再集計前の結果で操作できないようにする（AGENTS §7.3）。
- CSV 出力は表示中の推移表と内訳表を1ファイルへ出す（指標・判定を含む）。

### 2.2 集計項目（金額は税抜）

| 項目 | 源泉 | 計算 |
|---|---|---|
| 期首在庫 | SummaryRealStock / SummaryStock / 在庫伝票 | 期間開始時点の全倉庫在庫数 × 商品マスタ原価 |
| 期末在庫 | 同上 | 期間終了時点の全倉庫在庫数 × 商品マスタ原価 |
| 発注 | Tran13Hachu | Σ CalcFlag × 明細 Kingaku |
| 受注 | Tran12Jyuchu | 同上 |
| 仕入 | Tran03Shiire | 同上（消化仕入を含む） |
| 売上 | Tran00Uriage（卸）＋ Tran01Tenuri（店舗） | 同上 |
| 売上原価 | 同上 | Σ CalcFlag × 明細 Su × 商品マスタ原価 |
| 粗利 | ― | 売上 − 売上原価 |

数量（発注・受注・仕入・売上・期首／期末在庫）も同時に返し、画面で比率を計算する。

画面で計算する指標:

| 指標 | 式 |
|---|---|
| 粗利率 | 粗利 ÷ 売上 |
| 消化率 | 売上数 ÷ (売上数 + 期末在庫数) |
| 在庫回転日数 | 平均在庫金額((期首+期末)/2) ÷ 売上原価 × 期間日数 |
| 判定（内訳表） | `不良在庫`: 期末在庫数>0 かつ 売上数≤0 ／ `過剰発注`: 発注数>0 かつ 消化率<30% ／ `在庫過多`: 在庫回転日数>180 ／ `欠品注意`: 売上数>0 かつ 期末在庫数≤0 |

判定の閾値は画面側の定数（`CorporateAnalysisViewModel`）。運用で変える場合はそこを直す。

### 2.3 期間単位

| 単位 | 入力 | 1区切り | 上限 |
|---|---|---|---|
| 年 | 年度 From〜To（yyyy） | 会計年度（期首月=`MasterSysman.FiscalStartDate` の月）。計上月12か月 | 10年度 |
| 月 | 計上月 From〜To（yyyy/MM） | 自社締日（`MasterSysman.ShimeBi`）による計上月。末締め(99)なら暦月 | 36か月 |
| 日 | 日付 From〜To | 1日 | 93日 |

年・月は在庫集計（SummaryStock の SumMonth = 計上月）と同じ区切りにそろえる。

### 3.2 パラメータ・結果

- `Unit`（0=月 / 1=年 / 2=日。既定値と JSON 往復で値が変わらないよう月を0にした）、`From` / `To`（年 yyyy・月 yyyyMM・日 yyyyMMdd）
- `ByBucket`: true=区切りごとの行（推移表）、false=期間全体を1区切り（内訳表）
- `GroupAxis`: 0=全社（1行）/ ブランド / アイテム / 展示会 / シーズン / 素材 / 商品
- `Filters`: (軸, Id) の配列。商品マスタの属性 Id で絞り込む（`Id=0` は「未設定」）
- `Limit` / `SortKey`: 商品軸の上限件数（既定2000、最大10000）と、上限で切る前の並び順（売上・期末在庫・発注の金額降順）。クライアントの gRPC 受信上限（既定4MB）を超えないため
- 結果 `Rows` は「区切り × 軸」の行。区切りキーは年・月=開始計上月 yyyyMM、日=yyyyMMdd、期間全体=空文字。`TotalCount` は上限で切る前の行数

### 3.3 SQL（SQLite 方言を正典、`ExDatabase.FetchDialect` で実行）

集計は全て SQL の GROUP BY とウィンドウ関数で行い、C# は区切りの算出・名称付与・上限切りだけを行う。

1. **fact**（UNION ALL）: 区切りキー `b`、商品 `sid`、種別 `k`（0=在庫増減 / 1=発注 / 2=受注 / 3=仕入 / 4=売上）、数量・金額。各源泉で `b, sid` ごとに先に集計してから結合する。
   - 伝票は `json_each(Jmeisai)` で展開し、`DenDay BETWEEN 期間` で索引（`*_nk1(DenDay)`）を使う。`json_valid` ガード必須。
2. **在庫（高速化の要点）**: 期首から積み上げると SummaryStock（開発DB 530万行）の全件走査になる（実測 約3.1秒）。代わりに **期末在庫 = 現在庫(SummaryRealStock) − 期末より後の増減** で求める（実測 約0.34秒、積み上げと同値を確認）。
   - 年・月: アンカー `b='~'` = SummaryRealStock − SummaryStock(SumMonth > 終了計上月)。区切り内の増減 = SummaryStock(SumMonth が区切り内)。
   - 日: アンカー = SummaryRealStock − SummaryStock(SumMonth > 終了日の計上月) − 在庫伝票(終了日の翌日〜その計上月末)。区切り内の増減 = 在庫伝票(開始日〜終了日、日別)。在庫伝票の符号・除外条件は `SummaryDb.CreateSummaryStockSql` と同じ（売上・店舗売上・移動出庫 −、仕入(IsStock=1)・調整 +、移動は出庫側 −／入庫側 +、倉庫・商品の `IsZaiko=0` を除外）。
3. **agg**: fact を MasterShohin と結合し、絞込を WHERE、`b, gid`（軸の Id 列。全社は 0）で GROUP BY。
4. **grid**: 区切り一覧（UNION ALL のリテラル）× agg に現れる gid。期末在庫 = アンカー − (後ろの区切りの増減の累計)。`SUM() OVER (PARTITION BY gid ORDER BY ord DESC ROWS BETWEEN UNBOUNDED PRECEDING AND 1 PRECEDING)`。期首 = 期末 − 区切り内増減。
5. 最終 SELECT で名称を結合（属性は MasterMeisho の Id＋区分、商品は MasterShohin）し、全項目0の行を除く。

区切りキー・日付はサーバが検証済みの数字だけで組み立てた値を埋め込む（利用者の文字列は埋め込まない）。絞込 Id は long。

### 3.4 前提・制約

- 原価は **商品マスタの現在の原価（TankaGenka）** で評価する（既存の投入売上在庫表・全社受払表と同じ）。原価履歴（TranGenka）による時点評価はしない。
- 在庫は SummaryRealStock と SummaryStock が整合している前提（在庫再集計で両方が作り直される）。整合が崩れている場合は先に在庫再集計を行う。
- 期末在庫は全倉庫・全店舗合計。倉庫間移動は相殺され、移動中（出庫済み未入庫）は在庫に含まれない（SummaryStock.Su と同じ）。
- 売上は明細 Kingaku（税抜）で、ヘッダ値引（Nebiki00Total）は含めない（既存の分析帳票と同じ）。返品は CalcFlag で差し引く（AGENTS §7.6）。
- 古い期間（終了月が過去にさかのぼるほど）では「期末より後の増減」が増えるため遅くなる（最悪でも積み上げ方式と同程度）。
