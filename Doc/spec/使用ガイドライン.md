## 2. 共通の前提とDB準備

### 開発DBの所在

本書と現行の仕様書・手順書では、開発用SQLite DBを **「開発DB」** と呼び、実ファイル名はこの節にだけ記載する。DBを切り替えたときは、この節と下記の固定パス一覧を更新する。

- **開発DB**: `CvServer/appsettings.Development.json` の `ConnectionStrings:sqlite` が指すファイル。相対パスのため、CvServerをカレントディレクトリにして起動したときの `CvServer/<ファイル名>` になる。
- **現在値（2026-10-16 確認）**: `server-user52.db`
- **旧開発DB**: 同ファイルの `ConnectionStrings:old-sqlite`。現在値は `server-user163.db`（2026-10 まで開発DBとして使用）。
- 開発DBのパスは、ファイル名を書かずに設定から求める。appsettingsはコメントを含み、Windows PowerShell 5.1 の `ConvertFrom-Json` では読めないため、`sqlite` キーの値を抽出する。

```powershell
$devConfigText = Get-Content -Raw -Encoding UTF8 -LiteralPath 'C:\gitroot\new2022\cv10\CvServer\appsettings.Development.json'
$devDbName = [regex]::Match($devConfigText, '"sqlite"\s*:\s*"([^"]+)"').Groups[1].Value
if (-not $devDbName) { throw 'ConnectionStrings:sqlite が見つかりません。' }
$devDbPath = Join-Path 'C:\gitroot\new2022\cv10\CvServer' $devDbName
if (-not (Test-Path -LiteralPath $devDbPath -PathType Leaf)) { throw "開発DBがありません: $devDbPath" }
```

**DBを既定で開くコード（2026-10-16 時点）**: DBファイル名はコードに固定せず、`Doc/test/UatVmSeed/DevDb.cs` が上記の設定から求める。DBを切り替えても、コードの修正は不要。

| 箇所 | 動作 |
| --- | --- |
| `Doc/test/UatVm/VmHost.cs` | `--sqlite` を省略したときのシード先を開発DBにする |
| `Doc/test/UatVm/Scenarios/ManualLock*Scenario.cs` の `ResolveDbPath()` | `--sqlite` と無関係に開発DBを直接開く |
| `Doc/test/UatVmSeed/LogisticsSeeder.cs` | `CvServer` フォルダの `appsettings*.json` に `sqlite`／`old-sqlite` として定義されたDB（開発DB・旧開発DB）への投入を拒否する。設定が読めない場合も拒否する |

### UAT前後の認証切替

gRPCを使うUATは、実行前にリポジトリルートから [change4uat_run.ps1](tools/change4uat_run.ps1) を実行して認証を解除する。対象は `CvServer/Services` 以下の `*Service.cs` にある `[UatChangeable]` 直後の属性だけで、引数なしでは `[Authorize]` を `[AllowAnonymous]` に変更する。

```powershell
# UAT開始前

# UAT終了後（失敗・中断時も復元する）
& ./Doc/spec/tools/change4uat_run.ps1 enable_auth
```

スクリプトは自身の配置先から親をたどり、`creativevision10.slnx` のあるリポジトリルートを解決するため、カレントディレクトリやリポジトリ内での配置階層に依存しない。ルートまたは `CvServer/Services` が見つからない場合は、書込み前に停止する。

認証解除後はCvServerを再ビルドして専用サーバを起動する。終了後は専用サーバを正規停止し、`enable_auth` で `[Authorize]` に戻して再ビルドする。起動中のサーバにはソース変更だけでは反映されないため、継続使用する場合は再起動する。認証解除中のソース・生成物はコミット・配布しない。

**配置変更後の確認（2026-10-07）**: 一時リポジトリのサンプルで、`Doc/spec/tools` と異なる深さの配置、無関係なカレントディレクトリからの実行、解除・再実行・位置引数／switchによる復元、BOM・CRLF保持、ルート／Services未検出時の停止を確認済み。実リポジトリの認証属性は変更せず、サーバ再build・実UATは再実行していない。

**実行確認（2026-10-07）**: 新規専用SQLite DB・専用URL・表示ありで `billing --no-execute --no-seed --sqlite <専用DB> --url <専用URL> --manage-server` を実行し、gRPCによる締日一覧取得と入力検証2件がPASS、終了コード0を確認した。終了後の17箇所の認証復元、元ソースとのバイト一致、CvServer再ビルド（警告・エラー0件）も確認済み。請求計算の更新処理と他シナリオは未実施。

### 複製DBと専用サーバ

更新する試験は、共有の開発DB・旧開発DB（[開発DBの所在](#開発dbの所在)）または本番DBへ直接実行しない。シード・再集計・migrationもDB更新に含む。

1. 複製元を利用するサーバ／クライアントを正規停止するか、SQLiteの整合したバックアップを取得する。WAL書込み中の `.db` 単独コピー、`-wal`／`-shm`の削除をしない。
2. 毎回、新しい専用フォルダへ整合したDBをコピーする。前回更新済みDBを再利用するなら、どのシード・設定・残置伝票があるか明示する。
3. 対象DBが必要なマスタと製品スキーマを持つことを確認する。古い複製は専用サーバで製品migrationを先に適用し、正規停止してからシードする。シーダー共通の `SeedSchema.ApplyMigrations` も各シーダーの呼出を確認する。すべてのツールが自動初期化するわけではない。
4. シード時は、その**複製DBを開くサーバを停止**しておく。外部サーバに接続する場合は、その接続先DBも同じ複製であることを確認する。
5. 専用URL／ポートを使う。以下の例は `http://127.0.0.1:5017`。ポート使用中なら既存プロセスを止めるのではなく試験用の空きポートを選ぶ。

次は、複製元を正規停止済みでWALの内容が反映されている場合の準備例。`$devDbPath` は[開発DBの所在](#開発dbの所在)の手順で求める。以後のコマンドは同じPowerShellで `$dbPath` と `$runDirectory` を使用する。

```powershell
$runDirectory = Join-Path 'C:\gitroot\new2022\cv10\Doc\test' ('uat-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [Guid]::NewGuid().ToString('N').Substring(0, 8))
New-Item -ItemType Directory -Path $runDirectory -ErrorAction Stop | Out-Null
$dbPath = Join-Path $runDirectory 'test.db'
Copy-Item -LiteralPath $devDbPath -Destination $dbPath -ErrorAction Stop
```

初期化済みのコピーが取れない場合は、データ・列・索引の準備条件を確認してから進める。新規の空DBへ固定Idのツールをそのまま実行しても同じ試験にはならない。

### 3.2 請求・支払・掛残高の再計算

2026-10-13に旧CLIツールを削除し、システム管理の「在庫・掛再更新」画面へ案内を統一した。

1. 検証時は専用DBコピーと専用サーバを使用する。
2. 開始年月・終了年月を指定する。旧CLIの対象期間自動抽出は引き継がないため、必要な期間を明示する。
3. 「売掛のみ」は売掛と請求残、「買掛のみ」は買掛と支払残、「全て」はそれらに在庫を加えて再作成する。
4. 確認ダイアログの対象を確認して実行し、完了後に帳票・残高を独立に検算する。

- 請求残・支払残は指定範囲の各月とマスタの有効締日から対象を作成し、既存Summaryがない月も計算対象にできる。
- 保存済み締日と現在マスタが不一致の場合は開始を止める。請求計算／支払計算画面で対象を手動再計算し、旧締日の残データを確認する。保存済み行がなければ締日変更は検出できない。
- 複数要求は順次実行されるため、途中失敗・キャンセル時は先の要求が反映済みになり得る。全期間を単一トランザクションで戻す前提を置かない。

### 3.3 summaryreconcile

**用途**: 固定の202607データを投入して締計算・掛計算・在庫再集計を検算する開発ハーネス。

| command | 処理 | 副作用 |
| --- | --- | --- |
| `seed`（省略時） | Clean→投入→4計算→表示 | 伝票削除・投入、Summary再計算 |
| `show` | 現在の対象Summary表示 | 業務表示のみ、起動時migrationあり |
| `idempotent` | 計算を再実行しスナップショットを比較 | 再計算 |
| `closingcheck` | 締日不一致の警告判定 | 取引先締日を一時変更しfinallyで99へ設定 |
| `paysakicheck` | 親子の請求先／支払先締日検査 | テストデータ・設定変更を伴う |
| `stockrebuild` | Clean→投入→在庫全件再集計→照合 | 伝票・Summaryの削除／投入／再集計 |
| `all` | seed→show→idempotent→closingcheck→paysakicheck→stockrebuild | 上記すべて |

```powershell
& 'C:\gitroot\UT\vscmd.bat' dotnet run --project Doc/spec/tools/summaryreconcile/summaryreconcile.csproj -- all $dbPath
```

**この例は専用コピーだけに実行する。** 次の削除範囲と残置を理解したうえで使う。

- **showもread-onlyではない**。command分岐より前に `UpdateDb.WriteVersionInfoAsync` が走るため、旧コピーではmigrationによるDB更新があり得る。

- `Clean()` は202607の `SummaryUriKake`／`SummaryKaiKake`、20260731の `SummaryUriSei`／`SummaryKaiShi` を **取引先で絞らず削除**する。テスト伝票と対象SKUのSummaryStock／SummaryRealStockも削除する。
- `stockrebuild`／`all`の最後は、この削除後に在庫を再計算するが、削除した請求／支払／掛Summaryを最後に再作成しない。専用DBにも削除状態が残る。
- テスト期間202607、得意先・仕入先・倉庫・KIN区分等の固定実データに依存する。「元々取引ゼロ」という当時の前提は現在の共有DBで保証されない。
- `closingcheck`の復元は保存していた元値への復元ではなく **99へ設定**する。例外時finallyもプロセス強制終了まで保証しない。設定が完全復旧するという前提で共有DBを使わない。
- **プロセス終了0だけでは合格としない**。各単独チェックのbool戻り値は終了コードに反映されず、未知commandも表示だけで正常終了し得る。`all`は最後の `ALL: idempotent=PASS closingcheck=PASS paysakicheck=PASS stockrebuild=PASS` と途中のFAIL／例外を確認する。
- 成功後もDBを共有側へ戻さない。再試験は初期バックアップから新しいコピーで始める。

**用途**: デモ環境の `CvServer/img`（商品）・`CvServer/imgshain`（社員）直下の `.jpg` を、`MasterShohin.Code`／`MasterShain.Code` のファイル名へ割り当て直す。DBへ接続せず、事前に取得したCD一覧JSONを入力する。画像の内容とマスタの実物が一致することは保証しない。

| 引数 | 意味 |
| --- | --- |
| `-CodesPath <json>` | `{"MasterShohin":[...],"MasterShain":[...]}` 形式のCD全件一覧（UTF-8）。cv-sqliteで1000件ずつページングして取得する |
| `-ServerRoot <dir>` | 対象の `CvServer` フォルダ。省略時はツール配置先リポジトリの `CvServer` |
| `-Apply` | 実際にリネームする。省略時は予定表示のみ |
| `-ManifestPath <json>` | `-Apply` 時に必須。新規ファイルへ変更前後のファイル名・SHA256を保存する |
| `-RestoreManifest <json>` | マニフェストに従い元へ戻す（既定は予定表示、`-Apply` で実行） |

```powershell
$tool = '.\Doc\spec\tools\demo-environment\Rename-DemoImages.ps1'
& $tool -CodesPath C:\demo-work\master-codes.json -ServerRoot C:\demo\CvServer
& $tool -CodesPath C:\demo-work\master-codes.json -ServerRoot C:\demo\CvServer -Apply -ManifestPath C:\demo-work\rename-20261021.json
```

- 既にCDと同名の画像は維持し、残りを元ファイル名のOrdinal昇順で未配置CDへ割り当てる。CD不足・重複・出力先競合は変更前に停止する。
- 共有の開発環境の画像フォルダを対象にしない。作業前にフォルダをバックアップする（強制終了・電源断では自動復元できない）。
- CD一覧JSON・マニフェストはリポジトリ外の作業フォルダに置く。取得手順・初回実施記録は [demo-environment/README.md](tools/demo-environment/README.md)。

## 4. Doc/test/UatVmの使用方法

### 4.1 標準の実行順

1. 2章で複製DBと出力フォルダを準備する。
2. 対象シナリオとシーダーの固定年月・対象コード・生成／削除範囲・期待値をソースで確認する。
3. `change4uat_run.ps1` で認証を解除し、サーバとUatVmをbuildする。UatVmのbuildだけではCvServerの実行dllを準備したことにならない。
4. 対象コピーを開くサーバが停止している状態で、`--sqlite`・`--url`・`--manage-server`を付けてシナリオを1本実行する。
5. 終了コード、VERDICT、JSONL、画像／帳票、DB残置を確認する。続く試験で前提を汚さないよう、必要なら初期コピーから再準備する。
6. 専用サーバを正規停止し、`change4uat_run.ps1 enable_auth` で認証を復元してCvServerを再ビルドする。試験失敗時も復元する。

```powershell
try {
    & ./Doc/spec/tools/change4uat_run.ps1
    & 'C:\gitroot\UT\vscmd.bat' dotnet build CvServer/CvServer.csproj
    if ($LASTEXITCODE -ne 0) { throw 'CvServerのbuildに失敗しました。' }
    & 'C:\gitroot\UT\vscmd.bat' dotnet build Doc/test/UatVm/UatVm.csproj
    if ($LASTEXITCODE -ne 0) { throw 'UatVmのbuildに失敗しました。' }
    & ./Doc/test/UatVm/bin/Debug/net10.0-windows10.0.19041/UatVm.exe haibunflow --sqlite $dbPath --url http://127.0.0.1:5017 --manage-server
    if ($LASTEXITCODE -ne 0) { throw 'UATに失敗しました。証跡を確認してください。' }
}
finally {
    & ./Doc/spec/tools/change4uat_run.ps1 enable_auth
    & 'C:\gitroot\UT\vscmd.bat' dotnet build CvServer/CvServer.csproj
    if ($LASTEXITCODE -ne 0) { throw '認証復元後のCvServerのbuildに失敗しました。' }
}
```

この例の `haibunflow` は配分の通し試験で、シード・在庫・引当・伝票生成を伴う。画面表示が必要な試験では `--hide-views`を付けない。`billing` は画面表示時の初期化で締日一覧を取得するため、`--no-execute` の場合も `--hide-views` を付けない（非表示では初期化待ちがタイムアウトする）。

### 4.2 引数と既定値

| 引数 | 意味・適用範囲 | 注意点 |
| --- | --- | --- |
| 最初の位置引数scenario | 下表のシナリオ名 | 省略／未登録名は使い方を表示し終了2。名前は大文字小文字を区別しない。 |
| `--manage-server` | CvServerを起動し終了時に正規終了を要求 | シードは起動前。Debug/net10.0/CvServer.dllが必要。終了要求後60秒で停止しない場合は強制終了へ移行する。 |

| `--sqlite <絶対パス>` | シードとmanage-serverのSQLite接続文字列 | 省略時シードは開発DB（[開発DBの所在](#開発dbの所在)）。**manageなしでは接続先サーバのDBを切り替えない**。 |
| `--no-seed` | Program登録のシーダーを呼ばない | 画面コマンドやシナリオ内の更新は止めない。シード済みデータ再利用用。 |
| `--no-execute` | BillingCalculationScenario.Execute=false | **billing固有**。全シナリオのread-only／dry-runではなく、シードも止めない。 |

| `--out <dir>` | menulayoutの画像・結果の出力先 | **menulayout固有**。既定は `out/menulayout-<日時>`。他シナリオの証跡出力先は変わらない。 |

### 4.3 登録シナリオ一覧

下表は `Program.cs` の登録とシーダー辞書を確認した一覧。**シードなしは読み取り専用の意味ではない**。シナリオの説明は選択用の概要で、個々の期待件数・固定データは対応するScenariosソースが基準となる。

**隔離の例外**: `manuallock`、`manuallock2`、`manuallockrestart1`／`manuallockrestart2` は、各Scenarioの `ResolveDbPath()` が開発DB（その環境の `CvServer/appsettings.Development.json` の `ConnectionStrings:sqlite`）を直接開く。**`--sqlite`やサーバ接続文字列を変えても、この直接アクセス先は変わらない**。共有DBのある通常checkoutでは実行しない。リポジトリとテストDBを別ディレクトリに隔離し、その環境の開発DBだけが試験用になる構成を準備したうえで使用する。隔離できない場合は未実施として残す。

**フォーム変更を伴う試験**: `nouhinprintfail` は対象売上伝票の `IsPrint` を更新し、ローカル `printform/` の納品書qfmを一時的に移動して失敗を作る。対象伝票は既定Id `50317`（`UATVM_DENID` で変更可）。専用DBだけでなく、専用checkoutのフォームを使う専用サーバで実行する。終了時は `finally` で `IsPrint` とqfmを戻すが、強制終了時の復元は保証されないため、残った `.uatvm-hidden` と伝票状態を確認する。

**専用DB名を要求するシーダー**: `customerprofile` は `customer-profile-uat-*.db`、`aiquery` は `aiquery-uat-*.db` という名前の、未作成または空のファイルだけを受け付け、`CvServer` 配下のパスは拒否する。開発DBの複製ではなく新規の専用DBを `--sqlite` に指定する。

#### 操作履歴の運用設定と分析

- 記録範囲はサーバ `appsettings.json` の `OperationLog` 節で決める（`Level` 0:記録しない 1:画面起動・終了のみ 2:＋更新・処理実行・印刷 3:＋照会、既定3。`SkipEmptyQuery` 既定true。`MaxConditionLength` 既定4000。`KeepMonths` 既定13）。変更はサーバ再起動で反映する。件数が多すぎる場合は `Level` を2へ下げる。
- 自動実行「操作履歴 保持月数…を削除するタスク」（毎日2:20、既定有効）が `KeepMonths` より古い行を削除する。0以下にすると削除しない。
- 参照は汎用テーブルメンテ・汎用SQL等で行う（専用画面なし）。検索条件に顧客名等が含まれるため、閲覧はシステム管理者に限る運用とする。判断の経緯は [設計判断記録](2026-09-28_設計判断記録.md) 2.16。
- `Kind` は 1:画面起動 2:画面終了 3:照会 4:更新 5:処理実行 6:印刷。主な列は `OpTime`（サーバ時刻 `yyyyMMddHHmmssfff` の文字列）、`Id_Shain`、`ScreenSession`（1回の画面利用）、`FunctionId`、`MenuPath`、`Op`、`DataType`、`Condition`、`ResultCount`、`ElapsedMs`。分析SQL例（旧CV `HC$TRAN_CLICKCNT` 向けSQLの置換え）:

```sql
-- 指定期間に「AI照会」を開いた人と日時
select substr(h.OpTime,1,8) 日付, s.Code 社員コード, s.Name 社員名,
       h.MenuPath メニュー, h.FunctionId
  from SysHistOperation h left join MasterShain s on s.Id = h.Id_Shain
 where h.Kind = 1
   and substr(h.OpTime,1,8) between '20260601' and '20261231'
   and h.FunctionId like '23AiQuery.%'
 order by h.OpTime;

-- 1回の画面利用で何をしたか（起動〜終了、条件つき）
select h.OpTime, h.Kind, h.Op, h.DataType, h.Condition, h.ResultCount, h.ElapsedMs
  from SysHistOperation h
 where h.ScreenSession = @0
 order by h.OpTime;

-- メニュー別・月別の利用回数と利用者数
select substr(OpTime,1,6) 年月, FunctionId, count(*) 回数, count(distinct Id_Shain) 人数
  from SysHistOperation where Kind = 1
 group by substr(OpTime,1,6), FunctionId order by 1, 3 desc;
```

- 汎用の追加・更新・削除は拒否される。汎用SQL（`QueryListSqlParam`）経路は従来どおり任意SQLを実行できるため、改ざん防止はその範囲に留まる。

### 4.5 排他の競合・再起動と停止補助

| 補助スクリプト | パラメータ・用途 | 現行の制約 |
| --- | --- | --- |
| `Run-ManualLockRace.ps1` | Url=127.0.0.1:5002、LeadSeconds=40、ManageServer=true、SleepBeginMs=60000。2プロセスを同時発火 | **SQLiteパスの引数なし**。専用接続文字列を環境で指定し管理起動、またはManageServer=falseで専用サーバへ接続する。 |
| `Run-ManualLockRestart.ps1` | Url=127.0.0.1:5002、HideViews=true。restart1→restart2でサーバを2回起動 | **SQLiteパスの引数なし**。restart1/2も固定DB直接書込み。通常checkoutでは実行せず、リポジトリごと隔離した試験環境でのみ使う。 |
| `Stop-CvServer.ps1` | ProcessId、TimeoutSeconds=30。Ctrl+C相当の正規停止 | PID省略時はCvServerらしいプロセスの先頭を選ぶ。**必ず専用PIDを渡す**。共有サーバを停止しない。 |

これらを引数なしで実行しない。通常は `--sqlite` を使えるUatVmを優先し、競合は接続先・設定を確認して専用環境で実行する。`manuallock`／`manuallock2`／再起動は上記の固定DB問題があるためリポジトリごと隔離した環境を必要とする。

競合試験では、CvServerは1本、UatVmをA/Bの2プロセスとして同じURL・同じ発火時刻へ送る。A/B単体では勝ち・負けのどちらもPASSになり得るため、**2本を合わせて勝者1・敗者1、排他行と結果の整合**を確認する。`CV10_LOCK_SLEEP_BEGIN_MS` 等の試験スイッチは専用サーバだけに設定し、試験終了後は解除する。

再起動観測の前提は、専用DBのマニュアル排他監視ジョブを有効にしcronを `*/1 * * * *` に設定してサーバへ反映すること。試験の前後で設定を保存／復元する。restart1が作った排他行と監視の「前回状態」を観測し、正規停止後にrestart2を実行する。監視できない・スキップの場合は再起動ケースPASSとしない。

専用PIDが確認できた場合の停止形は次のとおり。`12345` は実際に記録した専用サーバPIDへ置き換える。

```powershell
& ./Doc/test/UatVm/Stop-CvServer.ps1 -ProcessId 12345 -TimeoutSeconds 30
```

強制終了やWAL削除で試験DBを片付けない。通常のmanage-serverはハーネスへ終了要求を任せるが、60秒の待機後は強制終了へ移行する。強制終了ログがある場合は正規停止済みと判定せず、専用PID・接続・DB状態と復元対象を確認する。

- PASS／FAIL／SKIP／未実施を分け、JSONL・画像・PDFへの対応を残す。古い報告の件数を新DBの期待値にしない。
- ファイル生成・送受信試験では送信／受信／出力先も専用フォルダにする。外部先や共有運用フォルダにテストファイルを配置しない。
- 試験後は専用サーバを正規停止し、`change4uat_run.ps1 enable_auth` とCvServerの再ビルドで認証を復元する。接続文字列・試験スイッチ・監視cron等の変更も元へ戻す。検証したDBを共有開発DBへ上書きしない。
- 証跡に秘密情報・資格情報・無関係な個人データを含めない。既存の結果・DB・outを一括削除しない。保存・削除の判断は人間が行う。
- `Doc/aicoding_log.md` は作成・追記しない。試験結果は該当する専用証跡フォルダへ記録する。
