## 2. 処理の意味・不変条件

- 現在積送を消す**集計補正の移動受**を作成する。旧移動出庫／移動受は削除せず、月次集計を直接ゼロにしない。
- 元出庫に紐付かない受入・負残が存在するため、出庫Id別残数を正典にしない。生成伝票の `RelateNo1=0`。元出庫を推測して紐付けない。
- 元倉庫を特定できない集計補正なので `Id_Soko=Id_Ido=対象倉庫`。移動受の出庫元計上フラグは全て0、移動先は実在庫+Su・入庫+Su・積送−Suであり、同一倉庫でも二重計上されない。
- 倉庫合計が0でも、SKU単位に+10/−10などが残っていれば表示・処理対象。正負相殺で行を隠さない。
- クリア後も**出庫番号別の移動未受リストは消し込まれない**。クリア済み分を通常の移動受で再登録しない運用が必要。画面・実行確認にも示す。
- 既存集計と源泉伝票の整合が前提。もともと集計にズレがある場合、全件再集計後に積送残が復活する可能性がある。受入検証は源泉が整合した隔離データで再集計前後を照合する。

## 5. I/F・伝票組立

### 5.1 読込

- 一覧: `SummaryStock` を `Id_Soko, Id_Shohin, Id_Col, Id_Siz` でGROUP BYし、`SUM(TransitQty)<>0`。全期間を使用し、月指定で古い積送を漏らさない。
- 倉庫名称: 対象 `MasterTokui` の現行コード・名称を参照。マスタ欠落・在庫対象外は選択実行時に停止する。
- 明細: 同じ集計を既存 `Tran99Meisai` へ投影し、商品・色・サイズの名称は現行マスタ／派生マスタから補完する。派生行重複で数量を倍増させない。
- 生成時の対象商品のマスタ欠落・在庫対象外は停止する。商品／倉庫の在庫フラグを無視すると、移動受を保存しても集計が消えないため。
- 数量はintの既存格納範囲を検査し、倉庫合計はlong。色・サイズ0は既存仕様に従い許容する。

### 5.2 移動受

| 項目 | 値 |
|---|---|
| テーブル | `Tran11IdoIn` |
| `Id/Vdc/Vdu/OldSeqNo` | 新規。監査日時は既存サーバで設定 |
| `DenDay` | 実行開始日 `yyyyMMdd` |
| `Id_Soko/Id_Ido` | 対象倉庫。`VSoko/VIdo`は作成時点の名称 |
| `RelateNo1` | 0（集計補正・元出庫なし） |
| `Id_Shain/VShain` | 0／空（自動処理。担当者を推測しない） |
| `Jmeisai` | 1SKU1行。`Su=現在積送残`（正負）、商品・色・サイズのIDと名称 |
| 単価・金額 | 0（売買ではない集計補正）。価格履歴や税を変更しない |
| `SuTotal` | 明細の符号付き合計。int範囲を検査 |
| `Memo` | 指定文言＋実行開始時刻。全伝票同じ日時 |

倉庫ごとに100明細以下で伝票を分割する（数量合計がint範囲外なら停止）。**選択された全倉庫の全伝票を1回の `InsertBulkParam` で送信**し、既存サーバの1トランザクションで伝票・在庫副作用を保存する。倉庫ごとの別送信による途中完了を作らない。
保存直前まで取消可能。書込送信後はクライアントから取消・自動再送を行わず、応答を待つ。通信エラー・応答形式異常では結果不明として実行ボタンをロックする。再取得だけでは解除せず、サーバ処理の完了・生成伝票を確認してから画面を開き直す。
成功時は返された伝票件数・Idを確認して再一覧取得し、対象倉庫のSKU積送残が0であることを確認する。再取得失敗は「保存済み・結果確認未完了」と表示し、自動再送しない。

## 6. 運用・受入条件

実行前: バックアップ、対象拠点の積送／実在庫確認、移動・HHT・他端末クリア・在庫再集計の停止、生成移動受の実在庫影響を確認。クライアントの停止チェックは排他ロックではない。
既存 `InsertBulkParam` に残数検査・実行IDはないため、読込と保存の間の競合・応答喪失の冪等性はサーバでは保証しない（利用者が停止運用を選択）。
誤実行は生成した移動受伝票を確認し、通常削除経路で在庫効果を戻す。画面から自動取消は提供しない。既存移動出庫の受入を併用しない。

| ケース | 期待 |
|---|---|
| 0件 | 空一覧、実行不可 |
| 停止確認OFF／未選択 | 書込なし |
| 倉庫合計0・SKUは正負 | 一覧に残り、選択で両方クリア |
| 選択2倉庫・非選択1倉庫 | 選択SKUだけ0、非選択は不変 |
| 部分受入後の残 | 現在残だけ計上し、以前受けた分は加算しない |
| サイズ違い | 別SKUとして処理 |
| 正残／負残 | 実在庫は残数だけ増／減、積送は0 |
| 表示後に同合計の別SKUへ変化 | 差を検出して書込前に停止 |
| 再実行 | クリア済み倉庫は対象なし、追加伝票なし |
| 保存失敗 | サーバ全件ロールバック。応答不明は再実行ロック |
| マスタ欠落／在庫対象外／数量範囲外 | 書込前に停止 |
| 備考・日付 | 指定書式、全生成伝票で同一時刻 |
| 全件再集計 | 整合した源泉データでは実在庫・積送が処理直後と一致 |
