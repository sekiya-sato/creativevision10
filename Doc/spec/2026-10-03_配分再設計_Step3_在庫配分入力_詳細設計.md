## 1. 背景と目的

基本設計で次のように決めている。

- D2: 区分 1（在庫配分）に、区分 4（店舗出荷依頼）・5（在庫品配分）・7（移動指示）を統合する。
- D4: 「在庫配分入力」1 画面に、店舗配分入力の在庫モード・在庫品配分・店舗出荷依頼・移動指示をまとめる。
- 5 章: 按分計算を純粋関数 `AllocationCalculator` にまとめる。

### 現状

- 在庫配分は、店舗配分入力（`ShopHaibunInputViewModel`）の「区分＝在庫配分」モードで作っている。
  - タブ 1 は商品一覧（売上・在庫・指示・入荷予定）、タブ 2 は「店舗ごとに SKU 行を入力する」形。
  - 配分先は売仕店(3)と直営店(6)だけで、倉庫(0)・卸先(1)へは配分できない。
  - 配分可能数は「現在庫 − 指示数 ＋ 入荷予定」で、他の画面と算式が違う（P5）。
  - 按分の機能（同数・比率）がない。
- 在庫品配分・店舗出荷依頼・移動指示(SKU)・移動指示(商品) の 4 画面は雛形しかない。

### 旧CVnet の在庫配分入力

参照: `refer/cvnet-knowlege/マニュアル/CVnetマニュアル-13-配分.pdf` 8〜11 ページ。

- 倉庫と品番を選ぶと、行＝店舗、列＝SKU のマトリクスで配分する。
- 上部に「有効在庫数」と「配分残数」を出す。入荷予定は使わない。
- 按分の機能:
  - **同数展開**: 上の店舗から順に同じ数を入れる。
  - **パターン登録・呼出**: 店舗別の比率をファイルに保存して呼び出す。
  - **P比率セット**: 比率で割り振る。端数は「切捨」か「四捨五入」。
  - **ショートカット 2**: 比率を決める参考に、消化率・在庫・積送・当日／前日／前々日売上を表示する。

### Step 3 の目的

在庫配分を **Step 2 と同じマトリクス形式**の専用画面にし、按分機能と、倉庫・卸先への配分を加える。

## 3. 画面仕様

### 3.1 タブ 1：商品一覧

| 条件 | 説明 |
|---|---|
| 配分元倉庫（必須） | `TenType IN (0,3,6)`。現行と同じく、在庫を持つ拠点 |
| ブランド・アイテム・シーズン・商品コード・商品名 | 現行の店舗配分入力の条件をそのまま引き継ぐ |
| 在庫ありのみ（既定オン） | 有効在庫 > 0 の商品だけを出す |
| 滞留（任意） | 最終売上日（店舗売上・出荷売上）から N 日以上経った商品だけを出す。在庫品配分の代わり。N は 0〜365（実装時に追加した制約。下記） |

一覧の列:

| 列 | 内容 |
|---|---|
| 商品・ブランド・上代 | |
| 実在庫 / 引当 / 有効在庫 | 有効在庫 = 実在庫 − 引当 |
| 未確定の在庫配分 | 区分 1 の未完了の配分数 |
| 直近 4 週売上 | 店舗売上 ＋ 出荷売上 |
| 最終売上日 | 直近 1 年の売上だけを見る。それより前しか売上がなければ「1年以上なし」 |

> 実装時の追加: 売上明細は JSON のため全履歴を展開すると遅い（開発DBで約15秒）。伝票日付の索引が効くよう直近 1 年に絞った（0.3 秒未満）。

- 行をダブルクリック、または［配分入力へ］でタブ 2 に進む。

### 3.2 タブ 2：配分先×SKU マトリクス

レイアウトは Step 2 の商品別画面と揃える。

- **列見出し**: SKU ごとに「有効在庫」「配分」「配分後在庫」を出す。
  - 有効在庫 = 実在庫 − 引当 ＋ 読み込んだ自分の配分。基本設計 5 章の算式で、P5 を解消する。
  - 配分後在庫がマイナスなら赤字にする。
- **行**: 配分先 1 件ずつ。固定列は「配分先」「種別（出荷売上／移動）」「比率」「合計」。
- **初期の配分先**: この倉庫×商品にある修正可能な在庫配分（区分 1、`EditableWhereSql`）の配分先。数量も読み込む。
- **配分先の追加・削除**
  - 複数選択ダイアログで追加・削除する。対象は `TenType IN (0,1,3,6)` で、配分元の倉庫自身は除く。
  - ［前回の配分先を読込］で、この商品の直近の配分（区分 0 / 1、状態は問わない）の配分先を追加する。この商品の配分がなければ、同じブランドの直近の配分先を使う。
- **単価**

| 配分先 | 単価 |
|---|---|
| 倉庫(0)・売仕店(3)・直営店(6) | 配分先別の適用上代。上代の系統は店種で選ぶ（倉庫・直営店は店舗用、売仕店・卸先は本部売上用。`EnumJodaiTaisho` の定義どおり。現行の店舗配分入力は売仕店にも店舗用を使っていた） |
| 卸先(1) | 上代 × 得意先の掛率（`MasterTokui.RateProper`）÷ 100、1 円未満切捨（判断 2）。受注入力は掛率をヘッダに持つだけで、単価を自動計算する共通処理はないため、ここで規則を決める |

- 下代は商品マスタの原価（現行どおり）。

### 3.3 按分パネル（タブ 2 の上部）

| 項目 | 選択肢 |
|---|---|
| 方式 | 同数／比率 |
| 同数の数量 | 1 配分先・1 SKU あたりの数（例: 2） |
| 比率の基準 | 売上実績／前回配分／手入力 |
| 売上実績の範囲 | 期間（既定は直近 4 週）、対象（同一商品／同一ブランド） |
| 端数 | 切捨／四捨五入 |
| 配分する総数 | SKU ごとに「有効在庫」（既定）または「入力した数」 |
| 対象 SKU | 全 SKU／選択中の列だけ |

- ［比率を計算］で、各行の「比率」列に比率（%）を入れる。手入力で直すこともできる。
- ［按分実行］で、マトリクスに数を入れる。既存の入力は上書きする。

**比率の基準**

| 基準 | 内容 |
|---|---|
| 売上実績 | 期間内の配分先別の売上数量。店舗は店舗売上（`Tran01Tenuri.Id_Tenpo`）、卸先・売仕店は出荷売上（`Tran00Uriage.Id_Tokui`）を使う。倉庫は 0 |
| 前回配分 | 前回の配分先と同じ配分（区分 0 / 1）の、配分先別の数量 |
| 手入力 | 「比率」列にそのまま入力する |

- 比率の合計が 0 のとき（売上がまったくない場合など）は、均等にする。

### 3.4 按分の規則（`AllocationCalculator`、純粋関数）

**同数** `Equal(perDestination, available, destinationCount)`

- 行の並び順（上から）に、1 行ずつ `min(同数, 残り)` を入れる。残りがなくなったら止める。旧「同数展開」と同じ。

**比率** `ByRatio(total, weights, rounding)`

- 計算値 = 総数 × 比率 ÷ 比率合計
- 切捨: 計算値の整数部だけを入れる。余りは配らない（旧仕様と同じ）。
- 四捨五入: 計算値を四捨五入する。合計が総数を超える場合は、小数部の小さい行から 1 ずつ減らして、総数以内に収める。
- 総数・比率が 0 以下なら、すべて 0 にする。

在庫上限:

- 「総数＝有効在庫」なら、合計は有効在庫を超えない。
- 「総数＝入力した数」が有効在庫を超える場合は、按分実行時に警告を出して続行する（確定時の在庫検査で止まる）。

## 4. 登録（保存）

1. 検査（警告だけ出して続けられる）
   - 配分後在庫がマイナスの SKU がある → 確定時にエラーになる旨を出す。
2. 洗い替え
   - `SaveHaibunAsync(置換対象, 新しい行)` を 1 回呼ぶ。
   - 置換対象は、この倉庫×商品にある修正可能な区分 1 の配分すべて（読込時と同じ条件）。
3. 新しい行の値
   - `Kubun = 1`（在庫配分）、`RelateNo1 = 0`
   - `Id_Soko` = 配分元倉庫、`Id_Tenpo` = 配分先
   - `DenDay` / `NouhinDay` = 画面の指示日 / 納品日
   - 単価は 3.2 のとおり。
4. 確定は Step 1 の配分確定画面で行う。
   - 配分先が倉庫(0)・直営店(6)なら移動出庫、卸先(1)・売仕店(3)なら出荷売上になる（決定 I4。変更なし）。

> 区分 1 の既存の配分（現行の店舗配分入力で作ったもの）は、同じ条件でこの画面に読み込まれる。データの移行は要らない。

## 6. 承認をお願いしたい点

1. **画面の統合**: 在庫品配分・店舗出荷依頼・移動指示(SKU/商品) を独立した画面にせず、「在庫配分入力」1 画面で扱ってよいか。
   - 在庫品配分 → タブ 1 の「滞留」条件で抽出する。
   - 店舗出荷依頼 → 本部が依頼数をこの画面で入力する（店舗側からの入力画面は作らない）。
   - 移動指示 → 配分先に倉庫を選べるようにする。
2. **卸先(1)への配分の単価**: 上代 × 得意先の掛率（`RateProper`）÷ 100、1 円未満切捨でよいか。掛率が 0 の得意先は上代のままにする。倉庫・売仕店・直営店は、現行どおり店舗別の上代にする。
3. **比率の基準**: 売上実績・前回配分・手入力の 3 種類でよいか。旧CVnet のショートカット 2 にあった消化率・積送数・当日／前日／前々日売上の表示は入れない。
4. **名前付きパターンの登録・呼出**（旧「パターン登録」）を 1.1 以降に回してよいか。当面は「前回配分」の比率で代わりにする。
5. **店舗配分入力の扱い**: 「在庫配分」の区分を外して初回配分専用にし、Step 4（仕入配分入力）で画面ごと置き換える方針でよいか。
