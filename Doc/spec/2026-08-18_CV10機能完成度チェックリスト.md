## 1. 本書の目的・判定基準

### 1.1 目的

本書は、2026-08-12版の「フォルダ別・画面実装レベル集計」を置き換え、次の担当者がそのまま設計・実装・UAT準備へ進めるための基準書とする。

- 現行の大メニューを基準に、実装済み領域と残作業を整理する。
- 残作業を **1.0実装予定 / 1.1予定 / 1.2以降** に分ける。
- 実装済み機能の詳細説明は繰り返さず、Release Gate、必要な仕様決定、最小UATの不足を中心にする。
- `refer/cvnet-knowlege/` に存在する旧CV.netの業務能力を、CV10での実装時期・代替・見送り判断へ対応付ける。

### 1.2 正本の優先順位

内容が食い違う場合は、次の順に確認する。

1. 最新コミットの実コード・DB定義・テスト。
2. `CvWpfclient/Models/MenuData.cs` の現行大メニューと到達経路。
3. [2026-08-18_請求計算・支払計算_詳細設計.md](archive/2026-08-18_請求計算・支払計算_詳細設計.md) および同日付の各詳細設計。
4. [2026-08-17_旧cvnet比較_仕様決定判断材料.md](2026-08-17_旧cvnet比較_仕様決定判断材料.md) と [未適用・保留課題台帳](2026-08-17_旧cvnet比較_未適用・保留課題.md)。
5. `refer/cvnet-knowlege/` のマニュアル、業務フロー、帳票集、DB定義。
6. 2026-08-12版チェックリスト（当時の調査履歴）。

`MenuData.cs` の `addInfo:"準備中"` は更新漏れを含む。出荷指示確定、出荷処理、配分・引当・有効在庫照会などは実装済みのため、**表示文言だけで未実装判定しない**。

### 1.3 状態・期別の定義

| 表記 | 判定 |
|---|---|
| 実装済 | 実コードに業務処理があり、ビルドまたは関連テストの記録がある |
| 要UAT | 実装済みだが、実ユーザーの業務シナリオとして合格記録が無い |
| 1.0実装予定 | 1.0の必須業務シナリオ、移行、請求・支払、月次運用を成立させるためRelease前に必要 |
| 1.1予定 | 1.0に代替手段があり、初回Release後に業務範囲・利便性を拡張するもの |
| 1.2以降 | 外部契約、画像・高度分析基盤、複数締日、別製品との責務分担など、先に要件化が必要なもの |
| 仕様決定 | 実装前に業務責任者が選択し、Given/When/Thenまたはデータ契約へ落とす必要があるもの |
| 対象外候補 | 旧CV.netにはあるが、CV10で継承するか未決定。削除・非表示は承認後に行う |

完成度は画面数ではなく、次の条件で判定する。

- 1.0必須シナリオが画面からサーバー、DB、帳票まで完遂する。
- 通常更新値とRebuild値が一致する。
- 取消・再実行・楽観排他・異常終了後の復旧手順が確認されている。
- 移行データと新規テストデータの両方で金額・数量・税・残高を検算できる。
- UATの実施者、証跡、合格基準が決まっている。

### 2.2 1.0完成までの結論

商品登録から発注、仕入、在庫、配分、出荷、売上、入金・支払、消込、請求・支払計算、Rebuildまでの主要部品は揃った。現在の主要なRelease Gateは次の4点である。

1. 請求書・支払/買掛帳票・月次予定表を、生成済み `SummaryUriSei` / `SummaryKaiShi` と数値突合していない。
2. 1.0で必要な月次・原価処理の範囲が確定しておらず、月間集計、在庫累計、原価更新が未実装（期首売掛/買掛/請求/支払の残高投入は2026-08-19に外部CSV取込＋再計算ガードで対応済み。在庫/原価の期首残は未対応）。
3. 発注・受注・仕入・支払・配分の移行実データが極端に少なく、通し検証用データと期首残高投入方法が未整備。
4. 実DBでの請求/支払計算、締日変更警告、Rebuild冪等性を含むMini-UATの担当者、証跡、合格基準、再実行手順が未決定である。

## 8. 次担当（Luna等）への実行指示

### 8.1 最初に行うこと

1. `git status --short` と最新HEADを確認し、本書のHEAD差分を更新する。
2. 4.3の優先順1から、請求書・支払/買掛帳票・月次予定表を生成済み集計と数値突合する。
3. 実DBコピーとバックアップを準備し、締日変更警告・Rebuild冪等性・旧締日残データ手動再計算を含むMini-UATへ進む。
4. 実施ごとに本書4章の状態と6章のUAT現在地だけを更新する。実装詳細を本書へ重複転記しない。

### 8.2 請求・支払実装の停止条件

- D-04（親子請求出力）またはD-05（適格請求書要件）が未決で、請求書QFM/SQL/UIのデータ契約を一意にできない。
- 移行DBのバックアップ無しに実DB再集計やMini-UATを実行しようとしている。

### 8.3 変更単位

- コミット1: 請求書・支払/買掛帳票・月次予定表の数値突合とQFM/SQL/UI。
- コミット2: 実DBコピーによるMini-UATの証跡と必要な修正。
- コミット3: 期首残高（外部CSV取込＋再計算の期首以前ブロック。2026-08-19実装）と移行リハーサル。
- コミット4: D-04/D-05の決定反映。
- コミット5: D-01/D-07、性能、メニュー公開/権限の決定・実装。

各コミットで `git diff --check`、影響する最小プロジェクトのbuild/test、CRLFを確認する。DB、税、金額、月次、請求に関わるため、正常系だけでなく境界値・再実行・rollbackを必須とする。

## 9. 既知のリスク

| リスク | 影響 | 対応 |
|---|---|---|
| `MenuData`の準備中表示が実装状態と不一致 | UAT対象の誤認 | D-10でAvailabilityを導入し、表示文言を同期 |
| 1.0月次・原価範囲が未決 | 売上/在庫金額/粗利/帳票がRelease後に変動 | D-01/D-06/D-07を先行決定 |
| 請求再計算と再発行の帳票確認未実施 | 番号維持、連番更新、再発行表示を実DBで確認できていない | 通常再計算/Rebuildと明示的再発行をMini-UATで比較する |
| 親子請求の実データが無い | 警告・合算・帳票を検証できない | 専用UATデータを作成 |
| 支払・配分の移行データがほぼ無い | 正常系しか確認できない | 境界/取消/例外データを新規作成 |
| 保存済み請求残・支払残が無い | Rebuildの締日変更履歴を検出できない | 実DB/UATで旧締日残データを確認し、変更時は手動再計算する |
| 請求/支払/Rebuildの実画面操作 | ダイアログ、ストリーム取消、警告表示の自動証跡が無い | 実DBコピーでMini-UATを実施する |
| `substr(DenDay, 1, 6)` 締日照会 | 大量残高行での照会性能が未計測 | 実DBコピーで実行時間・索引要否・取消を測定する |
| 大量店舗売上データ | 月次・帳票の性能劣化 | 時間上限、索引、キャンセル、再実行を計測 |
| 外部連携画面が通常メニューから開く | 空画面・誤操作 | 1.0ではHidden/Preview |
| LCV個人情報の責務未定 | 1.1の法務・セキュリティ・削除・移行要件不足 | D-14を1.1設計前に決定し、独立したセキュリティ審査を行う |
