# クライアントのユーザ別配布（複数ユーザ対応の公開案）

調査日: 2026-11-09（CV10 `62012e29`、Velopack 1.2.161）／確認日: 2026-11-15（`166cda67`。配布スクリプト・クライアント設定と読込・Velopack 版数が変わっていないことを静的に確認。スクリプト作成・pack・導入は未実施）
位置付け: 公開方式の提案。実装・運用の承認を意味しない。未実装。

## 1. 目的

利用ユーザ（顧客）ごとに接続先の CvServer が異なるため、接続先 URL をユーザ別に設定した WPF クライアントを配布する。設定は `appsettings_user01.json` のようなユーザ別ファイルで管理し、共通の `appsettings.json` の URL など必要な項目だけを上書きする。

## 2. 現状

| 項目 | 現行 |
|---|---|
| 配布作成 | `publish-velopack.bat`。publish → `vpk pack --packId CreativeVision10` |
| 公開経路 | (1) 版数なし: 社内配布・自動更新あり。pack 後に `~/bin/publish.sh` で更新先へ転送（この端末には現在このスクリプトが無い）<br>(2) 版数あり: GitHub Release 用 Portable ZIP・自動更新なし（[公開手順](公開手順.md)） |
| 接続先 URL | `CvWpfclient/appsettings.json` の `ConnectionStrings:Url` |
| 更新先 URL | `CvWpfclient/appsettings.Production.json` の `Update:FeedUrl`（git 管理外、publish 出力に含まれる）。`Update:Channel` は未使用 |
| 設定の読込順 | `appsettings.json` → `appsettings.{環境}.json` → `%LOCALAPPDATA%\CreativeVision10\clientsettings.json`（開発環境以外。`noclientjson` 指定時は無効） |
| 出力時の URL 置換 | 版数ありの経路だけ `prepare-release-client.ps1` が `ConnectionStrings:Url` をテキスト置換（コメント保持のため JSON パーサー不使用） |

Velopack の制約: `vpk pack` は `--packDir` を固めるだけで設定を差し替えない（pack 前の publish 出力で差し替える）。更新時はインストール先（`current`）が丸ごと置き換わり、手修正は失われる。更新元は起動中のクライアントの `Update:FeedUrl` で決まる。

## 3. 方式（案A: ユーザ別パッケージ）

1回の publish 出力をユーザ数だけ複製し、ユーザ別設定を上書きしてからユーザごとに `vpk pack` する。

```text
publish（1回） ─┬─ 複製 → user01 設定を上書き → vpk pack → Releases\user01\ → 更新先 …/wpfclient/user01/
                ├─ 複製 → user02 設定を上書き → vpk pack → Releases\user02\ → 更新先 …/wpfclient/user02/
                └─ （共通版は従来どおり）
```

### 3.1 ユーザ別設定ファイル

- 名前は `appsettings_<ユーザID>.json`。ユーザID は英数字・`-`・`_` に限る（packId・フォルダ名・URL に使うため）。
- 置き場所はリポジトリ直下の `deploy/clients/`（案、未作成）。顧客サーバの URL を含むため git 管理の有無は要判断（7章）。管理しないなら `.gitignore` に追加する（現行の `appsettings.*.json` は `_` 区切りに一致しない）。publish 出力へ混入しないよう `CvWpfclient/` 直下には置かない。
- 変える項目だけを書く。

```json
{
	"ConnectionStrings": { "Url": "https://user01.example.jp:5012" },
	"Update": { "FeedUrl": "https://cv10.dtpnet.co.jp/wpfclient/user01/" }
}
```

- 上書きできるキーは許可リストで限定する（必須: `ConnectionStrings:Url`、`Update:FeedUrl`。任意: `Application:WeatherRegion`、`Application:JmaWeatherAreaCode`、`Application:FitPosition`）。それ以外のキーや認証情報らしき値（`prepare-release-client.ps1` と同じ検査）があれば停止する。

### 3.2 上書き処理

- 複製した出力の `appsettings.json`（`ConnectionStrings:Url` 等）と `appsettings.Production.json`（`Update:FeedUrl`）を、現行と同じく「該当キーが1件だけあることを確認してから値をテキスト置換」する。コメント・既定値・版数は残す。
- URL は `http`/`https` の絶対 URL でユーザ情報を含まないことを検査し、`FeedUrl` は `/` 終わりにそろえる。
- 書き換え後、全ユーザ分の `ConnectionStrings:Url` と `FeedUrl` を一覧出力して目視できるようにする（認証情報は出さない）。

### 3.3 pack と出力先

- 版数は全ユーザ共通（1回の実行で `Application.Version` を1回だけ増分）。
- packId は既定の `CreativeVision10` のまま、出力先と更新先をユーザ別に分ける（既存のインストール先・ショートカットは変わらない）。1台に複数ユーザ版を同時に入れる場合だけ `--packId CreativeVision10-<ユーザID>` とするが、別アプリ扱いで既存版から更新では移れない（入れ直し）。
- 出力先は `CvWpfclient\Releases\<ユーザID>\`。差分パッケージは前回出力を基に作られるため、ユーザごとに固定して残す。共通版も従来どおり作成できるようにする。

### 3.4 スクリプト構成（案）

- 新規 `publish-velopack-users.ps1`（リポジトリ直下）。引数 `-Users user01,user02`（省略時は `deploy/clients/appsettings_*.json` 全件）、`-Local`（転送しない）。手順は vpk 版数確認 → 版数増分 → publish（1回）→ ユーザごとに「複製 → 検査・上書き → `vpk pack`」→ 転送。いずれかで失敗したら停止し、作成済み分も転送しない（全件そろってから転送）。
- `publish-velopack.bat` は変更しない（共通版・GitHub Release の経路はそのまま）。
- 転送は `publish.sh` の代わりにユーザ別出力を `…/wpfclient/<ユーザID>/` へ送る処理が要る。方法（scp 先・認証）は現行運用に合わせて決める（7章）。

## 4. 既知の注意点

1. **画面で保存した URL が優先される**: 開発環境以外では `clientsettings.json` の `ConnectionStrings:Url` が優先される。設定画面（`SysSetConfigViewModel`）で保存すると URL も書き込まれ、その端末ではパッケージ側の URL が効かない。導入・切替時に `clientsettings.json` の URL を確認・削除する手順を運用に含める。
2. **既存端末の移行**: 既存端末は共通の更新先（`…/wpfclient/`）を見ているため、初回だけユーザ別 Setup で入れ直す（packId が同じなら上書きインストール）。
3. **更新先を共通にしない**: ユーザ別版の `FeedUrl` を共通にすると、次の更新で共通版に置き換わり URL が既定値に戻る。
4. **環境名**: `appsettings.Production.json` は `DOTNET_ENVIRONMENT` 未設定時（Production）に読み込まれ、端末で別の値を設定していると読み込まれない。
5. **ディスク容量**: 自己完結の publish 出力とパッケージをユーザ数分作る。

## 5. 検証計画

| 区分 | 確認内容 |
|---|---|
| 生成 | 2ユーザ分を `-Local` で作成し、各パッケージの `appsettings.json` / `appsettings.Production.json` の URL がそのユーザの値で、他の項目・コメントが共通版と同じこと |
| 異常系 | 許可外キー、認証情報らしき値、不正 URL、`ConnectionStrings:Url` が0件・2件、ユーザ設定ファイル無し → いずれも停止し転送しないこと |
| 導入 | 検証用 PC（または VM）に user01 版をインストールし、user01 のサーバへ接続できること |
| 更新 | user01 の版を1つ上げて user01 の更新先へ置き、更新後も URL が user01 のままで、共通の更新先を参照しないこと |
| 既存端末 | 共通版の導入済み端末へ user01 版を上書きインストールし、更新先・URL が切り替わること。`clientsettings.json` に URL がある場合の挙動 |
| 回帰 | `publish-velopack.bat`（版数なし・版数あり）の出力が従来と同じこと |

## 6. ロールバック

- スクリプトの追加だけで製品コードは変更しない。不要になればスクリプトとユーザ設定ファイルを削除する。
- 誤った URL のパッケージを公開した場合は、正しい設定で版数を上げて同じユーザの更新先へ再公開する。接続も更新確認もできない端末は正しい Setup で入れ直す。

## 7. 判断が必要な事項

1. ユーザ別設定ファイルの置き場所と git 管理の有無（顧客サーバ URL を含む）。
2. packId を共通（`CreativeVision10`）にするか、ユーザ別にするか（1台に複数ユーザ版を入れる必要があるか）。
3. 更新先サーバのフォルダ構成（`…/wpfclient/<ユーザID>/`）と転送方法。現行の `~/bin/publish.sh` の置き場所。
4. GitHub Release の Portable ZIP もユーザ別に作るか（本案は社内配布の自動更新経路のみが対象）。
5. 既存端末の移行方法（入れ直しで良いか）。
6. 4章1の `clientsettings.json` の URL 優先を運用で扱うか、別途コード変更で対応するか（本案の範囲外）。
