# `Tran*.Rate` 列の掛率・税率分離課題（未処理）

作成日: 2026-08-24
発端: `Doc/spec/2026-08-24_HHTデータ更新詳細設計.md` の検討中に判明。**HHTデータ更新の実装スコープ外**として切り出した。
状態: **未着手**（対応方針の決定が必要）

## 1. 課題

`Tran00Uriage` / `Tran01Tenuri` / `Tran03Shiire` / `Tran12Jyuchu` の `Rate` 列は、
列コメントが「掛率」であるにもかかわらず**入力画面は消費税率(%)として使っている**。

方針として「`Tran13Hachu` と同様に `Rate` を掛率のまま残し、税率はローカル変数
`taxRatePercent` に分離する」ことが決定した（2026-08-24）。ただし**既存データの移行方針が未決**である。

## 2. 現状の実装

### 2.1 `Rate` を税率として使っている画面

| 画面 | 該当箇所 |
| --- | --- |
| 出荷売上 | `CvWpfclient/ViewModels/06Uriage/ShukkaUriageInputViewModel.cs` `LoadTaxRateAsync()` / `UpdateHeaderTotals()` |
| 店舗売上 | `CvWpfclient/ViewModels/06Uriage/ShopUriageInputViewModel.cs` 同 |
| 仕入 | `CvWpfclient/ViewModels/05Shiire/ShiireInputViewModel.cs` 同 |
| 受注 | `CvWpfclient/ViewModels/04Juchu/JuchuInputViewModel.cs` 同 |

いずれも次の形になっている。

```csharp
async Task LoadTaxRateAsync() {
    var rate = await AppGlobal.LogicGetTax(1, Current.DenDay);
    CurrentEdit.Rate = rate;              // ← 税率を Rate へ入れている
    UpdateHeaderTotals();
}

void UpdateHeaderTotals() {
    var absKingakuTotal = Math.Abs(CurrentEdit.KingakuTotal);
    var tax = (int)Math.Round(absKingakuTotal * CurrentEdit.Rate / 100.0);   // ← Rate を税率として使用
    CurrentEdit.Tax = tax;
    CurrentEdit.Total = absKingakuTotal + tax;
}
```

### 2.2 目標とする形（発注が既に実装済み）

`CvWpfclient/ViewModels/03Hatchu/HachuInputViewModel.cs` は税率を `Rate` から分離している。

```csharp
// 仕入先掛率(Rate)から分離した消費税率のキャッシュ。伝票を開いた時点の発注日基準で LoadTaxRateAsync が更新する。

void UpdateHeaderTotals() {
    var absKingakuTotal = Math.Abs(CurrentEdit.KingakuTotal);
    var tax = (int)Math.Round(absKingakuTotal * taxRatePercent / 100.0);

async Task LoadTaxRateAsync() {

```

`CvDomainLogic/ConvertDbTran.cs` は旧CVnetの「掛率1」を `Rate` へ入れている。同ファイルにコメントがある。

> CV10側では消費税率として使う。新規入力の各InputViewModelのUpdateHeaderTotalsと同じ式）から

該当箇所: `ConvertDbTran.cs` の `Rate = rate` 5箇所（`Tran00Uriage` / `Tran01Tenuri` / `Tran03Shiire` / ほか）と `CalcMigratedTaxTotal()`。

## 3. 既存データの実態（`server-user163.db` / 2026-08-24 確認）

| テーブル・列 | 値の分布 | 意味 |

## 4. 決めるべきこと

1. **既存 `Rate` の扱い**
   - 案A: 税率列（例 `TaxRate`）を新設し、既存 `Rate` の値をそこへ移してから `Rate` をクリアする。DDL追加（`UpdateDb.cs`）が必要。
   - 案B: `Rate` をそのまま掛率として扱い、既存値（税率10）はクリアする。税率は伝票日付から `MasterSysman` で毎回引き直す。DDL追加なし。
   - 案C: 現状維持（`Rate`=税率）とし、列コメントを「消費税率」に直す。掛率が必要なら別列を追加する。
2. **`Tran13Hachu` との整合**: 発注の `Rate`（掛率）はそのままか。
3. **`ConvertDbTran.cs` の移行ロジック**をどう直すか（再移行時の値）。
4. **`Tax` / `Total` の再計算が必要な既存伝票があるか**（`Rate` をクリアすると `UpdateHeaderTotals()` の再実行で `Tax` が 0 になり得る）。
5. 影響する帳票・集計（請求書、支払明細、売掛買掛集計）で `Rate` を参照している箇所の洗い出し。

## 5. HHTデータ更新側の扱い（決定済み・対応不要）

`Doc/spec/2026-08-24_HHTデータ更新詳細設計.md` の決定 F / G により、HHT変換で新規作成する伝票は
最初から次の形で作る。よって本課題の解決を待つ必要はない。

- `Rate` = VULCANの掛率（パーセント整数。`MasterTokui.RateProper` と同単位）
- 税率は `MasterSysman` から取得したローカル値で `Tax` / `Total` を計算し、`Rate` は使わない

ただし**本課題が未解決のうちは、HHT変換が作った伝票を既存の入力画面で開くと
`UpdateHeaderTotals()` が `Rate`（掛率）を税率として計算し、`Tax` が誤った値に上書きされる**。
入力画面側の分離（2.2 の形への統一）を先に行うか、HHT生成伝票を入力画面で開かない運用にするかを
実装時に確認する。
