## 1. 目的

既存の対比資料は、旧 CVnet の帳票を基準に CV10 の存在・項目・計算・レイアウト差を明らかにしたものである。本計画はその結果を入力とし、旧帳票の完全複製ではなく、**利用者が判断しやすく、機械にも意味を説明でき、継続的に改善できる CV10 の帳票体系**へ刷新する方針を定める。

帳票の価値は旧版との一致率ではなく、次の結果で評価する。

1. 数値が正しく、集計根拠を追跡できる。
2. 利用者が目的の判断や作業を短時間で完了できる。
3. PDFだけで閉じず、再集計・検索・AI支援に使える意味のあるデータを提供できる。
4. 法令、監査、個人情報、権限の制約を守る。
5. 帳票ごとの独自実装を減らし、変更と検証を継続できる。

## 2. 本計画の基本判断

### 2.1 旧帳票との差が軽微なら「済」とする

次のすべてを満たす帳票は、旧帳票との差が残っていても移植としては「済」とする。

- 金額、数量、税、在庫、締め、返品符号など業務結果が正しい。
- 法定記載、監査値、必須識別子が欠けていない。
- 主利用目的と対象範囲、集計粒度、並び順が実務上同等である。
- 主要な小計・合計が画面または帳票で確認できる。
- ラベル、余白、用紙方向、装飾、既定順などの差が判断結果を変えない。
- 代表データと境界値でPDFを確認できる。

用紙方向、罫線、旧版固有の配置、使用実績のない選択肢を一致させること自体は完了条件にしない。差を残す場合は「CV10仕様」として理由を記録する。

### 2.2 差分を4種類に分ける

| 区分 | 意味 | 例 | 扱い |
| --- | --- | --- | --- |
| A 正確性是正 | 数値・対象・法令・監査結果が誤る | 返品符号、税率、集計期間、親子請求単位 | 最優先で修正 |
| B 業務価値再設計 | 判断に必要な粒度・軸・合計が不足 | 店舗別、色サイズ別、予算対比、例外抽出 | 利用目的から再設計 |
| C 軽微差 | 結果を変えない表示差 | 用紙方向、余白、ラベル、旧既定順 | 原則「済」 |
| D 新規価値 | 旧帳票にないCV10機能 | 根拠表示、異常候補、データ出力、AI要約 | 効果と安全性を評価して追加 |

既存の「要修正あり」は、この4区分へ再判定する。旧版と異なるという理由だけで A または B にしない。

## 3. 次世代帳票の設計原則

### 3.1 帳票ではなく「判断単位」で設計する

先に帳票名や旧レイアウトを決めず、次を1枚の帳票定義として明文化する。

- 誰が、いつ、何を判断または処理するために使うか。
- 対象期間、対象組織、抽出条件、除外条件。
- 明細・集計・例外のどの粒度が必要か。
- 金額、数量、率、在庫の定義と符号。
- 帳票から次に行う操作（確認、連絡、補充、承認、再印刷等）。

同じデータを目的別に紙帳票へ増殖させず、検索条件・表示モード・出力形式で共通化できるものは統合する。一方、法定帳票や現場作業票など用途が異なるものは無理に統合しない。

### 3.2 三層で提供する

| 層 | 役割 | 主な提供物 |
| --- | --- | --- |
| 概要 | 状況と例外を素早く把握 | KPI、前年差、予算差、警告件数、上位要因 |
| 分析 | 原因を比較して判断 | 店舗・得意先・商品・色サイズ・期間の切替、構成比、推移 |
| 根拠 | 数値を検算・監査 | 伝票・明細、計算式、抽出条件、作成日時、データ基準日 |

PDFは固定保存・配布に適した最終表現とする。対話的な絞り込みや探索をPDFへ詰め込まず、CV10画面で分析し、必要な状態をPDFとして固定する。

### 3.3 意味を共有する

帳票ごとにSQLを個別解釈しないよう、主要指標に共通の意味定義を持たせる。

- 指標ID、表示名、説明、単位。
- 計算式、符号規則、丸め、NULL・0の扱い。
- 対象伝票区分、取消・返品・値引の扱い。
- 集計可能な軸と禁止する集計。
- データ基準日、更新頻度、確定・速報の区別。
- 機密区分と必要権限。

同じ「売上」「粗利」「消化率」「投入数」が帳票ごとに別定義にならないことを目標とする。定義が異なる場合は名称を分け、帳票上でも注記する。

## 4. AI対応方針

### 4.1 AI対応の意味

AI対応は、帳票へ生成文章を付けることだけではない。まず、AIや後続処理が数値の意味・条件・根拠を誤解しない構造を整える。

優先順位は次のとおりとする。

1. 指標定義とデータ契約の明示。
2. PDFと同じ条件・列定義を持つ機械可読データの提供。
3. 集計値から根拠明細へ到達できる識別子の保持。
4. ルールベースで再現可能な例外・変化点の検出。
5. 上記の確定データだけを材料にしたAI要約・質問支援。

### 4.2 AI支援の候補

- 「前月比が大きい店舗と主因を示す」など、定義済み指標に基づく要約。
- 欠品、滞留、急増減、予算乖離などの候補提示。
- 自然文から帳票候補と検索条件を提案するナビゲーション。
- 集計結果から根拠明細へ誘導する説明支援。
- 帳票の利用履歴と問い合わせ傾向を基にした改善候補の提示。

AIの文章は参考情報とし、確定値・法定表現・会計税務判断を書き換えない。数値、対象期間、フィルタ、指標定義、根拠行を併記し、利用者が検証できるようにする。

### 4.3 AIへ渡さないもの・自動化しないもの

- 権限外の得意先、仕入先、社員、原価、個人情報。
- APIキー、接続情報、認証情報、内部ログの機密値。
- 根拠が確定していない推測値を正式帳票の確定値として扱うこと。
- AI判断だけによる請求、支払、在庫評価、税額、承認状態の更新。
- 入力データ、モデル、プロンプト、出力根拠を追跡できない自動配布。

## 5. 帳票ポートフォリオの再評価

既存2資料の各帳票を、次の状態へ再分類する。

| 状態 | 判定 |
| --- | --- |
| 継続 | 現状で目的を満たす。軽微差は許容 |
| 軽微改善 | 読みやすさ、注記、並び順等だけを直す |
| 正確性是正 | 数値・範囲・法令・監査上の誤りを直す |
| 再設計 | 利用目的、粒度、集計軸、導線から作り直す |
| 統合 | 類似帳票を条件・表示モードでまとめる |
| 廃止候補 | 利用目的がなく、他画面・帳票で代替できる |
| 新規 | 現行業務に必要だが代替がない |

再評価票には最低限、利用者、利用頻度、判断目的、現行代替、数値リスク、法令・監査要件、改善効果、概算規模、状態、根拠を記録する。利用頻度が不明な帳票は、推測で廃止せず確認対象とする。

## 6. 優先順位

優先度は旧帳票との差の数ではなく、次の順で決める。

1. 数値誤り、税・請求・支払・在庫、監査不備などの影響。
2. 日常業務の停止、手作業、二重入力、誤判断の頻度。
3. 対象利用者・伝票・金額の規模。
4. 複数帳票へ共通適用できる改善効果。
5. 実装・移行・検証コスト。

初期候補は以下とするが、着手順は再評価票と業務確認で確定する。

- 最優先: 返品符号など横断的な数値正確性、請求・支払・税・在庫の不整合。
- 次点: 配分など現行帳票がなく手作業が残る領域、根拠明細へ到達できない重要帳票。
- 再設計候補: 投入売上在庫、商品消化率、得意先別売上日報、半期・予算実績系。
- 統合候補: 同一データの粒度違い・原価表示有無・週報月報・ランキング系。
- 後回し: 旧版との用紙方向、余白、装飾だけの差。

## 7. 実施フェーズ

### Phase 0: 完了基準と棚卸し

- 既存対比表の全帳票を A～D とポートフォリオ状態へ再判定する。
- 軽微差を「済」に変更し、未完件数を実態に合わせる。
- 帳票ごとの責任者、主利用者、利用頻度、保存要件を確認する。
- 廃止・統合候補は利用部門の合意前に削除しない。

成果物: 帳票台帳、再評価票、優先順位、廃止・統合候補一覧。

### Phase 1: 正確性の基盤

- 返品・取消・値引・税・丸め・期間境界の共通規則を確定する。
- 売上、粗利、在庫、消化率、投入数など主要指標を定義する。
- 共通指標に対する正常系・境界値・異常系の検証データを整備する。
- 帳票に抽出条件、基準日、作成日時、確定・速報区分を表示する。

成果物: 指標辞書、計算規則、検証データ、横断テスト。

### Phase 2: 高優先帳票の再設計

- 利用者への確認は旧項目の要否ではなく、判断と次の行動を中心に行う。
- 概要・分析・根拠の三層で画面とPDFの役割を分ける。
- 1帳票ずつ詳細設計を承認し、最小単位で実装・検証する。
- 旧帳票との比較は回帰確認に使い、レイアウトの目標にはしない。

成果物: 帳票別詳細設計、画面・QFM・データ契約、受入結果。

#### 実績: 配分4帳票（2026-09-17）

- 滞留・欠品例外（出荷指示一覧）: 既存の画面検索・CSV出力にPDF出力を追加。SQL・QFM列対応・buildは確認済みで、実PDFと複数伝票・欠品時の小計確認は残る。
- 出荷指示明細書: header/detailの2帳票を実装し、F6から連続出力する。SQL・QFM列対応・buildは確認済みで、実PDF・バーコード可読性と複数伝票の確認は残る。
- 納入一覧表: 色／サイズ基準を切り替える固定10列マトリクスを実装。qfmprintで横計、10列超の続きページ、改ページを確認済み。本番gRPC経路と実データの10列超は未確認。
- 配分出荷リスト: 伝票別、品番別、SKU別、商品得意先別の4形式を1画面の出力単位として実装。qfmprintで多段小計、改ページ、最大桁を検算済み。本番CvServer経路は未確認。

いずれもSQLの列順とQFMの`itemN`対応、cp932・XML、`dotnet build CvWpfclient/CvWpfclient.csproj`を確認済みである。旧形式の追加可否はH10の利用実績確認後に判断する。

### Phase 3: 機械可読化とAI支援

- 指標ID、列名、型、単位、機密区分を持つ出力契約を設計する。
- PDFと機械可読データが同じ条件・同じ計算結果になるようにする。
- 根拠参照、異常候補、要約、自然文検索を小さな対象で試行する。
- 正答率だけでなく、根拠提示率、誤誘導、権限漏れ、利用時間短縮を評価する。

成果物: データ契約、AI利用規約、評価セット、試行結果。

### Phase 4: 統合・廃止・運用改善

- 利用実績と代替可否を確認して重複帳票を統合する。
- 廃止時はメニュー、画面、QFM、文書、権限、保存データを一体で扱う。
- 問い合わせ、出力失敗、処理時間、利用頻度を定期評価する。

成果物: 移行計画、廃止記録、運用指標、改善バックログ。

## 8. 帳票1件の標準作業

1. 利用目的・利用者・次の行動を確認する。
2. 現行CV10、旧CVnet、実データ、関連画面の差を確認する。
3. 「継続／軽微改善／正確性是正／再設計／統合／廃止候補／新規」を決める。
4. 指標、粒度、フィルタ、権限、保存要件、PDFと画面の役割を詳細設計する。
5. SQLの列順とQFMの `itemN`、CSV契約を固定する。
6. 正常、0件、返品・取消、負値、NULL、最大桁、改ページを検証する。
7. qfmのcp932、XML、列対応を確認し、実PDFで視認性と数値を確認する。
8. 代表利用者の受入確認後、台帳と定義を更新する。

仕様変更を伴う場合は、帳票ごとの詳細設計を承認してから実装する。

## 9. 共通の受入基準

### 9.1 正確性

- 明細から小計・合計を再計算できる。
- 返品、取消、値引、税、丸め、期間端点が定義どおりである。
- 画面、PDF、機械可読データで同じ条件なら同じ結果になる。
- 監査値と現行マスタ値を混同しない。

### 9.2 利用性

- 帳票名、対象期間、フィルタ、単位、基準日が一目で分かる。
- 重要な合計と例外がページを追わずに把握できる。
- コードだけでなく必要な名称を表示し、桁あふれや欠落がない。
- 0件時に空白PDFではなく対象なしを明示する。

### 9.3 技術・運用

- SQLのSELECT列、CSV列、QFMの `itemN` が一致する。
- QFMはcp932、所定のXML・CSV構造を守る。
- 代表データによる実PDF確認と差分レビューを実施する。
- 権限外データを検索・PDF・データ出力・AIへ渡さない。
- 指標定義、変更理由、検証結果、残余差を記録する。

### 9.4 AI支援

- AI出力から対象期間、条件、参照指標、根拠データを確認できる。
- 確定値とAI生成文を視覚的・データ的に区別する。
- 根拠が不足する場合は断定せず「判断不可」とできる。
- 同じ入力に対する重要数値はモデル出力ではなく確定計算から取得する。

## 10. 効果測定

刷新の進捗は帳票作成本数ではなく、次で測定する。

- A区分（正確性是正）の未完件数。
- 指標定義済み帳票の比率。
- 根拠明細へ到達できる主要帳票の比率。
- 手集計・Excel再加工・二重入力に要する時間。
- 帳票の出力失敗、問い合わせ、数値不一致の件数。
- 利用されていない帳票と重複帳票の削減数。
- AI支援の根拠提示率、誤誘導率、権限違反0件、作業時間短縮。

## 11. 実装開始前の確認事項

1. 「軽微差は済」とする本計画の完了基準を採用するか。
2. 最初に再評価する業務領域（候補: 分析、配分、売掛・買掛、在庫）。
3. 正式な指標定義を承認する業務責任者。
4. PDF以外に必要な機械可読形式と利用者。
5. AI支援で外部サービスを利用できるデータ範囲と、社内限定処理の境界。
6. 利用実績を取得できない帳票の存廃判断方法。

上記を確認後、Phase 0 の帳票台帳・再評価票を作成する。個別帳票の実装は、再評価結果と帳票別詳細設計の承認後に開始する。
