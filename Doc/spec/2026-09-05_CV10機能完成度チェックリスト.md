## 1. 本書の目的・判定基準

### 1.1 目的

- 現行の大メニューを基準に、実装済み領域と残作業を整理する。
- 残作業を **10.0実装予定 / 10.1予定 / 10.2以降** に分ける。
- 実装済み機能の詳細説明は繰り返さず、Release Gate、必要な仕様決定、最小UATの不足を中心にする。

### 1.2 正本の優先順位

内容が食い違う場合は、次の順に確認する。

1. 最新コミットの実コード・DB定義・テスト。
2. `CvWpfclient/Models/MenuData.cs` の現行大メニューと到達経路。
3. `Doc/spec/` フォルダの各詳細設計。
4. `refer/cvnet-knowlege/` のマニュアル、業務フロー、帳票集、DB定義。

### 1.3 状態・期別の定義

| 表記 | 判定 |
|---|---|
| 実装済 | 実コードに業務処理があり、ビルドまたは関連テストの記録がある |
| 要UAT | 実装済みだが、実ユーザーの業務シナリオとして合格記録が無い |
| 10.0実装予定 | 10.0の必須業務シナリオ、移行、請求・支払、月次運用、原価、上代を成立させるためRelease前に必要 |
| 10.1予定 | 10.0に代替手段があり、初回Release後に業務範囲・利便性を拡張するもの。**締日更新・配分の別入力経路・納品/出荷帳票・自動補充の4系統に限る** |
| 10.2以降 | LCV、権限判定、外部連携、その他。実施条件・契約・データ所有者の確定が先行する |

### 1.4 Release Gateの原則

- 10.0必須シナリオが画面からサーバー、DB、帳票まで完遂する。
- 通常更新値とRebuild値が一致する。
- 取消・再実行・楽観排他・異常終了後の復旧手順が確認されている。
- 移行データと新規テストデータの両方で金額・数量・税・残高・**原価**を検算できる。
- UATの実施者、証跡、合格基準が決まっている。

### 6.3 Release判定

1. UAT-01〜08、UAT-10、UAT-11がすべて合格し、重大/高課題が0件（UAT-09は10.2以降）。
2. 請求・支払・在庫・原価は、標準/軽減/非課税を含む画面値、DB値、帳票値、手計算値が一致。
3. 通常更新とRebuild、初回実行と再実行、取消前後、自社締日境界が一致。
4. 移行リハーサルを同一手順で2回成功し、件数・金額差異・税額差異が説明可能。
5. **原価4項目の月次原価が手計算と一致し、再実行で同値（冪等）。負在庫・原価0円の中断が仕様どおり。**
6. **上代一括変更Phase2は、既存形式の `TranJodai` が現行と同一の `DerivedJodai` を生成する回帰に合格。確定後のScope解決と競合検出が期待どおり。**
7. **POSサーバI/Fの契約（`PosContracts.cs`）が固定され、税計算とレジ単位精算の集計値が検算と一致。** POSアプリ側テストの結果受領は10.0判定の前提としない（D-11により別枠責務）。
8. Preview/Hiddenを含むメニュー一覧と10.1以降の代替運用を利用者へ提示。
