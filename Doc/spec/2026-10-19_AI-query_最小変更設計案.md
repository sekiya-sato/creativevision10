## 2. 基本設計からの変更点

| 基本設計 | 本設計（最小変更） | 理由 |

## 3. 全体構成

```text
[CvWpfclient] AiQueryView / AiQueryViewModel （会話・QuerySpec・SQL・結果は画面が保持）
   │ ① 対話          Msg091_AiQueryChat     (新) ──▶ [CvServer] AiQuery処理 ──▶ ローカルLLM (OpenAI互換HTTP)
   │                                                     ├ スキーマ説明（実DB PRAGMA + [Comment]）
   │                                                     ├ 業務辞書（AiQueryDictionary.md）
   │                                                     └ SQL検査（AiQuerySqlGuard + EXPLAIN）
   │ ② SQL検査       Msg092_AiQueryValidate (新, AIなし)
   │ ③ 実行          Msg101_Op_Query + QueryListSqlParam(typeof(object))  (既存)
   │ ④ 共有保存      Msg101 QueryListParam / Msg201 Insert・Update・Delete (既存) ──▶ SysAiQuery (新テーブル)
   └ ⑤ CSV・SQLファイル・個人保存はクライアント内で完結（%LocalAppData%\CreativeVision10\AiQuery）
```

- LLMはDB接続を持たない。スキーマ取得・検査はサーバが行い、結果行はLLMへ送らない。
- 保存SQLの再実行は ②→③ だけで、AI（①）を呼ばない。AI停止・未設定でも動く。

## 4. 利用フローと状態

基本設計 §4・§6.2 のフローを次の呼び出しへ対応付ける。

| 画面状態 | 操作 | 呼び出し | 次状態 |
|---|---|---|---|
| 入力待ち | 要求を送信 | ① `Mode=Chat` | 質問中 / 条件確認待ち |
| 質問中 | 回答を送信 | ① `Mode=Chat` | 質問中 / 条件確認待ち |
| 条件確認待ち | 「この内容でSQL作成」 | ① `Mode=Generate` | SQL検査済み / 失敗（確定条件は保持） |
| SQL検査済み | 「実行」 | ③（手修正SQLなら先に②） | 結果あり（件数・プレビュー） |
| 結果あり | CSV保存・SQL保存・共有保存・個人保存 | ④ または クライアント内 | 結果あり |
| 任意 | 条件変更の発言 | ① `Mode=Chat` | 質問中 / 条件確認待ち。SQL・結果は「旧版」表示にし、保存・CSVを無効化 |

- クライアントは送信ごとに `Revision` を1増やす。応答の `ConversationId`/`Revision` が現行と一致しなければ破棄する。
- 実行結果は取得時の `Revision` と取得時刻を持つ。条件変更後は旧結果からCSV・保存できない。
- 送信中は送信・実行ボタンを無効化し、「取消」で `CancellationToken` を取消す（gRPC取消→サーバの `HttpClient` 取消）。
- AIの応答は数十秒〜数分かかるため、応答待ちの間は会話欄に待機表示を出す（2026-10-19 利用者要望）: 会話欄の上端に不確定の進行帯、下端に回転表示と「AIが考えています…（SQL作成時は「AIがSQLを作成しています…」） 経過 m:ss （［取消］で中止できます）」を重ねる。経過時間は1秒ごとに更新し、応答・失敗・取消・画面終了で消す。重ね表示は会話のスクロールや選択を妨げない。

## 5. モデル

### 5.1 DB: `SysAiQuery`（新規、共有保存）

`CvBase/BaseDb0Config.cs` に追加し、`DefineDataTable.TableTypes` のシステムテーブル群へ登録する。`Sys` 接頭辞にすることで、`GetTableCounts` の一覧・AIのスキーマ説明（§6.3）・SQL検査の参照可能表（§7）から自動的に外れる。

| 列 | 型 | 保存6項目との対応 | 内容 |
|---|---|---|---|
| Id / Vdc / Vdu | long | （共通列） | `BaseDbClass`。Vdu は既存の更新競合検査に使う |
| SaveDate | string(8) | 日付 | 保存日 `yyyyMMdd`。**サーバが打刻** |
| Title | string(100) | タイトル | 会話から自動生成。画面で修正可 |
| SqlText | string | SQL文 | 検査済みSQLite照会SQL |
| SqlParams | string(JSON) | SQLパラメータ | `List<AiQueryParam>` を `Common.SerializeObject` した文字列（§5.3） |
| Id_Login | long | ユーザId | 保存操作者の `SysLogin.Id`。**サーバが打刻**。権限制御には使わない |
| Description | string(2000) | SQL内容の説明 | 会話から推測・確定した集計対象・項目・条件の日本語説明 |

- 索引: `nk1`=Title、`nk2`=Id_Login（一覧の絞込用、非一意）。
- 移行: 既存DBには `DefineDataTable.InitializeAsync` の `CreateTable` で新規作成される。既存表の変更・データ移行はないため `UpdateDb` の移行行は追加しない。
- `SqlText` の列長は `ColumnSizeDml` 指定とPostgreSQL/MariaDBのDDL型（TEXT化の閾値）を `DdlSnapshotTests` で確認して決める。
- `SqlParams` は `[SerializedColumn]` にせず文字列で持つ。読込時は `json_valid` 相当の防御として、デシリアライズ失敗をその行のエラー表示に留める。

### 5.3 パラメータDTO（`CvBase/AiQueryParameters.cs`、新規）

既存パラメータと同じく record を JSON で `CvMsg.DataMsg` に載せる。gRPC契約（protobuf）は増えない。

```text
AiQueryChatParam
  ConversationId : string        // 画面セッションで採番した GUID
  Revision       : int           // 送信ごとに +1
  BaseDate       : string        // 会話開始日 yyyyMMdd（「先月」等の基準）
  Mode           : EnumAiQueryMode  // Chat=0 / Generate=1
  Messages       : List<AiQueryMessage>   // {Role: User/Assistant, Text}。古い往復は画面で要約せず件数上限で切る(§6.5)
  Spec           : AiQuerySpec?  // 直前応答のQuerySpec
  KnownTables    : List<string>  // これまでに説明を取得した表
  BaseSql        : AiQuerySqlDraft?  // 保存SQLを会話で修正する時の出発点（任意）

AiQueryChatResult
  ConversationId, Revision       // 要求の値を返す
  Status         : EnumAiQueryStatus  // Asking / Confirming / Generated / Failed
  AssistantText  : string        // 質問 or 確認要約 or 失敗理由
  Spec           : AiQuerySpec?
  KnownTables    : List<string>
  Draft          : AiQuerySqlDraft?   // Generated（Failed時も最後の生成SQLを保持）
  Errors         : List<string>  // 検査エラー

AiQuerySpec（全項目 string / List<string>。LLMが更新し、画面は要約表示に使う）
  Target, Metrics, GroupBy, DateBasis, PeriodFrom, PeriodTo, Filters,
  TaxMode, ReturnMode, OutputColumns, OrderBy, Unresolved

AiQuerySqlDraft
  Sql : string, Parameters : List<AiQueryParam>, Columns : List<string>,
  Title : string, Description : string, Reason : string

AiQueryParam（SysAiQuery.SqlParams の要素。並び順＝@0,@1,…）
  Name : string, Label : string, Type : EnumAiQueryParamType (Text=0/Integer/Decimal/Date),
  Value : string, AskOnRun : bool

AiQueryValidateParam  { Sql, Parameters : List<AiQueryParam> }
AiQueryValidateResult { IsValid : bool, Errors : List<string>, Tables : List<string> }
```

- `Unresolved` が空でない間、サーバは `Mode=Generate` を `Failed`（「未確定事項あり」）で返す。
- 列挙の0値（`Text`/`Chat`）・`AskOnRun=false` はプロパティ初期値と一致させ、`DefaultValueHandling.Ignore` で省略されても往復で値が変わらないようにする（AGENTS §7.1）。
- 実行時は `Parameters` の `Value` を順に `string[]` へ詰めて既存 `QueryListSqlParam` に渡す。数値型パラメータはSQL側で `CAST(@n AS INTEGER|REAL)` を必須とし、検査で確認する（§7）。日付は `yyyyMMdd` 文字列のまま。

### 6.2 `Msg091_AiQueryChat` の処理

1. 設定 `AiQuery:Enabled=false`、または接続DBがSQLite以外なら `Failed`（「AI照会は未設定」「SQLiteのみ対応」）。
2. システムプロンプトを組み立てる: 役割・規則（実在しない表/列を使わない、列は `describe_table` で確認、未確定事項は質問、推測を確定扱いしない、更新系SQL禁止、応答は必ず終端ツールで返す）、`BaseDate`、業務辞書、`KnownTables` の列説明（前回までに取得した分を再取得して埋め込む）、現在の `Spec`。
3. LLMを `tools` と `tool_choice: "required"` で呼ぶ。応答は必ずツール呼出しになり、引数JSONで受け取る（本文テキストからの抽出はしない）。

| ツール | 種別 | Mode | 内容 |
|---|---|---|---|
| `list_tables` `{name_prefix?}` | 情報取得 | Chat/Generate | 実在表の名前と `[Comment]`（`Sys*` 除外、件数なし） |
| `describe_table` `{table}` | 情報取得 | Chat/Generate | 列・型・NOT NULL・主キー・`[Comment]`・JSON内項目（§6.3）。取得した表は `KnownTables` に追加 |
| `reply` `{action: ask\|confirm, message, spec, unresolved[]}` | 終端 | Chat | `ask`→`Asking`、`confirm`→`Confirming`（`message` は集計項目・単位・期間（具体日付）・条件・出力列・並び順の要約） |
| `submit_sql` `{sql, parameters[], columns[], title, description, reason}` | 終端 | Generate | §7 の検査を行う。エラーはツール結果としてLLMへ返し、最大 `MaxRepair`=2 回修正させる。成功で `Generated`、超過で `Failed`（最後のSQLとエラーを返す） |

4. 情報取得ツールの結果は `role: tool` メッセージで返して再度呼ぶ。1往復あたりの呼出しは最大 `MaxToolRounds`=8 回。超過・終端ツールの引数JSONが解析できない場合は `Failed`。
5. `Mode=Generate` は `Unresolved` が空のときだけ受け付け、終端ツールは `submit_sql` のみ渡す。
6. ログには ConversationId・Revision・モデル名・ツール呼出し回数・所要時間・結果種別を出す。プロンプト本文とSQLは既存の `LogDetailedRequest` と同じ詳細ログ扱いとする。

サーバは会話状態を保持しない（毎回クライアントが会話・Spec・KnownTablesを送る）。1往復内のツールのやり取りはクライアントへ返さず、`KnownTables` だけを返す。

Step 0 の確認（2026-10-19）: `ornith-1.5-9b`（LM Studio）は `tools`＋`tool_choice: "required"` で終端ツールの引数JSONを返した。`tools` と `response_format: json_schema` の同時指定は「failed to parse grammar」で拒否され、`json_object` も非対応のため、構造化応答はツール引数で受け取る方式に統一した。

### 6.3 スキーマ説明（`AiQuerySchemaCatalog`）

- **表一覧**: `sqlite_schema` の実在表のうち `Sys%`・`sqlite_%` を除いたもの。説明はクラスの `[Comment]`。件数は数えない。
- **列説明**（要求された表のみ）: `PRAGMA table_info(<表>)` の列名・型・NOT NULL・主キーに、対応プロパティの `[Comment]` を付ける。`[SerializedColumn]` の列は要素型（`List<Tran99Meisai>` なら `Tran99Meisai`）のプロパティ名・型・`[Comment]` を「JSON内項目」として付ける。`Jdetail`（`BaseDetailClass` 派生）は基底の項目のみ説明する。
- 表名は連結せず `pragma_table_info(@0)` にバインドする（McpSql と同じ）。実在しない表・`Sys*` 表はエラー文を返す。
- C#型と実DBの差（実DBにない列・クラスにない列）は実DBを正とし、説明なしで出す。

### 6.4 業務辞書（`AiQueryDictionary.md`）

初版は代表3〜5要求（§11）に必要な範囲だけ書く。必須の記載項目:

### 6.5 LLM接続（`IAiQueryLlm`）

使用するAI（2026-10-19 利用者指定）:

| 項目 | 値 |
|---|---|
| ベースURL | `http://192.168.9.131:1234/v1` |
| モデル | `ornith-1.5-9b` |

## 7. SQL検査（`AiQuerySqlGuard` ＋ `Msg092`）

利用者別の認可ではなく、「生成・手修正したSQLが単一の照会で、実在の表・列に解決できる」ことの確認である。`Msg091` の生成後と `Msg092` で同じ処理を使う。

1. 空でない、長さ上限（4,000文字＝`SysAiQuery.SqlText` の列長）以内。
2. 字句検査（McpSql `SqlGuard` を流用）:
   - `SqlGuard.TryValidateReadOnly`: コメント・文字列・引用識別子を正しく読み飛ばしたうえで、`;` は末尾のみ（**複数文の拒否**。Microsoft.Data.Sqlite は1コマンドで複数文を実行するため、`EXPLAIN` 前に必ず行う）、`WITH` の後続文が `SELECT`/`VALUES` であることを確認する。
   - 追加条件（AiQuery側）: `SqlGuard.TryTokenize` の先頭トークンが `SELECT` または `WITH`（McpSql が許す `PRAGMA`・`VALUES`・`EXPLAIN` 前置は不可）。
   - 数値型パラメータ `@n` は `CAST(@n AS …)` で使われている。`@n` の最大番号＋1 と `Parameters` 件数が一致する。
3. `EXPLAIN <sql>` を `RawExecCmd`（パラメータをバインド）で実行し、`RawLastError` があれば構文・名前解決エラーとして返す。`EXPLAIN` は行を取得しない。
4. オペコード検査: `OpenWrite` があれば拒否（`WITH … DELETE` 等の更新を検出）。`OpenRead` の `p2`（rootpage）を `sqlite_schema.rootpage` と照合して参照表を求め、`Sys%` 表・`sqlite_schema` の参照を拒否する。参照表は `Tables` として返す。
5. 実行は検査後にクライアントが既存 `Msg101` で行う。`Msg101` 自体は従来どおり任意SQLを受け付ける（現行の認証済み利用者の範囲であり、本機能で新たな権限境界は設けない）。画面ではSQLを手修正したら再検査が通るまで実行・保存を無効にする。
