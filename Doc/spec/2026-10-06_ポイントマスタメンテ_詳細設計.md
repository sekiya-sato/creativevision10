# ポイントマスタメンテ 詳細設計

- 設計日: 2026-10-06
- 対象定義: schema commit `d94720d3` の `MasterPointBase` / `MasterPointRank` / `MasterPointBonus`
- 状態: 3画面とサーバ保存保護を実装・検証済み。MenuData.csの大メニュー「顧客管理」→「ポイント」へ組込み。

## 1. 対象と不変条件

今回の対象はポイント条件3マスタの一覧・追加・修正・削除。ポイント計算、売上連携、残高更新、既存残高移行、会員ランク文字列の移行は含めない。
`TranPointEvent` は追記台帳であり通常CRUD画面を作らない。台帳照会は将来機能とし、`SummaryPoint` を含めて汎用書込みを禁止する。
ポイント条件は使用済み版を変更せず新版を追加する。使用済みベース・ボーナスでは有効フラグだけ変更可能とし、再有効化時も期間重複を確認する。

## 3. 共通操作と状態

- ViewModelは `BaseMenteViewModel<T>`。`InitCommand` で一覧取得し、`BaseWindow` の自動初期化を利用する。
- 一覧取得(F5)、修正(F2)、削除(F3)、追加(F4)、閉じる(Esc)を既存方式で配置する。
- 一覧選択時に基底の `Current` → 複製した `CurrentEdit` へ展開する。入力中の値を直接一覧へ反映しない。
- 追加は入力フォームの条件を新しい行として保存する。既存行を選択して追加する場合もId/Vdc/Vduを新規値へ戻す。新版はコードを維持し版を明示的に変更する。
- 修正・削除はId>0の既存行のみ。Vduによる楽観排他は基底の応答処理に従う。
- 入力検証失敗、サーバ側の参照・期間・使用済み保護エラーは編集値を保持し、理由を表示する。数値Bindingは変換エラーを記録し、保存前に画面のValidationエラーを確認して古いモデル値の保存を防止する。競合は既存の再取得案内に従う。
- `ConfirmAction` で追加・修正の入力検証、`CreateInsertParam` / `CreateUpdateParam` で文字列正規化、`CanUpdate` / `CanDelete` で対象行確認を行う。
- `AfterList` 等のフックは必要な表示補助に限定し、基底クラスの変更を避ける。

## 4. ベース画面

一覧順は `Code, Version DESC, Id`。一覧列はId、制度コード、名称、版、開始日、終了日、有効、付与単価、P付与数、S付与数。

| 項目 | 入力と検証 |
|---|---|
| Code / Name | 必須、最大20 / 80文字、前後空白除去 |
| Version | 整数、1以上 |
| DayFrom / DayTo | DatePicker、実在日、yyyyMMdd、開始<=終了 |
| EnIsEnabled | EnumYesNo |
| PointUnitPrice | 整数、正数 |
| PointAmountProper / PointAmountSale | 整数、0以上 |
| EnTaxBasis | EnumPointTaxBasis |
| EnCalcUnit | EnumPointCalcUnit |
| EnRounding | 既存EnumRounding |
| EnDeductPointUse | 既存EnumYesNo |

右フォームは「制度・適用期間」と「付与条件」にまとめる。有効フラグ初期値0はモデルに従い、未確認条件を自動有効化しない。

## 5. ランク画面

一覧順は `Id_PointBase, Kubun, Id`。一覧列はId、親ベースId、ランクコード、名称、付与単価、P付与数、S付与数。

| 項目 | 入力と検証 |
|---|---|
| Id_PointBase | ベース選択、保存時>0、親レコード存在 |
| Kubun | 整数のランクコード。業務マスタの値でありenumにしない |
| Name | 必須、最大40文字、前後空白除去 |
| PointUnitPrice | 整数、正数 |
| PointAmountProper / PointAmountSale | 整数、0以上 |

ベース選択は汎用照会で取得した `BaseOptions` をComboBoxへ展開し、制度コード・名称・版を表示する。汎用選択画面には版列がないため、版を判別できる画面内選択を使用する。親は有効期間やランク条件を編集する単位であり、名称だけで照合しない。
税基準、計算単位、丸め、利用ポイント控除は親の条件を継承し、ランク画面に重複設定列を作らない。親リストは一覧取得時に更新する。
旧ランクの `Id_PointBase=0` は一覧に「移行設定待ち」と表示可能とし、新規・修正では親選択を必須にする。自動的に任意の親へ紐づけない。

## 7. enum・日付表示

`CvBase/Share/PointEnums.cs` の新規enumと既存 `EnumYesNo` / `EnumRounding` を使う。ComboBoxは `Enum.GetValues<T>()` をItemsSourceとし、モデルの `EnXxx` プロパティへTwoWayで結合する。
表示名はApp.xamlの `EnumCommentDisplayConverter`、日付は `DateYmd8Converter` を使う。保存列は既存規約どおりint / yyyyMMdd文字列のまま維持し、不正enum値は保存前に拒否する。

## 8. サーバ保存保護

クライアントの入力検証は操作補助であり、保存の正当性はサーバで確認する。単件・一括・Id指定削除を含む汎用経路へ同じ保護を適用し、3マスタのPartialUpdateを禁止する。

- 共通: 必須、文字長、日付、数値、enum、親存在、コード・版や親・ランクの一意性を検査。
- 期間: 有効な同一制度コードのベース版と、有効な同一ボーナスコードの版で期間重複を拒否。ボーナス期間は親期間内。無効→有効でも同じ検査を行う。
- 使用済み: `TranPointEvent.Id_PointBase / Id_PointRank / Id_PointBonus` の明示参照で判定する。使用済みベース・ボーナスはIsEnabledだけ変更可、使用済みランクは変更不可。
- 条件集合: 親ベースが使用済みならランク・ボーナス追加、条件変更、削除を拒否する。使用済み条件集合へ後から条件を挿入しない。有効切替の例外は前項に従う。
- 削除: 使用済みレコードを拒否。子ランク・子ボーナスのある親、指定ランクのボーナスから参照されるランクを拒否し、孤立参照を作らない。
- 同時更新: DB書込みと同じトランザクション内で重複・参照・使用済みを検査し、Vduの楽観排他を維持する。既存方言変換経路を使う。
- 台帳・残高: `TranPointEvent` と `SummaryPoint` の汎用追加・修正・削除・部分更新を禁止。専用のポイント取引保存は将来実装する。

新しい保存契約や画面独自SQL更新を導入せず、既存のCvMsg汎用照会・保存境界を維持する。DB接続の種類によるSQL分岐を作らない。
