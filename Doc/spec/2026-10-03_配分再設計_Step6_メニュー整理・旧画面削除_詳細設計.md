### 5.2 権限の機能ID

機能IDは View の型名から作られる（`MenuData.DeriveFunctionId`）。画面を消すと、その機能IDの権限明細は誰にも使われなくなり、後継画面は既定ポリシー（`PermissionDefaultMode`）で判定される。

| 旧機能ID | 後継の機能ID |
|---|---|
| `07Haibun.ShopHaibunInput` | `07Haibun.PurchaseReceiptAllocationInput`（初回＝仕入配分の後継） |
| `07Haibun.ShippingConfirmShohin` | `07Haibun.HaibunCommit` |
| `07Haibun.ShippingConfirmTokui` | `07Haibun.HaibunCommit` |

- 初期データ（`BaseDb0Login.DefaultDetailData`）の `07Haibun.ShopHaibunInput` を後継の機能IDに書き換える（新規DB向け）。
- 既存DB向けに migration（UpdateDb `26_10_03_03`）で付け替える。`SysPermissionProfileDetail` には一意キー（プロファイル×機能ID×操作種別）があるので、次の順で行う。
  1. 後継IDの行がまだ無いプロファイル×操作種別だけ、旧IDの行を後継IDとして INSERT … SELECT する。配分確定(商品)/(得意先) が同じプロファイルで食い違っていた場合は、**許可（IsAllowed=1）を優先**する（統合後は 1 画面で両方の並び順を使えるため）。
  2. 旧IDの行を削除する。
- SQL は SQLite 方言で書く（`INSERT … SELECT … WHERE NOT EXISTS`、`MAX(IsAllowed)` で許可を優先）。

## 6. 区分名の統一と出荷帳票からの取置の除外（S5・S6）

### 6.1 区分名

CvBase に区分名の唯一の出典を置く（例: `HaibunKubunNames`。`EnumHaibun` と同じファイル）。

| 区分 | 名前 | 新規作成 | 帳票の絞込に出すか |
|---|---|---|---|
| 0 | 仕入配分 | ○ | ○ |
| 1 | 在庫配分 | ○ | ○ |
| 2 | 受注配分 | ○ | ○ |
| 6 | 取置配分 | ○ | 出荷帳票には出さない（6.2） |
| 3 / 4 / 5 / 7 | 得意先別配分(廃止) / 店舗出荷依頼(廃止) / 在庫品配分(廃止) / 移動指示(廃止) | × | × |

- 帳票の SQL の区分名（`CASE h.Kubun WHEN …`）は、この表から組み立てる関数を CvBase に置き、2 本の ViewModel の複製をやめる。廃止区分の名前は、既存データが残っていた場合の表示のためだけに持つ。
- 納入一覧表の区分の選択肢を、英語の enum 名から上の日本語名に替える。

### 6.2 出荷帳票から取置を除く

- 出荷指示明細書・配分出荷リスト・納入一覧表は「倉庫から出荷・移動する配分」の帳票なので、区分「すべて」でも取置（区分6）を含めない（`h.Kubun <> 6`）。
- 取置は店舗の在庫を押さえるだけでピッキングが無く、印刷されると倉庫が誤って出荷する恐れがあるため。

## 9. 承認時の判断と実装時の補足

- 判断 1〜6 は推奨どおり（2026-10-03）。以下は承認依頼時の記載。
- 実装時の補足:
  - 区分名の出典は `CvBase/BaseDbHaibun.cs` の `HaibunKubunNames`（`All` / `ShippingKubun` / `Name` / `CaseSql`）。
  - 出荷帳票 3 本は区分の絞込に関わらず `h.Kubun <> 6` を付けた。廃止区分の既存データは「すべて」で出る（名前は「(廃止)」付き）。
  - migration 26_10_03_03 は、PostgreSQL で `IsAllowed` が boolean になるため、数値と比べず列同士の比較（`o2.IsAllowed > o.IsAllowed`）で許可を優先した。同じ値なら機能IDの小さい方（配分確定(商品)）を採る。
  - `ShippingConfirmShohin*` は `git mv` で `HaibunCommit*` へ改名し、`ShippingConfirmTokui*` を削除した。

### 承認依頼時の記載

1. **配分確定の統合**: 配分確定(商品)/(得意先) を 1 画面「配分確定」（`HaibunCommit*`）にまとめ、並び順を切り替える方式でよいか（D4 のとおり）。
   - 代わりの案: 2 画面のまま残し、名前だけ揃える。
2. **権限の付け替え**: 削除・統合した画面の権限明細を、migration で後継画面の機能IDへ移す方式でよいか。配分確定の 2 画面で許可が食い違うときは許可を優先する。
   - 代わりの案: 付け替えず、後継画面は既定ポリシーに任せる（古い明細は残る）。
3. **出荷帳票から取置を除く**: 出荷指示明細書・配分出荷リスト・納入一覧表では、区分「すべて」でも取置を印刷しない形でよいか。
4. **区分名**: 0 仕入配分 / 1 在庫配分 / 2 受注配分 / 6 取置配分、廃止区分は「(廃止)」付きの名前で表示だけ残す形でよいか（帳票の絞込には廃止区分を出さない）。
5. **発注メニューのショートカット**: 「発注配分入力」を残し、表示名を「仕入配分入力(伝票別)」に揃えてよいか。
6. **店舗配分入力の削除**: `ShopHaibunInput*` と検索条件ダイアログを削除してよいか（Step 4 でメニューから外し済み。機能は仕入配分入力(商品別)・在庫配分入力が引き継いでいる）。
