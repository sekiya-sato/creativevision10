## 1. 公開するファイル

`Releases/0.9.0/` の次の4点だけをReleaseへ添付する。

| ファイル | 対象 |
| --- | --- |
| `CvServer-0.9.0-win-x64.zip` | gRPCサーバ Windows x64 |
| `CvServer-0.9.0-linux-x64.zip` | gRPCサーバ Linux x64（glibc系） |
| `CreativeVision10-0.9.0-win-x64-Portable.zip` | WPFクライアント Windows x64 |
| `SHA256SUMS.txt` | 上記3ファイルのSHA-256 |

[リリースノート下書き](リリースノート_0.9.0.md) はWeb画面の本文欄へ貼り付ける。作成バッチは同じ内容を `Releases/0.9.0/release-notes.md` にもコピーする。このMarkdownは添付対象ではない。

クライアントはPortable ZIPを展開して使用し、自動更新は行わない。Setup EXE、更新用nupkg・索引JSONは公開しない。Velopackが内部生成するnupkg・索引は `CvWpfclient/bin/velopack-package/<実行ID>/` に保持する。

各publishはRelease / 自己完結型（.NET 10ランタイム同梱）。ARM64、Alpine/muslは対象外。`AssemblyVersion` は変更せず、`FileVersion` / `InformationalVersion` と配布設定の版数を指定版数へ合わせる。

## 2. 作成環境

Windows開発PCで、.NET 10 SDK、既存プロジェクトをビルドできるVisual Studio環境、Windows PowerShell 5.1以上、Git、Velopack CLI **1.2.161** を準備する。Web画面で公開するためGitHub CLIは不要。印刷無効で発行するため `printstream.jar` は不要。

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
Set-Location C:\gitroot\new2022\cv10
dotnet --version
# 未導入の場合
dotnet tool install -g vpk --version 1.2.161
# 導入済みの版数を変更する場合
# dotnet tool update -g vpk --version 1.2.161
vpk -h
git status --short
git remote -v
```

## 3. 作成・再作成

### 3.1 一括作成

```powershell
& C:\gitroot\UT\vscmd.bat publish-release.bat 0.9.0
if ($LASTEXITCODE -ne 0) { throw 'Release creation failed' }
```

バッチは次の順で処理する。GitHubへの書き込み・Git操作は行わない。

1. `publish-server.bat 0.9.0` → Windows/Linuxサーバを発行する。
2. `publish-velopack.bat 0.9.0 --local` → サーバZIPの `appsettings.json` を読み、両OSの版数・待受URLが一致することを確認する。クライアントのpublish出力設定へそのURLを反映し、Portable ZIPを作成する。
3. `prepare-release-assets.ps1 -Version 0.9.0` → 3つのZIPを検査して `SHA256SUMS.txt` とリリースノート下書きのコピーを作る。

配布設定ではサーバの `Kestrel.Endpoints.Http.Url` とクライアントの `ConnectionStrings.Url` がともに **`http://localhost:5002`**。ソースの `appsettings.json` を変更せず、パッケージ化前の出力だけを変更する。サーバ設定が不一致・不正・未作成の場合、クライアント作成は停止する。

サーバは `PrintEnable=false` で発行する。`CvPrints/CvPrints.csproj` は発行中だけfalseへ変更し、成功・失敗とも `finally` で元のバイト列へ復元する。publishにも `-p:PrintEnable=false` を指定する。プロセス強制終了・OS停止では復元処理が動かないため、次の作業前に `git diff -- CvPrints/CvPrints.csproj` を確認する。

サーバ出力は公開用 `appsettings.json` 雛形に置き換える。JWT鍵は空、DBは相対パス `server.db`。クライアントは `appsettings.*.json` を除外し、従来の更新フィード・開発用ログイン設定を持ち込まない。両ZIPへ `LICENSE` を同梱する。

明示版数のクライアントでは `--noInst --delta None` を使用し、GitHub添付先へPortable ZIPだけをコピーする。引数なしの既存クライアントバッチは従来の自動増分・サーバ版数同期・別サーバ転送を継続するため、今回の公開では使わない。

### 3.2 同じ版数を作り直す場合

既存ZIPは上書きしない。失敗成果物を含む旧フォルダを保存してから、一括作成する。

```powershell
# 作業ディレクトリをcv10ルートへ固定し、移動元・先がReleases配下か確認する。
$releaseRoot = [IO.Path]::GetFullPath((Join-Path $PWD 'Releases'))
$source = [IO.Path]::GetFullPath((Join-Path $releaseRoot '0.9.0'))
$destination = [IO.Path]::GetFullPath((Join-Path $releaseRoot ('archive\0.9.0-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))))
if ($releaseRoot -ne 'C:\gitroot\new2022\cv10\Releases' -or
    $source -ne 'C:\gitroot\new2022\cv10\Releases\0.9.0' -or
    -not $destination.StartsWith($releaseRoot + '\', [StringComparison]::OrdinalIgnoreCase)) {
    throw 'Unexpected release archive path'
}
New-Item -ItemType Directory -Force -Path (Split-Path $destination) | Out-Null
Move-Item -LiteralPath $source -Destination $destination
& C:\gitroot\UT\vscmd.bat publish-release.bat 0.9.0
if ($LASTEXITCODE -ne 0) { throw 'Release creation failed' }
```

この作業は公開前の再作成用。公開済み版の添付を別内容で差し替えず、公開後の変更は次の版数とする。

## 4. 公開前の確認

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-release-assets.ps1 -Version 0.9.0
if ($LASTEXITCODE -ne 0) { throw 'Release verification failed' }
Get-ChildItem Releases\0.9.0 -File
git diff --check
git diff -- CvPrints/CvPrints.csproj CvServer/appsettings.json CvWpfclient/appsettings.json
```

検査スクリプトは3つのZIP内の版数・接続先一致、設定JSONが1個であること、空以外の認証情報らしい設定値がないこと、印刷依存・DB・証明書・秘密鍵ファイルがないこと、LICENSE同梱を確認する。独自の機密ファイル名・埋め込み値の目視点検も行う。

Portable ZIPの `current/appsettings.json` は `Application.Version=0.9.0`、`ConnectionStrings.Url=http://localhost:5002`。ただし、通常起動時は別のクライアント設定ストアが優先されるため、導入時は次節の設定も必須。

Windows/Linuxサーバは専用の新規DBまたは開発DBの複製で起動確認する。サーバ起動時にはテーブル作成・migration・定期処理登録があるため共有開発DBを使わない。PortableクライアントはクリーンなWindows端末で起動・接続先・ログイン・代表的gRPC操作を確認する。Linuxのpublish成功を実機確認の代替にしない。

## 5. 配布先での導入

### サーバ

ZIPを専用フォルダへ展開し、展開先を作業ディレクトリにする。配布JWT鍵は空のため、配布先で独自鍵を設定する。例（Windows PowerShell、鍵を表示しない）:

```powershell
Set-Location C:\apps\cv10-server
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
$env:WebAuthJwt__SecretKey = [Convert]::ToBase64String($bytes)
$env:DOTNET_ENVIRONMENT = 'Production'
$env:ASPNETCORE_ENVIRONMENT = 'Production'
.\CvServer.exe
```

この環境変数は起動セッション限り。継続運用では同じ独自鍵を保護された環境設定等で保持する。Linuxも配布先でJWT鍵を設定し、`chmod +x CvServer` 後、Production環境で `./CvServer` を起動する。Windowsで作ったZIPは実行権限を保持しない。LinuxのOSネイティブ依存は別途準備する。

新規DBの初期管理者ID・パスワードは、どちらもDB作成日の `yyyyMMdd`（例: 2026-10-08作成なら `20261008`）。初期ログインの有効期限は作成日から1か月。ログイン後に運用用の利用者設定へ変更する。SQLiteは既定で `server.db`。設定 `ConnectionStrings.sqlite` は接続文字列ではなくファイル名なので、`Data Source=server.db` と書かない。既存DBを切り替える前にバックアップする。印刷機能は無効で、設定変更だけでは有効にならない。常駐化・Windowsサービス・systemd登録は配布先で別途設定する。

### クライアント

Portable ZIPを全体ごと書き込み可能なフォルダへ展開し、直下の `CreativeVision10.exe` を起動する。`current/` 以下の構成を保持する。WebView2利用機能にはWebView2 Runtimeが必要。

**通常起動では `%LOCALAPPDATA%/CreativeVision10/clientsettings.json` の接続先が同梱appsettingsより優先される。** 初回未作成時も既存 `ClientSettingsDocument` の初期値 `https://localhost:5012` が適用される。環境設定（F10）で接続先をサーバに合わせて保存し、再起動する。事前にファイルを作る場合の最小内容:

```json
{
  "ConnectionStrings": {
    "Url": "http://localhost:5002"
  }
}
```

既存 `clientsettings.json` は接続先だけを変更し、他設定や認証情報を上書きしない。この運用設定ファイルを公開ZIPへ追加しない。

別端末では `localhost` を実際のサーバ名へ置き換える。サーバ側のHTTP/2対応HTTPS・証明書・ネットワーク設定を構成し、そのHTTP/HTTPSとポートをクライアントへ合わせる。

## 6. Web画面で公開

1. 公開対象ソースを通常の手順でレビュー・commit・pushし、タグ対象コミットを確定する。本作業はcommit・pushを行っていない。作業ツリーから作成した今回の成果物と確定ソースに差があれば、確定後に作り直す。
2. [Releases](https://github.com/sekiya-sato/creativevision10/releases) → **Draft a new release** を開く。
3. タグ `v0.9.0` を選択する。未作成の場合は同画面でタグを作成し、Targetを公開対象コミットへ指定する。既存タグが別コミットの場合は付け替えず確認する。
4. タイトルを `CreativeVision10 0.9.0` とし、[下書き](リリースノート_0.9.0.md) の内容を本文へ貼り付ける。実機確認を追加した場合は「確認状況」を更新する。
5. 第1節の4ファイルだけを添付する。`release-notes.md`、内部nupkg、索引JSON、旧成果物フォルダは添付しない。
6. 下書きでタグ・対象コミット・本文・ファイル名を確認する。今回は通常Releaseとして公開する。試用版へ変更する場合は本文と **Set as a pre-release** を揃える。
7. **Publish release** を実行する。
8. [v0.9.0](https://github.com/sekiya-sato/creativevision10/releases/tag/v0.9.0) を未ログインのブラウザで開き、3つのZIPとSHA256SUMSをダウンロードし、SHA-256の一致を確認する。

## 7. 次回更新

新しい版数（例 `0.9.1`）で同じバッチを使い、対応する `Doc/spec/リリースノート_0.9.1.md` も作成する。クライアントは新しいPortable ZIPを別フォルダへ展開し、設定を確認して切り替える。自動更新フィードは今回の公開方針では設定しない。
