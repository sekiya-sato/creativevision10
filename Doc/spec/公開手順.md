GitHub操作と実環境への配置は人間が行う。`publish-release.bat`・`publish-server.bat`・`publish-server.ps1`・`prepare-release-assets.ps1` の省略時既定値は0.9.0のままなので、**必ず版数を明示する**。以下の `0.9.2` は例。

0.9.1以後のソースには、POS統合、MariaDB／PostgreSQL対応（DB切替・方言変換・AI照会の3DB対応）、印刷無効時の一覧PDF出力（下記）、NuGet更新（MailKit 5 等）が含まれる。次回版はこれらを含めて作成・検証する。CvWpfposは配布物に含めない。

## 1. 公開するファイル

`Releases/<版>/` の次の4点だけをReleaseへ添付する。

| ファイル | 対象 |
| --- | --- |
| `CvServer-<版>-win-x64.zip` | gRPCサーバ Windows x64 |
| `CvServer-<版>-linux-x64.zip` | gRPCサーバ Linux x64（glibc系） |
| `CreativeVision10-<版>-win-x64-Portable.zip` | WPFクライアント Windows x64 |
| `SHA256SUMS.txt` | 上記3ファイルのSHA-256 |

リリースノートはWeb画面の本文欄へ貼り付ける。作成バッチは `Doc/spec/リリースノート_<版>.md` を `Releases/<版>/release-notes.md` にコピーするが、添付対象ではない。

クライアントはPortable ZIPを展開して使い、自動更新は行わない。Setup EXE、更新用nupkg・索引JSONは公開しない（Velopack内部生成物は `CvWpfclient/bin/velopack-package/<実行ID>/` に残る）。

各publishはRelease / 自己完結型（.NET 10ランタイム同梱）の **単一実行ファイル**（`PublishSingleFile=true`・`IncludeNativeLibrariesForSelfExtract=true`）。`appsettings.json`・AI業務辞書・LICENSE などは外置き。起動時にネイティブライブラリを展開するため、実行ユーザーが展開先へ書き込めることが必要。`PublishTrimmed=false`、`DebugType=None`・`DebugSymbols=false`。ARM64、Alpine/muslは対象外。`AssemblyVersion` は変えず、`FileVersion` / `InformationalVersion` と配布設定の版数を指定版数へ合わせる。

## 2. 作成環境

Windows開発PCで、.NET 10 SDK、既存プロジェクトをビルドできるVisual Studio環境、Windows PowerShell 5.1以上、Git、Velopack CLI **1.2.161** を準備する。GitHub CLIは不要（Web画面で公開）。印刷無効で発行するため `printstream.jar` は不要。

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new()
Set-Location C:\gitroot\new2022\cv10
dotnet --version
dotnet tool install -g vpk --version 1.2.161   # 導入済みで版数が違う場合は update
vpk -h
git status --short
```

## 3. 作成・再作成

### 3.1 一括作成

```powershell
& C:\gitroot\UT\vscmd.bat publish-release.bat 0.9.2
if ($LASTEXITCODE -ne 0) { throw 'Release creation failed' }
```

バッチの処理（GitHubへの書き込み・Git操作は行わない）:

1. `publish-server.bat <版>` → Windows/Linuxサーバを発行する。
2. `publish-velopack.bat <版> --local` → サーバZIPの `appsettings.json` を読み、両OSの版数・待受URLの一致を確認し、そのURLをクライアントのpublish出力設定へ反映してPortable ZIPを作成する。
3. `prepare-release-assets.ps1 -Version <版>` → 3つのZIPを検査し、`SHA256SUMS.txt` とリリースノートのコピーを作る。

- 配布設定ではサーバの `Kestrel.Endpoints.Http.Url` とクライアントの `ConnectionStrings.Url` がともに **`http://localhost:5002`**。ソースの `appsettings.json` は変えず、パッケージ化前の出力だけを変更する。サーバ設定が不一致・不正・未作成ならクライアント作成は停止する。
- **印刷は `-p:PrintEnable=false` で発行し、`printstream.jar`・IKVM依存を含めない。** `CvPrints/CvPrints.csproj` は発行中だけfalseへ変更し、成功・失敗とも `finally` で元のバイト列へ復元する。強制終了時は復元されないため、次の作業前に `git diff -- CvPrints/CvPrints.csproj` を確認する。
- **0.9.1以後の変更**（98fdc1aa）: `PrintEnable=false` のサーバは印刷要求に失敗を返さず、`data.txt` を確認用の一覧PDF（A4横、PDFsharp、IPAゴシック埋込み）にする。このためサーバに PDFsharp とフォントが同梱され、出力に `IPA_Font_License_Agreement_v1.0.txt` が加わる見込み。検査スクリプトの除外条件には該当しないが、実際のpublish・ZIP内容は未確認。
- サーバ出力は公開用 `appsettings.json` 雛形に置き換える（JWT鍵は空、DBは相対パス `server.db`）。クライアントは `appsettings.*.json` を除外し、更新フィード・開発用ログイン設定を持ち込まない。両ZIPへ `LICENSE` を同梱する。
- 明示版数のクライアントは `--noInst --delta None` でPortable ZIPだけを出力する。引数なしの `publish-velopack.bat` は従来の自動増分・サーバ版数同期・別サーバ転送の経路なので、公開には使わない。

### 3.2 単一実行ファイル生成の指定

一括バッチはサーバ2種と公開用クライアントへ次を渡す（引数なしの従来クライアント発行経路は対象外）。

```text
--self-contained true
-p:PublishSingleFile=true
-p:IncludeNativeLibrariesForSelfExtract=true
-p:PublishTrimmed=false
-p:DebugType=None
-p:DebugSymbols=false
-p:PrintEnable=false
```

本体はサーバWindowsが `CvServer.exe`、Linuxが `CvServer`、クライアントが `current/CreativeVision10.exe`（Velopack Portableの起動ランチャーと `Update.exe` は別途同梱）。ZIP内に本体DLL・ランタイムDLL・PDBが分散していないこと、単一ファイル内部の収録一覧にも `printstream.jar`・IKVM・開発用設定がないことを確認する。外部設定だけを検査してバンドル内部の秘密情報検査を省略しない。

### 3.3 同じ版数を作り直す場合

既存ZIPは上書きしない。旧フォルダを `Releases/archive/` へ退避してから一括作成する。

```powershell
# 作業ディレクトリをcv10ルートへ固定し、移動元・先がReleases配下か確認する。
$ver = '0.9.2'
$releaseRoot = [IO.Path]::GetFullPath((Join-Path $PWD 'Releases'))
$source = [IO.Path]::GetFullPath((Join-Path $releaseRoot $ver))
$destination = [IO.Path]::GetFullPath((Join-Path $releaseRoot ('archive\' + $ver + '-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))))
if ($releaseRoot -ne 'C:\gitroot\new2022\cv10\Releases' -or
    $source -ne (Join-Path $releaseRoot $ver) -or
    -not $destination.StartsWith($releaseRoot + '\', [StringComparison]::OrdinalIgnoreCase)) {
    throw 'Unexpected release archive path'
}
New-Item -ItemType Directory -Force -Path (Split-Path $destination) | Out-Null
Move-Item -LiteralPath $source -Destination $destination
& C:\gitroot\UT\vscmd.bat publish-release.bat $ver
if ($LASTEXITCODE -ne 0) { throw 'Release creation failed' }
```

公開前の再作成用。公開済み版の添付を別内容で差し替えず、公開後の変更は次の版数とする。

## 4. 公開前の確認

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\prepare-release-assets.ps1 -Version 0.9.2
if ($LASTEXITCODE -ne 0) { throw 'Release verification failed' }
Get-ChildItem Releases\0.9.2 -File
git diff --check
git diff -- CvPrints/CvPrints.csproj CvServer/appsettings.json CvWpfclient/appsettings.json
```

検査スクリプトは、3つのZIP内の版数・接続先一致、設定JSONが1個であること、空以外の認証情報らしい設定値がないこと、印刷依存・DB・証明書・秘密鍵ファイルがないこと、LICENSE同梱を確認する。独自の機密ファイル名・埋め込み値は目視でも点検する。

Portable ZIPの `current/appsettings.json` は指定版数と `ConnectionStrings.Url=http://localhost:5002`。通常起動では別のクライアント設定ストアが優先されるため、導入時は第5節の設定も必須。

Windows/Linuxサーバは専用の新規DBまたは開発DBの複製で起動確認する（起動時にテーブル作成・migration・定期処理登録があるため共有開発DBは使わない）。PortableクライアントはクリーンなWindows端末で起動・接続先・ログイン・代表的gRPC操作を確認する。印刷無効時の一覧PDFが出ることも確認する。Linuxのpublish成功を実機確認の代替にしない。

## 5. 配布先での導入

### サーバ

ZIPを専用フォルダへ展開し、展開先を作業ディレクトリにする。配布JWT鍵は空のため、配布先で独自鍵を設定する。例（Windows PowerShell、鍵を表示しない）:

```powershell
Set-Location C:\apps\cv10-server
$bytes = New-Object byte[] 32
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
try { $rng.GetBytes($bytes) } finally { $rng.Dispose() }
$env:WebAuthJwt__SecretKey = [Convert]::ToBase64String($bytes)
$env:DOTNET_ENVIRONMENT = 'Production'
$env:ASPNETCORE_ENVIRONMENT = 'Production'
.\CvServer.exe
```

この環境変数は起動セッション限り。継続運用では同じ独自鍵を保護された環境設定等で保持する。Linuxも配布先でJWT鍵を設定し、`chmod +x CvServer` 後、Production環境で `./CvServer` を起動する（Windowsで作ったZIPは実行権限を保持しない。OSネイティブ依存は別途準備）。

新規DBの初期管理者ID・パスワードはどちらもDB作成日の `yyyyMMdd`（有効期限は作成日から1か月）。ログイン後に運用用の利用者設定へ変更する。SQLiteは既定で `server.db`。`ConnectionStrings.sqlite` は接続文字列ではなくファイル名なので `Data Source=server.db` と書かない。既存DBを切り替える前にバックアップする。印刷はPrintStreamを含まないため帳票形式では出力されず、確認用の一覧PDFになる（0.9.1は印刷不可）。常駐化・Windowsサービス・systemd登録は配布先で別途設定する。

DBは既定でSQLite。MariaDB／PostgreSQLで運用する場合は、サーバ設定（または環境変数）の `Database:Provider` を `MariaDb`／`Postgres` にし、`ConnectionStrings:MariaDb`／`ConnectionStrings:Postgres` に接続文字列を追加する（配布の `appsettings.json` には記載がない。パスワードは配布物・リポジトリへ含めない）。対応下限は MariaDB 10.11 LTS（`utf8mb4_bin`）／PostgreSQL 16（`LC_COLLATE=C`）。既存のSQLiteデータを移す場合は、SQLiteで起動したサーバで「■ システム管理 › ▲ 保守ツール › DB切替処理」を実行してから `Database:Provider` を変えて再起動する（移動先の表は削除・再作成される）。空のMariaDB／PostgreSQLへ直接新規作成して起動する経路は本書の範囲では未検証。詳細は [使用ガイドライン](使用ガイドライン.md) の「DBの種類」を参照する。

### クライアント

Portable ZIPを全体ごと書き込み可能なフォルダへ展開し、直下の `CreativeVision10.exe` を起動する。`current/` 以下の構成を保持する。WebView2利用機能にはWebView2 Runtimeが必要。

**通常起動では `%LOCALAPPDATA%/CreativeVision10/clientsettings.json` の接続先が同梱appsettingsより優先される。** 未作成時も既存 `ClientSettingsDocument` の初期値 `https://localhost:5012` が適用されるため、環境設定（F10）で接続先をサーバに合わせて保存し、再起動する。事前にファイルを作る場合の最小内容:

```json
{
  "ConnectionStrings": {
    "Url": "http://localhost:5002"
  }
}
```

既存 `clientsettings.json` は接続先だけを変更し、他設定や認証情報を上書きしない。この運用設定ファイルを公開ZIPへ追加しない。別端末では `localhost` を実際のサーバ名へ置き換え、サーバ側のHTTP/2対応HTTPS・証明書・ネットワーク設定に合わせる。

## 6. Web画面で公開

1. 公開対象ソースを通常の手順でレビュー・commit・pushし、タグ対象コミットを確定する。作業ツリーから作成した成果物と確定ソースに差があれば、確定後に作り直す。
2. [Releases](https://github.com/sekiya-sato/creativevision10/releases) → **Draft a new release** を開く。
3. タグ `v<版>` を選択する。未作成なら同画面で作成し、Targetを公開対象コミットへ指定する。既存タグが別コミットの場合は付け替えず確認する。
4. タイトルを `CreativeVision10 <版>` とし、リリースノートを本文へ貼り付ける。実機確認を追加した場合は「確認状況」を更新する。
5. 第1節の4ファイルだけを添付する。`release-notes.md`、内部nupkg、索引JSON、旧成果物フォルダは添付しない。
6. 下書きでタグ・対象コミット・本文・ファイル名を確認する。試用版にする場合は本文と **Set as a pre-release** を揃える。
7. **Publish release** を実行する。
8. 公開ページを未ログインのブラウザで開き、3つのZIPとSHA256SUMSをダウンロードしてSHA-256の一致を確認する。

## 7. 次回更新

公開後に版数とリリースノートを本書冒頭の表へ反映し、次の版数を決める。クライアントは新しいPortable ZIPを別フォルダへ展開し、設定を確認して切り替える。自動更新フィードは今回の公開方針では設定しない。
