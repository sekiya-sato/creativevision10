## 2. 方針

- 既存雛形 **顧客カルテ（`EndCustomerProfileView` / `EndCustomerProfileViewModel`）を実装する**。初版は「顧客検索」と「ポイント履歴」のみ。購入履歴タブ等の C01 残機能は後続とし、本書では作らない。
- 照会専用。登録・取消・残高修正の操作は持たない（手動登録は既存「ポイント手動登録」画面で行う）。
- データ取得はすべて既存の汎用照会 `Msg101_Op_Query`（`QueryListParam`）で行う。`PointLedgerManualViewModel.QueryListAsync` と同じ呼び方。新規 CvFlag・サーバ SQL・`QueryKey` は追加しない。
- メニュー「■ 顧客管理」直下、「顧客マスタメンテ」の次に「顧客カルテ」を登録する（`MenuData.cs`。クライアント側のみ）。権限は既存メニュー権限の仕組みに従う。

## 3. 画面構成

標準ウィンドウサイズ（`StandardWindowWidth/Height`）。最寄りの完成画面 `PointLedgerManualView` のレイアウト・スタイルを基準にする。

```text
┌検索条件──────────────────────────────────────────┐
│顧客コード[____] 氏名[______] カナ[______] 電話[______]          │
│所属店舗[____][選択] □退会者を含む          [検索 F5]              │
└──────────────────────────────────────────────┘
┌顧客一覧(上限500)──────┐┌顧客情報──────────────────────┐
│コード│氏名│カナ│店舗│電話│退会││コード 氏名(カナ) ランク 所属店舗 電話 退会日  │
│ ...                       ││台帳合計 / 集計残高 / 会員残高 （不一致時は警告色）│
│                           │├ポイント履歴─────────────────────┤
│                           ││期間[________]～[________] 種別[すべて▼] [解除]   │
│                           ││計上日│種別│増減│累計残高│付与│使用│失効│店舗│ │
│                           ││伝票Id│取消│摘要                                 │
└───────────────┘└──────────────────────────┘
メッセージ／件数                                         [閉じる F12]
```

- 顧客一覧で行を選ぶと右側に顧客情報とポイント履歴を表示する（選択＝特定）。ダブルクリック／Enter でも同じ。
- 一覧・履歴ともに右端列まで横スクロールで到達できること。

## 4. 処理詳細

### 4.1 顧客検索（`MasterEndCustomer`）

| 条件 | where 句（パラメータは `@n` バインド） |
|---|---|
| 顧客コード | `Code LIKE @n`（前方一致。完全一致の候補を先頭に並べるのは表示側で行う） |
| 氏名 | `Name LIKE @n`（部分一致 `%値%`） |
| カナ | `Kana LIKE @n`（部分一致） |
| 電話 | `Tel LIKE @n`（部分一致。ハイフン有無の正規化は初版ではしない） |
| 所属店舗 | `Id_Tenpo = 数値`（店舗選択画面で Id を得る） |

- 条件がすべて空なら検索しない（警告）。全件 48千件の誤取得を避ける。
- 並び `Code`、上限 500 件。上限到達時は「条件を絞ってください」を表示。
- 退会: `MasterEndCustomerAccount`（`Id_Customer IN (...)` を500件ずつ）から `IsWithdrawalFlag`・`WithdrawnDate`・`Point` を引く。「退会者を含む」未チェック時は退会会員を一覧から外す（クライアント側で除外）。
- 所属店舗名は `MasterEndCustomer.VTenpo`（現行名称スナップショット）を表示する。

### 4.2 ポイント履歴（`TranPointEvent`）

- 取得: `Id_Customer = 選択顧客Id`、並び `DenDay, Id`（索引 `nk1` を使用）、上限 20,000 行。上限到達時は警告し、累計残高列を空欄にする（途中までの累計を正しい残高と誤認させない）。
- **期間・種別はクライアント側で絞り込む**。全行を取得したうえで累計残高を計算し、表示だけ絞る。これにより期間開始前の繰越を別 SQL（集計）なしで正しく出せる。
  - 累計残高 = `DenDay, Id` 順の `PointDelta` 累計。旧CV履歴の日付「.」行は文字順で先頭に来るため、繰越として最初に加算される（移行設計書 §8 の「過去扱い」と一致）。
  - 期間既定は「指定なし（全期間）」。期間指定時は日付「.」行を表示しない旨を件数欄に示す（集計には含む）。
- 列: 計上日、種別、増減（`+#,0;-#,0`）、累計残高、付与／使用／失効の内訳、店舗、伝票Id（`Id_Tenuri`、0は空欄）、取消済（同顧客の取消行の `Id_OriginalEvent` から判定）、取消元Id、摘要。
  - 種別名・旧CV履歴の内訳表示は `PointLedgerManualViewModel.TypeName` と `PointLedgerManualRow` の `Jcalc`（`LegacyPointHistory`）読取を再利用する。必要なら行クラスを共用し、表示ロジックを二重に持たない。
  - 店舗名は `MasterTokui` を `Id IN (...)` で引く。
- 返品・取消の符号: 台帳 `PointDelta` は符号付きで保存済み。`CalcFlag` 等を再適用しない（AGENTS.md 7.6 の二重適用禁止）。

### 4.3 残高の表示

| 表示 | 取得元 |
|---|---|
| 台帳合計 | 取得した全履歴の `PointDelta` 合計 |
| 集計残高 | `SummaryPoint.Point`（`Id_Customer = 顧客Id`） |
| 会員残高 | `MasterEndCustomerAccount.Point`（`Id` 最小の1行。顧客マスタメンテと同じ） |

- 三者が一致しなければ警告色と「残高不一致（ポイント再計算で確認してください）」を表示する。照会画面からは補正しない。
- 履歴・集計行・会員行がいずれもない顧客は「ポイント履歴なし」と表示し、0 残高と区別する（C01 受入条件）。

### 4.4 状態遷移・無効化

- 検索条件を変更したら顧客一覧・選択顧客・履歴をすべて外し、再検索を促す（AGENTS.md 7.3）。
- 選択顧客が変わったら履歴・残高を即時クリアしてから取得する。取得中に別顧客を選んだ場合は先の要求を `CancellationToken` で取消し、遅れて届いた結果で上書きしない。
- 処理中は検索・選択操作を無効化する（`IsBusy`）。

## 8. 残余リスク

- 汎用照会の `LIKE '%値%'` は索引を使わない。顧客 5 万件規模では問題ないが、数十万件規模では氏名検索が遅くなる可能性がある（サーバ側を増やさない制約のため索引・専用 SQL は追加しない）。
- 本番で1顧客の旧CV履歴が上限 20,000 行を超える場合、累計残高を表示できない。移行後の顧客別最大件数を確認して上限を決める。
- 伝票Id から店舗売上伝票画面への遷移は、既存画面に Id 指定で開く経路がないため初版では行わない。
