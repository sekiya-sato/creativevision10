# MCP データベース I/F 拡張設計

調査日: 2026-11-05、調査対象 HEAD: `788a9a12b33fa35f282048348f0e656ecc7be95a`

## 方針

McpSql と McpOracle は stdio と既存ツール名・引数・正常時の JSON テキストを維持する。Codex と Claude Code に共通するツールを基本とし、Resources、Prompts、構造化出力、HTTP は両クライアントでの互換性確認後に別途検討する。

## 安全性と互換性

- 書き込みツールは従来どおり `--allow-write` がある場合に限り公開する。更新の結果が不明な場合は再送前に DB の状態を確認する。
- SQLite の `Sys*` 既定非表示は一覧の表示条件であり認可ではない。読み取り専用接続に失敗した場合の ReadWrite + query_only へのフォールバックは、OS 上の読み取り専用と同一ではない。
- Oracle の SELECT に含まれる関数には副作用があり得る。字句検査を認可の代わりにせず、接続アカウントの権限を制限する。`explain` は計画表に書き込み得るため、読み取り専用の annotation を付けない。
- 応答やログには認証情報、接続文字列、SQL、パラメータ値を無条件に含めない。診断情報は安全な項目の許可リストで構成する。

## 拡張項目と検証

現段階ではエラー詳細、列名検索、Oracle `explain` の annotation を実装する。以下のうち応答上限の全面適用、型付きパラメータ、追加探索機能は後続項目である。MCP キャンセル通知では通常のエラー応答を返せないため、エラー ID の取得を保証しない。

1. ツール失敗時は安全な分類と ID を返し、`get_error_details` で当該プロセス内の有効期限付き詳細を取得する。分類には発生処理、DB エラーコード、再送に関する注意を含める。キャンセルは MCP のキャンセルとして扱う。
2. 結果の行数・セル長・バイト数、メタデータ一覧、タイムアウト、キャンセルを評価し、既存の結果形式を維持したまま打ち切り理由を示す。安定した順序と更新時の意味を決めてからページングを追加する。
3. 列名からのテーブル検索、参照関係、ビュー定義を両 DB の権限・名前空間に合わせて提供する。SQLite の Sys* は既定非表示、Oracle は既存の USER_* 範囲を維持する。
4. 型付きパラメータと NULL、日付、数値、BLOB、重複列名を検討する。既存の `parameters` と正常応答は維持し、必要なら新ツールで拡張する。
5. 専用 SQLite DB と権限限定 Oracle 検証環境で、正常・不正入力・読み取り保護・サイズ・キャンセル・同時実行を検証する。Codex と Claude Code の接続、ツール発見、結果、エラー表示も実機で確認する。
